# SC-77. Переносимые формы создания записей

## Назначение и границы

Живая задача26c54f79aa1c9110536670ae8371a868 требует данных, форм и действий. SC-76 связывал списки, но кнопка открывала фиксированную форму доски. Дочерний этап **4c629c5a9eec7e53a5b11ecba1060cb4**, «P0 · Собирать переносимые формы создания записей», добавляет самостоятельный блок формы. Это позволяет собрать, например, страницу обращений: слева ввод контакта/вопроса, справа список, без неуместных обязательных системных секций.

Пользователь выбирает существующую доску, добавляет/скрывает/возвращает поля, меняет порядок, подписи, подсказки текстовых контролов, ширину из12колонок, размер текста, цвет текста и фона. Основные поля (название, описание, срок, ответственный, этап, приоритет) включаются по тому же принципу. Тип и обязательность пользовательского поля берутся из схемы доски — иначе две формы могли бы записывать несовместимые значения в одно поле. Скрытие не удаляет сам столбец и существующие данные. Название скрыть можно при явно настроенном начальном названии записи. Скрытое обязательное пользовательское поле без начального значения не даёт сохранить форму.

Действие этого этапа — только **создание записи**. Редактирование существующей записи, вычисляемые значения, условная видимость и цепочки действий ещё не реализованы. Подпись кнопки и сообщение результата настраиваются. Прогресс/читалка и все встроенные страницы не считаются завершёнными появлением седьмого блока.

## Данные, права и перенос

Конфигурация formFields/defaultTitle/successText хранится вместе с блоками в ревизии страницы. Сервер проверяет ключи/повторы/размеры/цвета, принадлежность источника и полей, скрытую обязательность. Создание использует прежний POST records с проверками пространства, участника, типов, обязательных значений и историей. Воспроизведён дополнительный дефект: поле email принимало строку invalid через API. Теперь новый ввод и начальные значения email проверяются сервером; старые записи автоматически не изменяются.

Набор переносит зависимую схему и конфигурацию формы. При установке ключи custom:fieldId переписываются на новые поля, подписи/порядок/оформление остаются. Форма и список одной доски используют одну независимую копию источника. Проверка формы также выполняется при снимке и установке; испорченная зависимость откатывает всю установку. Новых таблиц и миграций нет, схема064/116таблиц.

## Поведение пользователя

Предпросмотр отображает форму с типизированными контролами, проверяет заполнение, но не создаёт записи. Рабочая форма сохраняет несохранённый ввод локально для пользователя/пространства/страницы/блока при каждом изменении. После reload восстанавливаются доступные поля; при изменении конфигурации показано явное сообщение о необходимости проверить восстановленный ввод. Перед отправкой проверяется актуальная ревизия страницы. При ошибке ввод остаётся, автоматической повторной отправки нет. После успеха черновик удаляется, форма очищается до начальных значений, появляется ссылка на созданную карточку, связанные списки обновляются.

Существующий API создания пока не имеет идемпотентного ключа: неопределённый сетевой результат нельзя выдавать за гарантированно безопасный повтор. Этот предел унаследован от стандартной формы и требует отдельного этапа. Кнопка заблокирована на время запроса, но это не сетевой exactly-once. Физические устройства не проверялись; результаты локальной UI-приёмки и выпуска дописываются после выполнения.
