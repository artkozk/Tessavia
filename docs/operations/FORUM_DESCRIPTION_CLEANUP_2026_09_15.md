оно больше не занимает основную часть рабочего описания.

## Как выполнена очистка

Инструмент [clean-forum-import-descriptions-20260915.py](../../deploy/clean-forum-import-descriptions-20260915.py)
использует проверенный исходный план и неизменную квитанцию импорта. Перед
записью проверяются SHA256 плана, идентификаторы команды, доски и 81 карточки,
тип каждой записи и ожидаемый рабочий выпуск приложения.

1. Сначала выполнен предварительный просмотр без изменений бизнес-данных.
2. Из исходного описания извлекается точный служебный хвост — от разделителя
   перед «Исходный блок» до конечного маркера импорта. Его единственное точное
   совпадение удаляется из актуального текста. Дополнения пользователя до или
   после хвоста сохраняются. Изменённый или неоднозначный хвост останавливает
   проверку; произвольный текст после похожего заголовка не отсекается.
3. Все кандидаты проверяются до первой записи. Перед применением создана
   согласованная резервная копия SQLite на том же сервере.
4. Изменения выполнены штатным `PATCH /api/records/{id}`: только описание,
   ожидаемая ревизия `expectedUpdatedAt` и причина изменения. Прямая запись
   описаний SQL не используется. Параллельная правка карточки приводит к
   конфликту ревизии вместо перезаписи чужой работы.
5. После каждой записи перечитывается карточка. Итоговая сверка проверяет
   описания, сохранность остальных свойств всех записей команды, пользовательских
   значений и связей. Прежняя импортная квитанция проверена побайтово.

Штатный API сохраняет прежнее и новое описание в истории изменения. Отдельная
краткоживущая операторская сессия удалена после работы. Пользовательские данные,
план импорта и резервная копия в Git не включаются.

## Повтор, восстановление и дальнейший импорт

Перед PATCH новая квитанция сохраняет хеши исходного и ожидаемого описания.
Поэтому после потерянного ответа повтор распознаёт уже очищенную запись и
не возвращает служебный хвост. Если команда успела изменить очищенный текст,
повтор останавливается для проверки, а не восстанавливает прежнюю версию.
Восстановление при необходимости должно касаться только нужных описаний с
проверкой актуальных ревизий; автоматическая замена всей живой БД резервной
копией могла бы уничтожить последующую работу команды и не предусмотрена.

[Прежний отчёт импорта](TASK_WORKBOOK_IMPORT_2026_09_14.md) остаётся историей
первоначального переноса. Его утверждения о служебном снимке в описании и
успешном повторе прежнего плана относятся к состоянию до этой очистки.
Старый переносчик ищет маркеры в описаниях и требует полного совпадения с
исходным планом. Очищенные карточки больше не соответствуют этим условиям;
проверка такого состояния останавливает старый перенос до бизнес-изменений.
Повторно применять прежний импорт для «обновления» задач нельзя.

В будущем самостоятельном импорте внешние идентификаторы и журнал переноса
должны храниться отдельно от текста, который читает и редактирует команда.
Очистка не реализует синхронизацию Excel, новый импорт или автоматическое
сопоставление исполнителей; эти продуктовые задачи остаются самостоятельной
работой.
