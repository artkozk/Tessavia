## Назначение

## Ограничения и rollback

Тестовый код регистрации показывается в том же браузере и не подтверждает владение почтой. Allowlist остаётся активным; пройти его новый пользователь может только по действительной ссылке команды. Реальная доставка кодов и восстановление пароля записаны отдельной задачей.

Миграция 019 добавляет команды, приглашения, настройки интерфейса и меняет trigger нового пользователя. Поэтому простой длительный rollback только binary нежелателен. Порядок реакции:

1. Для локальной ошибки предпочтителен forward-fix.
2. При критическом нарушении сервис переводится в режим обслуживания.
3. Старый binary возвращается только вместе с восстановлением `pre-switch-business-control.db` и соответствующих uploads/config из backup.
4. Перед восстановлением отдельно экспортируются данные, появившиеся после backup.
5. После восстановления обязательны local/public health, marker, `integrity_check`, `foreign_key_check` и авторизованная проверка границ проектов.

Окончательный rollback не потребовался.
