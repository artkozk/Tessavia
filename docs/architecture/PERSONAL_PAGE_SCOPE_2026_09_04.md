# Независимые настройки личных страниц — 04.09.2026

Продолжение задачи `cf22d3a3a52d33eef11e8118a232d9a4` и контракта
`PERSONAL_TODAY_FOCUS_AND_TIME_2026_09_04.md`. Прежние замечания о привязке
личных страниц к команде сохранены как описание найденного дефекта.

## Причина и правило

Раньше кнопка «Личное» меняла только вид страницы. Активный workspace
оставался командным, поэтому конструктор сохранял личную раскладку
в строке настроек команды. Переход через переключатель пространств работал
иначе. Пользователь видел разные настройки одной личной страницы.

Теперь «Личное», личный календарь и личный день открывают существующее
личное пространство аккаунта из разрешённого сервером списка. Командный
календарь сохраняет контекст своего проекта. Личные заметки, файлы, планы,
связи и привычки не перемещаются: они уже хранятся у владельца.

## Переходы и сохранность

1. До смены области сохраняется положение командной страницы в истории.
2. Используется общий переход между пространствами: открытые формы должны
   сохранить черновик, несохранённая раскладка требует обычного решения
   пользователя. При отказе или ошибке переход прекращается.
3. После загрузки применяется целевая вкладка, дата и календарный контекст.
   Запоздалый ответ после новой навигации или смены аккаунта не открывает
   старую страницу. Ошибка загрузки остаётся видимой и допускает повтор.
4. Старые записи Back/Forward и reload с парой «команда + личная страница»
   нормализуются в личную область. Вкладка и положение прокрутки сохраняются;
   забытый диалог не открывается автоматически.
5. Конструктор и переносимые наборы используют прежнее API настроек в
   правильном workspace. ПК и телефон по-прежнему имеют разные профили.

## Однократный перенос раскладок — миграция 044

Копируются только страницы `personal`, `calendar:personal`, `day:personal`.
Прочие страницы, меню, ширина sidebar и общая плотность команды не переносятся.
Уже существующая личная страница имеет приоритет, включая явно пустую `{}`:
это может быть намеренный возврат к умолчаниям.

Для отсутствующей страницы выбирается последнее собственное сохранение
из доступных командных областей. У мобильного профиля используется его
`updatedAt`, чтобы более позднее изменение ПК не подменило мобильный выбор.
При равной отметке порядок разрешает идентификатор области. Каждая страница
выбирается отдельно. Заблокированное участие исключено из источников.
Регистрация создаёт одну личную область; защитный выбор при исторических
дубликатах — самая ранняя по дате и id. Новые аккаунты не получают чужих настроек.

Исторические строки команд не изменяются. В целевой строке добавляются
только отсутствующие страницы и обновляется отметка версии; остальные
настройки сохраняются. Повтор миграции не меняет результат. Это предотвращает
потерю уже проделанной настройки экрана при исправлении навигации.

## Проверки и границы

Миграционный тест проверяет двух владельцев, приоритет личной настройки,
раздельные ПК/mobile, выбор по времени, отсутствующую целевую строку,
заблокированное участие, сохранение всех старых строк и повтор.
Тесты навигации проверяют историю команды, целевую дату, отмену перехода
при незаписанном черновике, смену аккаунта и старые записи истории.
Браузерные результаты и координаты выпуска дополняются после проверки.

Это не завершает напоминания, ожидания и обзор нескольких команд из большой
задачи «Сегодня». Общий API раскладок пока не защищён сравнением версии при
одновременных сохранениях одного профиля; этот отдельный критерий относится
к задаче версий интерфейсных наборов. Перенос не заявляет исправление такого
конфликта. Физические телефоны не проверялись.
