# Каталог эмодзи и реакции — 04.09.2026

## Задача и причина изменения

Источник — живая карточка `313946e8cb6e8055306906a42ecb8aec`, «Добавить полноценный
выбор эмодзи и частых реакций», проект `bizflow-team`. Перед реализацией перечитаны
критерии на сервере, контракт чата, аудит требований и последний отчёт выпуска.
Карточка переведена в работу с маркером `[work:2026-09-04:emoji-catalog]`.

Раньше четыре вручную заданные группы не давали полноценного поиска. Недавние
хранились в общем ключе браузера и смешивались с реакциями других участников.
Сервер ограничивал реакцию восемью Unicode code points: часть семей и смешанных
оттенков не проходила. POST переключал состояние, поэтому повтор после потерянного
ответа мог снять уже записанную реакцию. Открытие каталога пересоздавало чат,
сбрасывая выделение и несохранённое редактирование.

Прежние разделы документации сохранены как история; для выбора эмодзи и новых
клиентов реакций действует описанный ниже контракт. Палитра, логотип и основные
действия чата остаются прежними.

## Пользовательские сценарии

1. В редакторе открыть «Вложения и дополнительные действия» → «Эмодзи».
   Выбранный эмодзи заменяет выделенный фрагмент либо вставляется на позицию
   курсора. Пробелы автоматически не добавляются. Сообщение не отправляется.
   Сценарий работает также при редактировании существующего сообщения.
2. У сообщения открыть «Добавить реакцию», либо «Другие действия» → «Все эмодзи».
   Заголовок явно отличается от вставки в текст. Выбор добавляет собственную
   реакцию или снимает ранее выбранную. Чужие реакции не удаляются.
3. Категории: эмоции, люди/жесты, природа, еда, путешествия, занятия, предметы,
   символы и флаги. Поиск понимает русские и английские названия/ключевые слова,
   несколько слов одновременно, `ё/е`. В поиск можно вставить готовый эмодзи,
   включая семейную последовательность, флаг региона или смешанный тон кожи.
4. Настройка «Тон кожи» выбирает стандартный либо один из пяти оттенков. Для
   эмодзи без такого варианта остаётся базовая форма. Флажок «Все варианты,
   включая разные тона кожи» открывает все последовательности, в том числе
   сочетания двух разных оттенков. Специальный жест удержания не требуется.
5. «Недавние» сортируются по времени, «Частые» — по числу использований с
   последним временем как вторичным критерием. История учитывает вставку в
   редактор и успешное добавление реакции; снятие и ошибка её не увеличивают.
   Пустой раздел объясняет, когда появятся элементы. Пять быстрых вариантов
   остаются в уже существующем меню сообщения.
6. Каталог занимает ограниченную панель в цветах чата, вписывается в видимую
   область. Кнопки эмодзи не меньше 44 × 44 px; текстовые названия доступны
   screen reader и в подсказках. Escape закрывает выбор и возвращает фокус,
   Tab перемещается внутри панели. Для touch клавиатура поиска появляется по
   запросу. Список начинается с 72 элементов, «Показать ещё» добавляет 72;
   поиск сразу охватывает весь каталог, а не только видимую порцию.
7. При ошибке загрузки каталога доступен повтор. При сбое сохранения реакции
   панель остаётся открытой, повторяет то же желаемое состояние. Текст редактора
   не затрагивается. Переключение проекта, аккаунта, диалога или редактора
   делает старый callback недействительным.

## Данные, воспроизводимость и лицензия

- Источник последовательностей: [Unicode 17.0 emoji-test.txt](https://www.unicode.org/Public/17.0.0/emoji/emoji-test.txt).
  Использованы все 3944 `fully-qualified` RGI последовательности, кроме группы
  самостоятельных компонентов. Они образуют 2134 базовых выбора в девяти группах.
- Русские/английские названия и ключевые слова: CLDR **48.2**, фиксированный tag
  `release-48-2`, файлы `common/annotations` и `common/annotationsDerived`.
  [Выпуск CLDR 48](https://cldr.unicode.org/downloads/cldr-48) поддерживает Unicode 17.
- `tools/emoji-data/sources.json` фиксирует точные URL и SHA256 всех шести
  исходников. `python tools/emoji-data/generate.py` скачивает отсутствующие
  исходники в `.artifacts/emoji-sources`, проверяет каждый hash и создаёт
  `web/vendor/emoji-17.0-cldr48.2.json`, `internal/emoji/sequences.txt` и
  `web/vendor/UNICODE-LICENSE.txt`. Данные поставляются по Unicode License v3;
  уведомление включено в приложение. Изменение исходника без обновления
  проверенного manifest останавливает генератор.
- Каталог встроен в бинарный файл. Внешних CDN и запросов к Unicode/CLDR при
  работе пользователя нет. JavaScript разбирает его при открытии выбора и
  переиспользует результат. Service worker включает публичный каталог в
  атомарно устанавливаемую оболочку для доступности после первого кэширования.
  JSON занимает примерно 1.16 МБ до транспортного сжатия. Приватные сообщения
  и история использования не попадают в публичный кэш.
- Отрисовка — системными emoji-шрифтами. Вид новых символов, флагов и сложных
  сочетаний зависит от ОС; на старых системах возможны отдельные компоненты
  или отсутствующий глиф. Каталог и API сохраняют последовательность целиком.

## Владение настройками и черновиком

Ключ `tessavie:chat-emoji:v1:<userID>` содержит только тон и максимум 128 записей
`emoji/count/last`. Чужие реакции не участвуют в рекомендациях. Прежний ключ
`business-control:chat-recent-emojis` не импортируется и не удаляется: определить
его владельца невозможно. Настройки локальны для аккаунта и браузера, не
синхронизируются между устройствами. При запрете, повреждении или переполнении
localStorage остаётся изолированная память текущей вкладки.

Панель не пересоздаёт чат. Вставка использует `setRangeText` и событие `input`,
поэтому обычный механизм черновика получает новое значение. Реакция обновляет
только её полосу у конкретного сообщения. Несохранённая правка существующего
сообщения дополнительно держится в памяти с ID автора, проекта, эпохой контекста,
диалога и сообщения: перестроение экрана, например при изменении ширины, не
возвращает старый серверный текст. Этот буфер не обещает восстановление после
полной перезагрузки страницы и не переносится в другой контекст.

## Серверный контракт

`PUT /api/chat/messages/{messageId}/reaction` принимает
`{"emoji":"👩🏽‍❤️‍💋‍👨🏿","active":true}`. `active` обязателен, `false` снимает
свою реакцию. Повтор PUT с тем же состоянием не переключает его. Старый POST
сохранён как переключение для совместимости с уже открытыми клиентами.

Сервер проверяет одну последовательность по встроенному RGI-каталогу, не по
лимиту количества code points. Защитная граница 128 байт больше любой включённой
последовательности. Презентационные формы `❤` и `❤️` эквивалентны; ZWJ, оттенки,
пол и части флагов сохраняются. Произвольный текст, несколько эмодзи и отдельный
тон кожи не создают реакцию. Старые произвольные реакции можно снять только
их владельцу; повтор снятия невалидного старого текста может вернуть 400,
так как он уже отсутствует. Идемпотентный контракт повторов относится к
поддерживаемым эмодзи.

Проверка активного сообщения, членства в диалоге и совпадения выбранного
workspace выполняется внутри той же SQL-транзакции, что и запись. Ошибки БД
не игнорируются. Сообщение отсутствует/архивировано → 404; нет доступа → 403;
некорректный ввод → 400; ошибка хранения → 500. Новый клиент передаёт захваченные
`X-Workspace-ID` и `X-Outbox-Owner`, чтобы смена аккаунта не перенаправила запись.
Транзакционный курсор собственных реакций закрывается до записи: SQLite
использует одно соединение.

Миграции и переписывания старых сообщений/реакций нет. Перед рабочим переключением
новый бинарник запускается на резервной копии; все 77 таблиц сравниваются
построчно с исходной копией. Для проверки чата на production не создаются
сообщения и реакции: авторизованные GET сопоставляются с доступными ID в БД.

## Проверка и границы выпуска

Автотесты проверяют все последовательности, составные семьи/флаги/смешанные тона,
повтор PUT, совместимость POST, презентационные алиасы, чужую сессию и
неучастника, архив/404, удаление только своей старой реакции. Node-тесты проверяют
поиск, все варианты, тон, недавние/частые, изоляцию владельцев, сбой storage и
замену выделенного UTF-16 фрагмента без отправки сообщения.

В браузере используется только локальная синтетическая база: вставка в
выделение, поиск на русском, редактирование, реакция без потери правки,
потерянный ответ после фактической записи и успешный повтор с одной строкой
в БД, выбор тона, панель при 320 px. Эмуляция ширины не заменяет проверку на
физических iOS/Android и настоящую экранную клавиатуру.

Сам каталог после кэширования доступен без сети. Запись реакции требует сети;
она не ставится в долговременную очередь. Отправка текста с эмодзи использует
уже существующую очередь сообщений. Этот выпуск не закрывает отдельные
карточки звонков, push-уведомлений, доставки и полного мессенджера.
