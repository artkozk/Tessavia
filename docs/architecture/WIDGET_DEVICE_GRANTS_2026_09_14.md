# Доступ устройства к выбранному блоку конструктора — 14.09.2026

## Причина и граница

Пользователь повторно запросил настоящие виджеты главного экрана телефона.
Предыдущий web-этап уже предоставляет установку PWA, быстрые ссылки и Web Push,
но ссылка на страницу не показывает её меняющиеся данные. Историческая оценка
в [мобильном исследовании](MOBILE_WIDGETS_AND_NOTIFICATIONS_2026_09_14.md)
сохраняется. Этот документ фиксирует следующий реализованный серверный контракт;
сам по себе он не подтверждает публикацию APK, iOS-сборку или физическую приёмку.

Первый поддерживаемый источник — обычный блок конструктора `tracker` («Пункты
и отметки») либо `progress`, ссылающийся на такой блок. Пользователь выбирает
свою страницу и блок. Здесь нет специального набора, созданного разработчиком
для конкретного аккаунта. Остальные типы блоков не выдаются за поддерживаемые:
читалка, привычки из отдельного личного модуля, таблицы и произвольные формы
требуют своих последующих адаптеров. Из виджета нельзя менять отметки или данные.

Единственный вход настройки — уже существующее окно «На телефоне» в общем
центре настроек. Сервер не добавляет строку в боковое меню, страницу пользователю
или новый набор. Выбор источника не переносит данные между пространствами.

## Обмен и API

Все шесть маршрутов обёрнуты в `Cache-Control: private, no-store` и
`Pragma: no-cache`, включая ошибки аутентификации. В URL не передаются токены,
пароли, pairing-коды и содержимое источника.

| Маршрут | Авторизация и результат |
| --- | --- |
| `GET /api/me/widgets/sources` | Обычная web-сессия и явный `X-Workspace-ID`; `{sources:[{pageId,pageName,blockId,title,kind}]}` только для выбранного пространства |
| `GET /api/me/widgets` | Web-сессия; `{devices:[{id,name,pageName,title,createdAt,pairedAt,lastUsedAt,expiresAt}]}` по всему аккаунту, без секретов |
| `POST /api/me/widgets` | Web-сессия, проверка same-origin, явный workspace; JSON `{pageId,blockId,name}`; `201 {id,pairingCode,pairingExpiresAt}` |
| `DELETE /api/me/widgets/{id}` | Web-сессия, same-origin; удаляет только собственный grant, `204`; чужой либо отсутствующий ID — `404` |
| `POST /api/mobile/widgets/redeem` | Без web-cookie; JSON `{code}`; `201 {token,expiresAt,widgetId}` после однократного обмена |
| `GET /api/mobile/widget` | Только `Authorization: Bearer <token>`; минимальный снимок выбранного блока |

Список источников и создание намеренно требуют заголовок пространства: общий
middleware рассматривает `/api/me/*` как настройки аккаунта и иначе выбирает
первое доступное пространство. Обработчики явно проверяют переданный ID через
`resolveWorkspaceAccess`, затем повторяют проверку в транзакции. Отсутствующий
заголовок даёт `400`, недоступное пространство — `403`. Список своих доступов
и отзыв работают даже после исключения из ранее выбранной команды.

Имя устройства обязательно, после обрезки пробелов — не более 80 Unicode-символов.
Пользователь может иметь не более 32 действующих или ожидающих pairing доступов.
Истёкшие доступы удаляются при очередном создании и не занимают этот лимит.
Запросы pairing/create ограничены 4096 байтами JSON, неизвестные поля и второе
JSON-значение после тела отвергаются.

Pairing-код — 128 случайных бит, 32 символа lowercase hex, срок пять минут.
Он показывается только в ответе создания. Сервер хранит SHA-256 кода. При обмене
создаётся отдельный 256-битный токен (64 lowercase hex), сервер хранит только
его SHA-256. Код атомарно заменяется хешем токена. Из нескольких одновременных
обменов ровно один получает успех. Повторный, истёкший, неверный либо отозванный
код даёт одинаковый `400` без сведений об аккаунте и источнике.

Срок токена — 90 суток от создания доступа, не от каждого обновления. Нет
бесконечного продления при чтении. Все даты — RFC3339 UTC. `pairedAt` пуст до
обмена, затем содержит время обмена; `lastUsedAt` пуст до первого успешного
чтения. Наличие записи в списке не доказывает установку приложения или показ
виджета на телефоне. Необменянный истёкший код исчезает из списка.

Если ответ однократного обмена потерян, сервер не может повторно показать токен:
plaintext уже не хранится. Пользователь отзывает доступ и создаёт новый код.
Повтор не создаёт другой токен и не расширяет действующий grant.

## Минимальный снимок и соответствие конструктору

Ответ чтения:

```json
{
  "widgetId": "grant-id",
  "title": "Мой список",
  "kind": "tracker",
  "completed": 3,
  "total": 12,
  "items": [{"label": "Пример пункта", "checked": true}],
  "updatedAt": "2026-09-14T12:00:00Z",
  "openUrl": "/",
  "color": "#176b58",
  "background": "#f5f4ef"
}
```

Это пример структуры, не пользовательские данные. `color` и `background`
необязательны и возвращаются только для валидного цвета блока `#RRGGBB`.
`openUrl` в первом этапе всегда `/`: переход к определённой странице здесь
не заявлен. Ответ не содержит workspace/page/block ID, email, автора, текста
других блоков, всей схемы страницы, заметок, таблиц и форм.

Снимок использует личные отметки владельца grant. Участник не получает отметки
создателя страницы или другого участника. `items` содержит максимум восемь
видимых подписей. `completed` и `total` считаются по всему списку (лимит
конструктора — 500 пунктов), а не по первым восьми. Для выбранного `progress`
выдаются только сумма и прогресс, `items: []`: скрытые за ним подписи источника
не являются содержимым выбранного блока.

Проверяются скрытие блока, вся цепочка родительских групп и условия `all/any`:
метрики `checked/remaining/percent`, сравнения `eq/ne/gt/gte/lt/lte`. Пустой
источник не выполняет условие. Процент сравнивается без округления, как в
`web/page-block-visibility.js`. Циклическая, повреждённая или неизвестная схема
не интерпретируется эвристически; источник недоступен. Для progress дополнительно
проверяется видимость исходного tracker и его родительских групп.

Пункт с `item.hidden=true` исключён и из подписей, и из чисел. Отдельное
оформление `elementStyles.item.hidden`/`item:<id>.hidden` скрывает подпись,
но сохраняет её вклад в расчёт: именно так работает web-конструктор. Частная
настройка `hidden:false` перекрывает общее скрытие. Скрытый заголовок заменяется
нейтральным названием типа. Разница между удалением пункта из расчёта и его
визуальным скрытием сохранена, иначе телефон показывал бы другой прогресс.

`updatedAt` — последняя дата изменения схемы или учитываемых отметок выбранного
tracker. Изменение постороннего блока отметок не выдаёт себя за обновление
выбранного источника. Это время данных; клиент отдельно хранит время получения
снимка, чтобы отличать свежий ответ от старого локального изображения.

## Отзыв, приватность и границы фоновой работы

Каждое чтение заново проверяет действующий токен, срок, доступ владельца к
пространству, состояние workspace/team, активное участие в workspace и team,
неархивную страницу, выбранный блок и условия показа. Личное пространство
дополнительно требует совпадения его владельца с владельцем grant. Проверки
и чтение отметок происходят в одной SQLite-транзакции; другой блок вместо
исчезнувшего не подставляется.

Недействительный или истёкший токен возвращает `401`; потерянный доступ,
скрытый источник либо архивная страница — `403`, без названий источника.
В списке web-настроек такая запись остаётся отзывной, но её pageName пуст,
title — «Источник недоступен». Клиент после `401/403` обязан удалить токен
и локальное изображение. Нет обещания мгновенно очистить экран отключённого
от сети устройства: отзыв начинает действовать на сервере сразу, на клиенте
обнаруживается при следующей проверке. Это ограничение явно отличать от
успешного удаления доступа в настройках.

Токен даёт только чтение одного блока через `/api/mobile/widget`. Его нельзя
использовать вместо cookie для обычных API или записать им новую отметку.
Public-маршруты отвергают cookie, даже вместе с действительным Bearer; обмен
также отвергает Authorization. Это предотвращает случайное использование
native-клиентом более широких браузерных полномочий.

Обычный web-выход не отключает отдельно разрешённый виджет. Ручной отзыв,
смена пароля аккаунта и удаление пользователя удаляют grant. Смена пароля
реализована SQLite-trigger, поэтому работает и с предыдущим бинарником,
который ещё не знает о виджетах. Срок, собственный отзыв и изменение пароля
не требуют запущенной native-оболочки.

Обмен ограничен 30 запросами в минуту с IP; чтение — 240. При превышении
возвращается `429`, `Retry-After: 60`. Это локальный limiter процесса с максимумом
4096 ключей и минутными окнами; после рестарта окна начинаются заново. Общего
Go-limiter в проекте до этого не было. Для соединения от loopback reverse proxy
допускается одиночный валидный `X-Real-IP`; от внешнего peer этот заголовок
игнорируется, цепочки `Forwarded/X-Forwarded-For` не используются. Nginx должен
сам задавать X-Real-IP, не передавать произвольное значение клиента. Необходимо
сохранить этот контракт при изменении размещения прокси.

## Схема и совместимость выпуска

`072_widget_devices.sql` только добавляет `widget_devices`, индекс
`widget_devices_owner_idx` и trigger `widget_devices_password_changed`.
Уникальные pairing/token hashes дополнительно обеспечиваются ограничениями
таблицы; ровно один из двух хешей присутствует. Бизнес-таблицы, схемы страниц
и личные отметки не переписываются. Имеются FK на пользователя, workspace
и страницу, без сохранения копий пользовательского текста.

Предыдущий бинарник может работать с расширенной БД, однако новый native API
при откате отсутствует. Поэтому release-проверка должна проверить новую схему
на копии, сохранность прежних таблиц, запуск предыдущего бинарника и отсутствие
восстановления старой БД поверх новых данных. Операционная квитанция и проверка
настоящего APK относятся к отдельному отчёту выпуска.

## Выполненные серверные проверки

`go test ./internal/app -run '^TestWidget' -count=1` проверяет реальный HTTP/API
и временную SQLite с миграциями, а не заменяет их JSON-макетом. Покрыты выдача
и отзыв; 8 одновременных обменов одного кода; хеши и одноразовость; private
no-store и отсутствие Set-Cookie; изоляция аккаунтов/пространств/личных отметок;
полный итог при обрезанном списке; отсутствие чужих текстов; progress; скрытые
предки; архив; отстранение участника команды; смена пароля и отдельный web-выход;
неверные, истёкшие и повторные секреты; лишние JSON-поля и хвост; same-origin;
лимит устройств и очистка истёкшего pairing; условия показа и стили; rate429.

Прохождение этих проверок подтверждает серверный протокол. Оно не подтверждает
показ RemoteViews на домашнем экране, работу iOS WidgetKit, обновление launcher,
сетевые условия реального телефона или приёмку push на устройстве.
