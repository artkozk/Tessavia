# Сохранение раскладок карты

Каноническая задача `98781560e9a1ca14c22e187f00d67c5e` переведена в работу
после выпуска независимых оценок. Этот документ фиксирует решение для реализации;
проверки и публикация должны быть дополнены фактическими результатами.

## Проблема

Координаты хранятся в `business-control:graph-positions:{user}:v4`, настройки —
в `business-control:graph-settings:{user}:v1`. Проект и вид карты отсутствуют
в ключах. Перестроение удаляет общий ключ. На другом устройстве данных нет;
ветка, строка поиска и глубина ещё и теряются отдельно от координат. Запоздалый
запрос графа может попасть в состояние уже выбранного другого проекта.

## Решение

1. Область раскладки: текущий пользователь, проект, вид. Виды — весь проект
   (`project`) и локальная карта конкретной карточки (`record:{id}`). Ветка и
   фильтры принадлежат выбранному виду. Координаты общие между устройствами;
   масштаб для читаемости рассчитывается под экран и не навязывает телефону
   масштаб большого монитора.
2. Сервер хранит координаты, настройки, фильтры и монотонную версию. Доступ
   определяется сессией и выбранным проектом; клиент не назначает владельца
   раскладки. Локальный вид и узлы проверяются на принадлежность проекту.
3. Запись требует ожидаемую версию и выполняется атомарно. Если другое окно
   успело сохранить свою раскладку, сервер отвечает 409. Клиент сохраняет
   локальный вариант и предлагает загрузить серверный или явно сохранить свой
   поверх актуальной версии. Автоматически смешивать координаты двух переносов
   ветки нельзя: такое смешивание разрушает выбранное взаимное расположение.
4. Перенос узла/ветки, фильтры и настройки сохраняются после завершения действия
   с небольшой задержкой объединения запросов. Показаны состояния «сохранено»,
   «сохраняется», ошибка/локальный черновик и конфликт. Ошибка сети не выдаётся
   за успешное серверное сохранение. Локальный черновик привязан к той же области
   и содержит ожидаемую версию; он переживает перезагрузку страницы.
5. Старые локальные ключи не удаляются. При отсутствии серверной раскладки
   переносим подходящие старые координаты только для узлов текущего проекта.
   Общие прежние настройки можно использовать как начальные. Серверные данные
   имеют приоритет над чистым локальным кешем; несохранённый вариант разрешается
   по версии, а не молча заменяет серверную раскладку.
6. Сброс/перестроение действует только на выбранный проект и вид. Отмена
   восстанавливает предыдущую раскладку новым сохранением. Эти действия не
   меняют карточки, родителей или смысловые связи. Добавление новых узлов не
   должно рандомизировать уже сохранённые позиции.
7. Загрузка и сохранение захватывают область при начале запроса. Ответ прежнего
   проекта/вида не применяется к текущей карте. Отложенные события уничтоженного
   графа не сохраняются под новым ключом. Настройки раскладки не должны ожидать
   загрузки всех других модулей платформы.
8. Экспорт включает только раскладки текущего пользователя для текущего проекта.
   Личные предпочтения других участников не попадают в командный экспорт.

## Приёмка

Нужны два проекта, два аккаунта, две независимые сессии/окна одного аккаунта:
перенос, повторное открытие, серверная загрузка, изоляция проекта/вида/пользователя,
конкурентная запись и оба варианта разрешения конфликта. Сброс и отмена
проверяются сравнением семантических связей до/после. Отдельно проверяются
локальный черновик при ошибке сети, поздний ответ другого проекта, перенос
старых координат без удаления старого ключа и узкий экран.

Физические устройства и полнота больших графов сверх существующего лимита
являются отдельными проверками; их нельзя считать пройденными по этой задаче.
