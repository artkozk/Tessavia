# SC-84. Значение действия из другого поля записи

## Причина и сценарий

После подключения источников и условий показа следующим критерием направления f4dd60e96ccb69635a2faa05a60fd058 стало вычисляемое значение действия. Раньше кнопка могла установить фиксированное значение или прибавить фиксированный шаг. Пользователь не мог собрать «Подтвердить оценку» с переносом текущего значения поля «Оценка» в поле «Подтверждено». Ему пришлось бы редактировать карточку вручную либо просить разработчика настроить отдельную функцию.

После сверки живой родительской карточки зарегистрирована узкая задача 2603cbd315162bc158387127d29c7e84. Теперь пользователь выбирает «Как изменить» → «Взять из другого поля» и источник значения. Кнопка берёт значение той же записи на момент проверки, показывает результат и требует подтверждения. Это одна операция над одним полем; родительское направление составных действий не закрывается.

## Настройка через интерфейс

1. В доске создать поля для исходного и подтверждённого значения. Можно использовать существующие поля.
2. На своей странице добавить «Список записей», выбрать доску и отображаемые поля.
3. В «Действия с записью» добавить действие, задать подпись и изменяемое поле.
4. Выбрать «Взять из другого поля», затем совместимый источник. Если совместимого поля нет, редактор объясняет, что добавить; неподходящие поля не предлагаются.
5. При необходимости включить условие выполнения. Для копирования новое условие по умолчанию проверяет заполненность источника; 0 и false считаются заполненными. Уже настроенное независимое условие сохраняется.
6. Сохранить страницу. В карточке раскрыть действия, проверить источник и значения «Сейчас»/«После подтверждения», подтвердить или отменить.

При переходе к установке/прибавлению sourceFieldId удаляется. При смене целевого поля способ возвращается к установке и прежняя связь не сохраняется скрыто. Источник, способ и условие входят в обычный черновик страницы, восстанавливаемый после reload. Отмена настроек не меняет сохранённую страницу.

## Типы и пустое значение

| Исходное поле | Совместимое целевое поле |
|---|---|
| Число или сумма | Число или сумма; без пересчёта единиц и валют |
| Текст или длинный текст | Текст или длинный текст |
| Флажок | Флажок |
| Дата | Дата |
| Дата и время | Дата и время |
| URL, email, телефон | Соответствующий такой же тип |

Значение не преобразуется догадкой: строка не становится числом, дата не получает произвольное время. Копирование в себя запрещено. Варианты select/multi_select исключены из этого этапа, поскольку ID вариантов принадлежат разным полям; для них нужен явный редактор соответствий. Связи на пользователей/записи и основные статус/исполнитель/срок требуют сохранения отдельного контекста и жизненного цикла. Это оставшаяся работа, а не отказ от расширяемости конструктора.

0 и false сохраняются как значения. Пустой источник может очистить необязательное поле: это объясняется в настройке и видно в предпросмотре. Для запрета очистки можно включить условие заполненности источника. Обязательное поле при пустом источнике не очищается; сервер отклоняет операцию до записи. Значение проходит штатную нормализацию целевого поля, включая формат даты и email.

## Сервер, версии и история

В PageRecordAction добавлены operation=copy и sourceFieldId. value для копирования отсутствует или null; ненулевое фиксированное значение отклоняется, чтобы конфигурация не имела двух противоречащих источников. Для set/add sourceFieldId запрещён. Оба поля должны быть активными, совместимыми и принадлежать выбранной доске.

Клиент не присылает новое значение при выполнении. Сервер читает сохранённую конфигурацию и актуальную запись, проверяет права, доску, условие и версии. schemaHash включает схемы целевого поля, источника значения и поля условия. Переименование/изменение схемы источника после предпросмотра требует нового просмотра даже при неизменившейся записи. Изменение значения источника повышает версию записи, и старое подтверждение даёт 409.

Обновление записи, поля и история остаются в одной транзакции. История действия содержит sourceFieldId для объяснения происхождения результата. Повтор старого успешного подтверждения не создаёт ещё одну запись истории. Запись с owner_only по-прежнему не изменяется участником без соответствующего права. Условие SC-80 повторно проверяется сервером и не обходится новым способом копирования.

Предпросмотр сообщает название источника и его актуальное значение рядом с итогом. При конфликте кнопка подтверждения выключена; пользователь явно обновляет предпросмотр и принимает новое решение. Автоматического применения изменившегося значения нет.

## Набор и совместимость

Снимок набора включает схему доски и конфигурацию действия, не записи автора. Установка создаёт новую доску и новые ID полей; переводятся fieldId, sourceFieldId и поле условия. Правило связывает поля установленной копии. При отсутствующем или чужом источнике установка/сохранение отклоняется. Подтверждённые значения автора не превращаются в результаты получателя.

Миграций нет: 117 таблиц, последняя схема 065_record_create_requests.sql. Предыдущий SC-83 не умеет operation=copy. Деплой проверяет точный предыдущий релиз, создаёт backup, выполняет dry run на той же машине и сравнивает все строки/таблицы. Если после остановки сервиса найдены сохранённые copy-действия в страницах или наборах, автоматический откат на старую несовместимую версию блокируется. Пользовательская база не заменяется старой копией для обхода проверки.

## Фактическая приёмка

- На синтетической доске подготовлены поля и запись 3/1. Страница и действие полностью настроены через UI: выбраны источник, поля списка, действие копирования и условие заполненности. Черновик восстановлен после reload.
- Открыт предпросмотр 1→3. Другой локальный API-клиент изменил исходную оценку на 5. Старое подтверждение получило 409. Обновление показало источник 5 и переход 1→5; отдельное подтверждение сохранило 5.
- Приватный тестовый набор установлен через UI. В независимой доске через стандартную форму создана собственная запись 0/8. Предпросмотр показал 8→0. Отмена сохранила 8; повторное открытие и подтверждение сохранили 0, результат остался после reload.
- В копии способ временно переключён на установку фиксированного значения: поле источника исчезло. Изменения отменены, API подтвердил сохранность operation=copy и условия.
- При 320×800 просмотрены длинная подпись, выбор источника, форма настроек и диалог подтверждения. Элементы доступны без наложений. После проверки обычная ширина восстановлена. Физические телефоны не использовались.

Node проверяет варианты источников, экранирование подписи, замену фиксированного ввода выбором источника и очистку привязки при смене способа.

## Следующий этап

Составное действие, меняющее несколько пользовательских полей за одно подтверждение: например, взять оценку из источника и поставить пользовательскую отметку согласования. Нужны атомарность всех шагов, общий предпросмотр, правила вычисления зависимых значений и перенос каждой привязки. Это остаётся в f4dd60e96ccb69635a2faa05a60fd058. Привязки свойств/видимости к произвольным данным, AND/OR, вложенные компоненты, основные поля и полная кастомизация встроенных экранов также остаются открытыми. Пользователь самостоятельно собирает свой набор; тестовые наборы не устанавливались в его production-аккаунт.
