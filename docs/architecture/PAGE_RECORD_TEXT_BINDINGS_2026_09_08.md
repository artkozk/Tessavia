# SC-88 — текст карточек из данных

## Пользовательский результат и причина

В конструкторе блока «Список записей» появился раздел «Текст карточек из данных». Пользователь выбирает поле для заголовка каждой карточки и независимое поле для подписи, добавляет текст до/после значения и замену пустого значения. Один реестр может показывать «Оценка: 9 часов», другой — собственный журнал с числом прочитанных глав. Настройка работает для каждой записи, а не требует ручного копирования значений в подписи. Исходное название записи, её поля, история и действия не переписываются.

Задача `7a85114ee0eb76dddd109eaf264e3b2a` фактически зарегистрирована в bizflow-team, родитель `2ad192a4298615883945e23a87d8ecd2`. Это первый срез привязок вложенного элемента списка. Он не закрывает произвольные свойства всей страницы или контекст пользователя. Пользователь по-прежнему сам собирает свой набор; проверочные страницы синтетические.

## Настройка и поведение

1. Выбрать доску списка и раскрыть «Текст карточек из данных».
2. Для заголовка выбрать поле либо оставить «Название записи». Для подписи выбрать поле либо «Без подписи».
3. Настроить префикс, суффикс и замену пустого значения. Каждый дополнительный текст ограничен 160 символами. Пробелы сохраняются: пользователь управляет разделителями и единицами измерения.
4. В том же разделе выбрать доступную запись для предпросмотра или «Пустые значения». Просмотр ничего не записывает в карточку и не переносит значения в определение/черновик/набор.
5. Сохранить страницу. Привязки участвуют в обычном черновике и expectedRevision. Кнопка «Убрать привязку» возвращает стандартное название или убирает подпись независимо от второй настройки.

Поддержаны text, long_text, number, money, date, datetime, url, email, phone, checkbox, select, multi_select. Используется штатное форматирование, включая названия вариантов вместо внутренних ID. Ссылки на пользователей и другие записи не раскрываются этим механизмом: они требуют отдельного контекста и проверки доступа. Ноль и false являются значениями; false отображается как «Нет». null, отсутствующее значение, пустая строка и пустой список используют замену. Недоступное поле или удалённый вариант также дают замену. Без заданной замены заголовок показывает исходное название записи, подпись скрывается.

Показанный текст входит в поиск списка вместе с исходным названием и выбранными полями. Открытие строки открывает прежнюю запись. Изменение исходного поля обновляет показанный текст обычной перерисовкой списка. Привязки не меняют набор доступных записей и не выполняют дополнительные запросы к чужим объектам. Тексты и значения экранируются как текст; произвольный HTML/JS не выполняется.

## Схема, перенос и смена типа

`PageAppBlock.recordBindings` — карта с ключами title/subtitle. Значение содержит fieldId, prefix, suffix, emptyText. Сервер разрешает только эти ключи, допустимые длины/ID и действующие скалярные поля выбранной доски текущего пространства. Проверки выполняются при сохранении страницы, снимке набора и его установке. Чужое или архивное поле не принимается. Редактор явно показывает недоступную привязку, чтобы она не выглядела выбранным стандартным названием.

Смена типа блока сохраняет неактивные привязки: после возврата к списку они снова применяются. Такой блок продолжает включать свою схему источника в набор, поэтому установка переводит ID обеих привязок даже при временном текстовом типе. Новая доска остаётся пустой; исходные записи, личные данные и выбранная запись предпросмотра не копируются. Явная смена доски сбрасывает несовместимые привязки вместе с прежними полями списка. Удаление привязок в копии не меняет оригинал или сохранённый набор.

Миграций нет: используется определение страницы, остаются 117 таблиц и схема065. Откат на SC-87 запрещён при сохранённых recordBindings в страницах/наборах: старая версия не понимает объект и могла бы потерять его при сохранении. Проверка отката выполняется после остановки службы. Деплой включает серверный backup, dry run со сравнением всех прежних строк, HTTPS/assets/health/nginx/integrity/FK/401.
