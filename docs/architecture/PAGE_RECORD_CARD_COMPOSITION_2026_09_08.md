# SC-93 — собственная структура повторяемой карточки

## Зачем

Пользователь просит собирать разные приложения и распространять их как наборы.
Фиксированная строка списка мешала этому: нельзя было произвольно расположить
название, выбранные поля и собственные пояснения. Этот выпуск добавляет структуру
тела карточки, которая повторяется для каждой доступной записи. Это очередная
часть общего конструктора, а не объявление его полностью готовым.

Задача на рабочем сервере: `d7c3e0a88408025472ab61119f4509c5`, родитель
`26c54f79aa1c9110536670ae8371a868`. Пользователь самостоятельно собирает свой
набор; проверочные страницы создаются только в синтетическом окружении.

## Как настроить

1. Открыть свою страницу → «Конструктор» → блок «Список записей».
2. Развернуть «Структура повторяемой карточки», включить «Своя структура карточки».
   Первое включение переносит все выбранные поля, заголовок и подпись.
3. Выбрать количество колонок карточек (1–4) и интервал (0–48 px). Нулевой
   интервал сохраняется; на узком экране карточки становятся одной колонкой.
4. Развернуть нужную часть: изменить её тип, ширину из 12 колонок, выбранное поле,
   собственную подпись поля или текст. Подпись поля можно скрыть отдельно.
5. Кнопки «Часть выше» и «Часть ниже» меняют порядок. «Убрать часть» скрывает
   представление, «Вернуть часть» восстанавливает его вместе с настройками.
   Это не удаление поля схемы и не удаление значений записей.
6. «Добавить часть карточки» создаёт новую текстовую часть и сразу раскрывает её.
   Тип можно заменить на поле, заголовок или подпись. Заголовок/подпись используют
   существующие привязки и числовые вычисления из «Текст карточек из данных».
7. Во «Вложенные элементы» выбрать «Часть карточки: …» и задать цвет, фон,
   размер текста, ширину, высоту, отступы и другие доступные свойства оформления.
8. Проверить живой предпросмотр, сохранить страницу. «Сохранить как набор»
   переносит структуру и оформление в шаблон; записи автора в набор не включаются.

Выключение своей структуры возвращает стандартное представление, сохраняя
настройки для повторного включения. Смена типа блока также сохраняет структуру
и ссылки на поля. Явная смена доски сбрасывает несовместимые ссылки и оформление
её частей, как уже происходит с привязками полей и действиями.

## Устройство и защита данных

`PageRecordCard` содержит enabled, columns, gap и parts. Часть имеет стабильный
ID, kind, fieldId, text, label, width, hidden и hideLabel. До **48** частей:
первоначальное описание задачи предполагало 24, но существующий список допускает
40 выбранных полей. Лимит 48 позволяет включить все 40 плюс заголовок и подпись
без молчаливого обрезания. Это технический предел текущего выпуска; скрытые
части тоже учитываются. Постоянного удаления части и вложенных повторителей нет.

Сервер проверяет уникальность ID, диапазоны, типы частей, длину текста (2000) и
подписи (160), принадлежность каждого поля доступной доске. Проверяются также
скрытые части и отключённая структура. Пустая структура допустима: карточка
сохраняет доступную кнопку «Открыть запись» и исходное доступное имя записи.

При установке набора переназначаются fieldId всех частей, включая скрытые.
Стабильные ID частей сохраняют связь с `elementStyles[recordPart:ID]`.
Набор содержит конфигурацию, а не значения записей; копия использует собственную
доску. Прежние права доступа и контроль устаревшей ревизии сохраняются.

Файл `web/page-record-card.js` формирует тело и реальной карточки, и предпросмотра.
Значения берутся из контекста конкретной записи; 0 и false не превращаются в
пустое значение. Пользовательский текст экранируется. Поиск учитывает выбранные
поля собственной структуры. Кнопка открытия и меню действий остаются снаружи
настраиваемого тела; пользователь не теряет доступ к записи при скрытии частей.
CSS использует исходную палитру, компоненты форм и адаптацию по ширине контейнера.

## Выпуск и оставшаяся работа

Миграции нет: схема 065, 117 таблиц. Штатный скрипт делает резервную копию на
том же сервере, dry run и сравнение всех строк, затем проверяет HTTPS, ресурсы,
health, 401, nginx, integrity/FK. Автоматический откат на предыдущую версию
блокируется, если уже сохранены recordCard или стили recordPart: старая версия
не понимает эти свойства и может потерять пользовательскую настройку.

Следующие этапы: произвольные привязки свойств к данным и контексту пользователя,
компоненты с параметрами, вложенные повторители и логика цепочек действий.
Постоянное удаление частей, произвольная структура самой формы записи, новые
виды данных и все свойства любого системного экрана этим выпуском не закрыты.
Большие задачи конструктора, чата и команд остаются открытыми.
