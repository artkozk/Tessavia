# Развёртывание бизнес-памяти BizFlow

Дата: 25 августа 2026 года.

## Разрешённый production-контур

BizFlow, production SQLite, вложения, резервные копии и конфигурация могут находиться только на `159.194.231.150` и обслуживать домен `control.e-rd.ru`. Другие известные серверы не являются допустимой площадкой для этого проекта.

## Характер релиза

Релиз содержит добавочную миграцию `012_business_memory_and_safe_undo.sql`. Она:

- добавляет в `records` поле предметного типа;
- создаёт таблицу специальных бизнес-полей;
- создаёт таблицу журнала безопасных отмен;
- переносит существующие решения в состояние `active` без изменения их текста и связей;
- не удаляет и не переименовывает существующие таблицы или столбцы.

Миграция выполняется один раз при старте приложения внутри штатного механизма миграций.

## Проверки до переключения

1. Проверить отсутствие незапланированных файлов и секретов в diff.
2. Выполнить форматирование Go-файлов.
3. Выполнить `go test ./...`, `go vet ./...`, `node --check web/app.js` и `git diff --check`.
4. Проверить desktop и mobile сценарии в локальном браузере на отдельной временной SQLite.
5. Собрать Linux amd64 бинарник без зависимости от библиотек production-хоста.
6. На основном сервере проверить активный release, сервисы, свободное место и состояние БД.
7. Создать согласованный backup SQLite и архив uploads на основном сервере.
8. Проверить `PRAGMA integrity_check` и `PRAGMA foreign_key_check` на backup до запуска новой версии.

## Переключение

1. Создать новый каталог `/opt/business-control/releases/<release>`.
2. Передать бинарник с проверкой SHA-256.
3. Остановить только сервис `business-control`.
4. Атомарно переключить `/opt/business-control/current` на новый release.
5. Запустить сервис и дождаться применения миграции.
6. Проверить локальный health и журнал миграции.
7. Проверить внешний HTTPS health и версию assets `20260825-business-memory-1`.
8. Проверить основные API, вход, поиск, очередь, проверки, решения, карту и историю.
9. Повторить проверки целостности рабочей SQLite после запуска.

## Обязательный smoke

- `/api/health` отвечает локально и по HTTPS;
- вход существующих пользователей не требует повторной регистрации;
- старые карточки, вопросы, исследования, решения и чат доступны;
- входящее создаётся без срока, приоритета и процента;
- входящее разбирается в новый тип без смены ID;
- экран `Риски и проверки` загружается без горизонтального переполнения;
- принятое решение не находится в активной очереди работы;
- форма решения не показывает срок, приоритет, оценку времени и прогресс и не принимает решение без содержания;
- новое решение может заменить старое, и связь видна на карте;
- глобальный поиск находит специальные поля;
- история открывает событие и предлагает отмену только для безопасного действия;
- `PRAGMA integrity_check` возвращает `ok`;
- `PRAGMA foreign_key_check` не возвращает строк;
- в журнале сервиса нет новых ошибок.

## Откат

Миграция добавочная и не ломает запуск предыдущего бинарника: новые столбцы имеют значения по умолчанию, существующие запросы перечисляют нужные поля явно. Поэтому при ошибке интерфейса можно вернуть symlink на предыдущий release без восстановления БД.

Во время такого временного отката нельзя редактировать новые риски, гипотезы, эксперименты и входящие: старый интерфейс может показать их как базовые совместимые типы. Данные при этом не удаляются.

Восстановление backup БД допустимо только при подтверждённой ошибке самой миграции или нарушении целостности. Оно откатывает все пользовательские изменения после backup и поэтому не используется как обычный способ возврата версии приложения.

## Фактический отчёт

Коммит, release, backup, контрольные суммы, состояние сервисов и результаты production smoke добавляются ниже после переключения. Инструкции выше не удаляются и остаются основой для проверки следующего релиза.
