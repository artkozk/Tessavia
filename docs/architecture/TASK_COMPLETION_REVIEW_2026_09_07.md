# Завершение задачи отдельно от проверки результата

Прямой запрос пользователя 07.09.2026: задача после «Сделано» исчезла с доски,
поскольку автоматически получила review, а системная колонка проверки скрыта.
Причина подтверждена в handleCompleteTask и стандартном наборе WORK_BOARD_DEFAULTS.
Реальная задача прежнего набора 7323301b79de2fc339d11144e81a313d уже завершена;
её не открываем заново. Текущий аудит 6e4f34f50ea37062254b52d8d63292b6 остаётся
в работе; этот новый запрос и проверяемый результат будут добавлены к нему.
На production найдена одна задача с review, progress 100 и последним submitted.

## Новое поведение

Завершение устанавливает completed и 100%, сохраняет результат и доказательства.
Проверка — отдельный reviewPending, не блокирующий завершение и положение карточки.
На пользовательской доске сохраняется именно выбранный done-этап, даже если таких
колонок несколько. Завершение из карточки сохраняет её текущий done-этап или выбирает
первый действующий done-этап. Принятие не меняет колонку и дату завершения.

Уведомление получает назначенный принимающий, иначе постановщик, когда работа
нуждается в отдельном просмотре и этот человек не совершил завершение сам.
Не рассылаем всем администраторам каждое завершение. Принимающий и администратор
текущего проекта могут подтвердить результат или вернуть задачу с пояснением.
Возврат переводит в работу, снимает ожидание проверки, сохраняет доказательства
и историю. Изменение статуса другим разрешённым действием также снимает ожидание.
Повтор завершения/принятия не создаёт повторных уведомлений или повторений задачи.
Завершение из карточки сохраняет требование итога и доказательства; перенос по
конструктору сохраняет прежний свободный сценарий доски без навязанной формы отчёта.

Повторяющаяся задача создаёт следующий экземпляр при фактическом завершении;
подтверждение лишь снимает ожидание и не создаёт второй экземпляр. Уже созданные
повторения не удаляются при возврате исходной задачи в работу.

## Совместимость

Миграция добавляет records.review_pending. Только старые задачи со статусом review,
100% и последним событием submitted восстанавливаются в completed с review_pending.
Их результат, доказательства, история, связи и уведомления остаются. На доске
восстанавливается текущий done-этап или первый действующий done; при отсутствии
такого этапа текущая колонка сохраняется. Ручной review без отправленного результата
и любые иные типы не преобразуются. updated_at обновляется для фоновой синхронизации.
Прежние контракты сохраняются как история; это дополнение заменяет правило,
по которому завершение исполнителя обязательно меняло колонку на review.

## Проверки до выпуска

Системная доска и конструктор с двумя done-колонками; исполнитель/постановщик/admin/
посторонний; уведомления и повтор запроса; принятие без переноса; возврат с причиной;
повторение без дубля; точная миграция старого случая без изменения соседних данных.
UI пройти через реальные действия на синтетических аккаунтах, включая узкий экран.
Фактические результаты и release дописываются после проверки.

## Дополнительная причина исчезновения, найденная в UI

При переходе из списка доска наследовала «Активные», поэтому колонка завершённых
оставалась пустой даже после исправления приёмки. Теперь ручной переход на доску,
как уже было для календаря, раскрывает все состояния вместо исходного активного
фильтра. Явное завершение на доске также снимает фильтр активных/просроченных,
чтобы показать результат в выбранной колонке. Поиск, исполнитель, направление и
сохранённые представления не переписываются. Список сохраняет своё действующее
ограничение активных; если пользователь выбрал его, завершённые логично исключаются.
Для различия доски/списка и незавершённого действия добавлен регрессионный тест.
