# Состав участников совместного решения — 07.09.2026

Ручной прогон SC-44 обнаружил блокировку: команда из трёх участников
показывала «1 из 4 ответов», поскольку listQuestionWorkflow и запись итога
считали все строки users. Регистрация постороннего клиента повышала порог
чужой команды. Это наследие первоначального продукта для двух основателей.
Исторические документы не удаляются; ниже зафиксирован текущий контракт.

## Текущее правило

Ответ требуется от каждого действующего участника рабочего пространства
карточки. Чужие аккаунты, вышедшие и исключённые участники не увеличивают
порог. В команде из одного человека достаточно его ответа: продукт не
требует несуществующего второго основателя для фиксации собственного решения.
Позднее можно добавить выбор конкретных респондентов; этот выпуск не
подменяет состав команды произвольной выборкой.

Исторические ответы не удаляются. API по-прежнему возвращает answers,
дополнительно activeAnswerCount показывает число ответивших из текущего
состава. Общее answered складывает именно текущие ответы. Интерфейс
отдельно раскрывает ответы бывших участников, а решение и AI-выжимка
проверяют текущий состав. Три старых ответа не заменяют ответ нового
участника, даже если численность команды после замены не изменилась.

Проверка готовности решения выполняется внутри транзакции его сохранения
по workspace_members карточки. Для ошибки чтения состава возвращается
ошибка сервера, для недостающих ответов — конфликт с понятным объяснением.
Схема БД не меняется; действующие решения, ответы и авторство сохраняются.

## Проверки

- Интеграционный сценарий: три участника плюс посторонний аккаунт; ответ
  постороннего не требуется. Пока действующий администратор не ответил,
  итог блокируется.
- Ответивший участник исключается и заменяется новым. Исторический ответ
  остаётся, но не засчитывается вместо нового. Обычный итог и AI-выжимка
  заблокированы до нового ответа; после него итог сохраняется.
- Сценарий команды из одного человека обновлён по новому контракту вместо
  исторического ожидания второго основателя.
- Клиентский тест проверяет счётчик активных ответов, сохранение старого
  текста и появление формы итога только после ответов текущего состава.

Ручная повторная проверка и публикация дописываются в журнал
docs/product/TESSAVIE_HANDS_ON_AUDIT_2026_09_07.md после фактического выполнения.
