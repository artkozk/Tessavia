# Личные разделы, своё меню и страницы конструктора — 13.09.2026

## Причина и связь с прежним решением

Пользователь сообщил, что личное боковое меню предлагает только «Сегодня» и
«Календарь», а остальные полезные функции приходится искать в перегруженной
полосе вкладок. Собственные страницы конструктора не должны требовать создания
команды: человек должен самостоятельно разнести свои сценарии по отдельным
страницам и возвращаться к ним через привычное меню.

Этот документ дополняет
[личный контекст](PERSONAL_CONTEXT_SEARCH_CONTRACT_2026_09_03.md),
[независимые настройки личных страниц](PERSONAL_PAGE_SCOPE_2026_09_04.md),
[проектный конструктор](PROJECT_COMPOSER_CONTRACT_2026_09_02.md) и
[единый центр настроек](UNIFIED_SETTINGS_2026_09_10.md).
Историческое ограничение меню двумя пунктами не удаляется из старых документов;
оно описывает прежний выпуск, а не предел возможностей платформы.

## Ключи меню и раскладок

Сохраняется существующий формат `InterfacePreferences`: `hiddenNavItems`
управляет скрытыми пунктами, `navOrder` — их порядком. Профиль принадлежит
текущему пользователю, выбранному workspace и отдельно ПК либо телефону.
Новые таблицы и миграции для расширения меню не требуются.

| Раздел | Постоянный ключ меню |
| --- | --- |
| Сегодня | `personal` |
| Календарь | `calendar` |
| Входящие | `personal:inbox` |
| Проекты | `personal:projects` |
| Цели | `personal:goals` |
| Заметки | `personal:notes` |
| Дела | `personal:plans` |
| Привычки | `personal:habits` |
| Карта времени | `personal:life` |
| Финансы | `personal:finance` |
| Обзор недели | `personal:review` |
| Ожидания | `personal:waiting` |
| Собственная страница | `page:<id>` |

Отдельный alias `personal:today` не вводится. Ключи `personal:<tab>` разрешаются
сервером только при сохранении меню personal workspace. Существующие проектные
ключи сохраняются в допустимом списке ради совместимости прежних профилей;
это не добавляет проектные разделы в личный интерфейс автоматически. Неизвестные
ключи и ID страниц другого workspace отбрасываются. Свои архивные страницы
остаются допустимыми в настройках, чтобы восстановление страницы не теряло
ранее выбранные порядок и видимость. Скрытие меню не является правом доступа.

Для `layout.pages` каждый личный раздел использует `personal:<tab>`, а «Сегодня»
сохраняет прежний ключ `personal`. Серверная нормализация уже поддерживает двоеточие
и сохраняет эти настройки независимо. Клиентский переход использует прежнюю
раскладку `personal` как совместимый fallback до первого отдельного сохранения.
Правила наследования и реальная браузерная проверка фиксируются интеграционным
этапом; этот серверный раздел не объявляет их проверенными заранее.

Наборы оформления переносят названные встроенные пункты меню и настройки
личных страниц. При применении набора к командному workspace личные ключи
меню снова фильтруются его допустимым каталогом. ID собственных страниц
в набор оформления не входят. Личные тексты `PageLayout.Texts` также не
публикуются: у получателя сохраняются его собственные подписи. Сохранение
композиции страницы как набора конструктора остаётся отдельным действием
с явным выбором видимости.

## Личные страницы без команды: существующий серверный контракт

Регистрация создаёт personal workspace с владельцем. API
`/api/workspace/pages`, `/api/workspace/pages/<id>/app`, отметки и расчётные
листы уже используют этот workspace без требования `kind=team`.
Создавать команду для собственной страницы не нужно. Личный владелец
управляет её структурой, архивирует и восстанавливает её; лимит активных
страниц и проверка ревизии остаются общими правилами конструктора.

`pageAppExists` проверяет принадлежность страницы текущему workspace.
Подмена ID страницы при сохранении, чтении, отметке или записи чисел не
обходит эту проверку. Аутентификация разрешает выбранный workspace только
при действующем членстве; членство и роль администратора в общей команде
не дают доступа к личному workspace другого человека. Штатные командные
операции ограничивают список проектов выбранной командой, поэтому личное
пространство не становится одним из её проектов.

Блоки списков и форм могут ссылаться только на доски того же workspace.
Сохранение ссылки на чужую доску отвергается даже при доступе пользователя
к обоим workspace. Блоки личных привычек и планов содержат только настройки
источника: актуальные записи запрашиваются от имени текущего пользователя,
а не автора страницы. Свободного указания чужого owner ID в конфигурации нет.

Набор конструктора переносит схему страницы, подписи, формулы, постоянные
числа и схему источников. Отметки, личные числа расчётного листа, планы и
записи досок не копируются. Установка создаёт независимую страницу и пустые
доски с новыми ID. Приватный набор доступен владельцу; получение другим
пользователем возможно после явной публикации. Такая публикация не открывает
исходную личную страницу или её данные.

## Изменённые файлы и проверка сервера

В `internal/app/project_composer.go` добавлен единый список личных ключей и
его применение в `navigationKeys` только для personal workspace. Найденная
причина потери настроек: прежде допустимый список содержал `personal`,
проектные пункты и `page:<id>`, поэтому `personal:notes` и подобные значения
молча исключались при подготовке профиля.

В `internal/app/interface_presets.go` тот же список подключён к переносимым
ключам меню и страниц. Иначе прямое сохранение профиля работало бы, но набор
оформления продолжал бы терять личные разделы и их независимую раскладку.

Новые HTTP-регрессии в `internal/app/personal_constructor_test.go` проходят
через действующие маршруты, сессии и реальную SQLite базу всех миграций:

1. Два аккаунта, изначально имеющие только personal workspace: создание страницы,
   доски, записи, личного дела, трекера и расчётного листа; сохранение и чтение;
   архивирование и восстановление без потери отметок и чисел; отказ чужому
   workspace, ID страницы и источнику; приватный набор и независимая установка
   после публикации без переноса данных; отказ администратору позднее созданной
   общей команды в доступе к чужой личной странице.
2. Все десять новых ключей меню сохраняются и читаются в исходном порядке;
   дубли и чужие ID отбрасываются; ПК, телефон и другой аккаунт независимы;
   personal, personal:notes и personal:finance сохраняют разные размеры;
   набор оформления переносит личные настройки без текстов и page ID;
   отмена применения возвращает прежний профиль; командное меню не принимает
   личные пункты через прямое сохранение или применение набора.

Вместе с существующими регрессиями устройств, наборов, компоновщика, источников
страниц и конфигурации личных данных прошли **10/10 Go-тестов**:
`go test ./internal/app -run 'Test(Personal(Constructor|Navigation)|Interface(Device|Preset)|PortablePreset|ProjectComposer|PageAppsCompose|PersonalDataPage|PageAppRecordSources)' -count=1 -v`.

Это локальная серверная проверка. Визуальное меню, переносы длинных названий,
320/390 px, смена вкладок, сохранность клиентского черновика, полный прогон,
коммит и production-выпуск подтверждаются отдельно. Личные production-данные
в тестах не использовались. Старые незавершённые изменения преобразования
типов полей не входят в этот этап.


## Согласованное поведение клиентского меню

По умолчанию личное меню показывает пять пунктов: «Сегодня», «Календарь»,
«Дела», «Привычки», «Финансы». Остальные семь встроенных разделов доступны
для включения в настройке меню: «Входящие», «Проекты», «Цели», «Заметки»,
«Карта времени», «Обзор недели», «Ожидания». Собственные страницы появляются
в меню, если пользователь сам их не скрыл. Таким образом человек получает
короткую начальную навигацию и может расширить её под свой сценарий.

После сохранения настройки полный `navOrder` обозначает явно выбранную
конфигурацию; прежние профили не переписываются автоматически. Отдельная
раскладка личной вкладки читает старый `pages.personal` только как fallback,
пока у вкладки ещё нет собственного ключа. Первое сохранение создаёт
`pages["personal:<tab>"]`, не изменяя настройки «Сегодня» или соседних вкладок.
Это согласованный клиентский контракт; фактические UI-проверки добавляются
после выполнения интеграционного этапа.

## Независимое ревью переходов и регрессионная проверка 13.09.2026

При проверке фактической функции `navigateToView`, а не только таблицы
маршрутов, обнаружен и исправлен возврат из личных уведомлений в проектный
обзор. Функция теперь применяет результат `personalRoute`; старый маршрут
`dashboard` внутри personal workspace обозначает «Сегодня» и явно сбрасывает
личную вкладку в `today`. Это важно для возврата после перезагрузки, когда
у браузера ещё нет предыдущей внутренней страницы.

Переход «Все ожидания» также раньше напрямую менял `personalTab` и заново
рисовал содержимое. Теперь модуль получает общий `navigate` и запрашивает
`personal:waiting`: обновляются активный пункт меню, заголовок, история, а
несохранённый редактор страницы сохраняет право отменить переход.

В тестах `navigation.test.cjs`, `personal-context.test.cjs`,
`personal-planning.test.cjs`, `reminder-digests.test.cjs` и
`personal-waiting.test.cjs` дополнены реальные поведенческие проверки.
Устаревшее извлечение единственной экспортируемой функции заменено поддержкой
нескольких экспортов модуля; проверки меню и переходов дайджеста больше не
зависят от конкретной формы строкового литерала в реализации.

Целевой прогон семи файлов, включая `personal-navigation.test.cjs` и
`page-layout.test.cjs`: **49/49 Node-тестов прошли**, пропусков нет.
Локальный журнал: `.artifacts/personal-navigation-20260913/node-review-targeted.log`.
Проверены переходы Финансы → Заметки → собственная страница, Back/Forward,

Дополнительное чтение сохранения и сброса раскладки подтвердило: редактор

Ограничение кнопки конструктора зафиксировано отдельно: `button.source`
сейчас указывает на другой блок той же страницы, а нажатие прокручивает к
нему. Это не маршрут меню; значения `personal:*` здесь не поддерживаются.
Новый sidebar даёт переходы между личными страницами. Межстраничные кнопки
нуждаются в отдельном типе назначения, проверке доступности и правилах
переноса ссылок при публикации набора, поэтому существующий ID блока в этом
выпуске не переопределяется.
