# SC-101 — освобождение места для блоков

## Задача и исходное поведение

Актуальная задача `1908592abd805fc870faf8fbee62092f` перечитана через API
14.09.2026 в проекте `bizflow-team`. Критерии и история сохранены; статус изменён
с `planned` на `in_progress` с проверкой версии. Родитель
`66da4e412e714f4ea85c56ff85de03ec` остаётся открытым. Это продолжение конструктора,
не объявление завершёнными всех требований платформы.

В опубликованной версии `ee7b320` воспроизведено через интерфейс: страница с
40 блоками, из них 35 скрытых, не позволяет добавить текст и сообщает только
«До 40 блоков на странице». Редактор предлагает скрыть, но не имеет операции,
освобождающей место. Скрытие сохраняет конфигурацию и поэтому не является
удалением. Сам лимит не увеличиваем без проверки нагрузки.

Синтетическая страница `SC-101 Блоки и восстановление` создана через API
localhost 38546 в отдельной тестовой базе. В группе находятся трекер с 1 из 2
отметок, прогресс 50% и расчётный лист: количество 7 × цена 25 = 175. Отдельная
кнопка ссылается на трекер; она нужна для проверки зависимостей. Данные настоящих
страниц, привычек и финансов не используются как тестовые примеры.

## Решение и границы

В конструкторе добавляется управление блоками и восстановимая корзина. В неё
переходит выбранное поддерево с исходными идентификаторами; строки личных отметок
и чисел остаются на сервере. Перенос и восстановление явно сохраняют текущий
черновик страницы одной операцией. Внешние зависимости блокируют перенос с
объяснением; восстановление проверяет свободные места, родителей и источники.

Хранение использует существующую историю и таблицу отмен, без новой миграции.
Обычные ленты получают краткое описание события, а не тяжёлый снимок настройки.
Повтор при потере ответа использует прежний идентификатор операции. Архивные ID
защищены от присвоения другому блоку. Полный контракт и причины решений:
[корзина блоков](../architecture/PAGE_BLOCK_TRASH_2026_09_14.md).

## Проверки и выпуск

На момент подготовки раздела выпуск не выполнен. Результаты автоматических
и браузерных проверок, точный коммит, резервная копия и квитанция будут добавлены

результатам одного изменения ширины браузера.

## Первичная браузерная приёмка

На первой локальной сборке 14.09.2026 пройден SC-101 через обычные элементы
интерфейса. Попытка добавить 41-й блок открывает управление блоками. Удаление
группы с внешней кнопкой заблокировано с её названием и переходом к настройке.
После переноса кнопки внутрь группы удаление сразу сохранило черновик и освободило
пять мест: 40 → 35. Создана новая памятка, и возврат пяти блоков при занятых 36
местах предсказуемо заблокирован: показаны числа 5 и 4 и путь освобождения места.

Через фильтр скрытых в корзину перенесена одна заметка; вместе с этим сохранена
новая памятка. Возвращена группа: 35 → 40. Перезагрузка подтвердила прежнюю отметку
«Глава 1», 50%, число 7 и итог 175. Новая памятка и перенос кнопки в группу остались.
API подтвердил исходные идентификаторы и ревизию 4. Проверка настоящих строк
этой синтетической корзины прошла; откат на старую программу ожидаемо заблокирован.

На 320 × 740 px отсутствует горизонтальное переполнение. По результату просмотра
исправлен дополнительный дефект: «Открыть блок» и выбор блока в длинном списке
теперь переводят фокус и прокрутку к форме настройки. Эта последняя правка входит
в окончательную сборку и проверяется повторно ниже. Работающие стили других
страниц не заменялись новыми; новая панель использует общую палитру и кнопки.

## Окончательная сборка и проверка ошибок

Из staged Git tree экспортированы точные blobs без Windows-фильтра окончаний
строк. Windows и Linux собраны из одного дерева; 505/505 Node и 35/35 проверок
deploy verifier прошли. `go vet ./...` прошёл. Первый полный Go-прогон выявил
устаревшее ожидание в проверке ресурсов: жёстко задано шесть подключений, а новый
CSS добавил седьмое. Проверка заменена перечислением конкретных ресурсов с
актуальной версией; это проверяет сохранность кеширования, не привязываясь к
случайному количеству строк. Изменён только тест, приложение не менялось.
Результат повторного полного Go-прогона добавляется при выпуске.

На окончательном Windows-бинарнике через localhost proxy 38547 проверен отказ
400 до записи: черновик текста сохранился, возврат к форме доступен. Затем
успешное удаление получило искусственный 503 вместо ответа. После reload редактор
восстановил прежний запрос и удерживал редактирование до «Проверить и продолжить».
Проверка вернула 39 блоков и ровно одну запись удалённой памятки в корзине.
Сам proxy не записывает тела запросов, пароли или заголовки; он работает только
с синтетическим localhost. Мобильный переход к настройке теперь проверен на
окончательной сборке: фокус находится на форме, её верх виден в пределах 320 px.

Повторный `go test ./...` прошёл: internal/app 111.637 s, web 0.307 s.
Аналогично проверен потерянный ответ восстановления: reload и повтор вернули
40 блоков без второй копии, первоначальный текст памятки остался. Ревизия выросла
только до 6 (одна запись удаления и одна восстановления); личная отметка и число 7
сохранились. На 1280 × 900 px список и кнопки находятся внутри диалога. Ошибок
JavaScript в тестовой вкладке не обнаружено. Физические устройства не проверялись.

Проверка метаданных бинарника выявила особенность вложенного каталога экспорта:
Go автоматически подписывал его предыдущим родительским Git-коммитом с `dirty`.
Для окончательного артефакта используется `-buildvcs=false`; источник подтверждается
побайтовой сверкой с коммитом и квитанцией SHA256, без неверной встроенной подписи.
Windows и Linux повторно собраны с этим флагом; код приложения не изменён.
