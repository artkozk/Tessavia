# Сохранённые связи личных дел в интерфейсе — SC-103, 14.09.2026

Документ дополняет [аудит личных проектов и целей](PERSONAL_HUB_AUDIT_2026_09_14.md).
Исправляются задачи `a65c8628293feb66d941f0e554343fc1` и
`9494b67b04f78cbf8b075f0eeee7d2f1`: недоступный родитель и сохранение дела после
архивирования связанного проекта или цели. Самостоятельные рабочие экраны
проекта и цели, задача `4420e0be29f8c092c19243aa9d102d38`, остаются отдельной
плановой работой. Исторические выводы аудита не удаляются и не заменяются
утверждением о готовности всего личного пространства.

## Подтверждённая причина потери связи

Ранее обзор исключал архивные проекты, цели и дела из обычных массивов.
Это правильно для каталога новых связей, но существующее дело продолжало
хранить прежний `projectId`, `goalId` или `parentId`.

Редактор строил select только из обычных массивов. Для архивного ID выбранного
option не существовало. Браузер показывал «Без проекта», «Без цели» или «Нет»,
а сохранение формы отправляло пустое значение. Пользователь мог потерять связь,
меняя лишь название дела. Детали также пропускали отсутствующий в массиве
проект или цель, поэтому не объясняли, что произошло.

Второй путь потери — восстановление локального черновика. Назначение select
значения, которого уже нет среди options, сбрасывает native selection в пустую
строку. Обычное восстановление текста поэтому не гарантировало сохранность ID.

Перед исправлением координирующий агент подтвердил первый дефект в браузере:
дело с сохранённым `projectId` показывало «Без проекта», а детали не показывали
проект. Старую форму не сохраняли, чтобы не создать искусственную отвязку.
Проверки исправленного выпуска и статус деплоя фиксируются в операционном
отчёте, отдельно от настоящего описания реализации.

## Контракт данных

Основные массивы `projects`, `goals`, `plans` личного обзора остаются каталогами
доступных сущностей. Дополнительное поле имеет вид:

```json
{
  "historicalReferences": {
    "projects": [{"id": "...", "title": "..."}],
    "goals": [{"id": "...", "title": "..."}],
    "parents": [{"id": "...", "title": "..."}]
  }
}
```

Этот DTO содержит только собственные архивные сущности, на которые ссылаются
сохранённые неархивные дела пользователя. В него не входят заметки, описания,
чужие названия или полный архив. `parents` используется отдельно от основного
массива дел. Пустые списки допустимы и не означают ошибку загрузки.

`personal-plan-references.js` разрешает подпись по обычному массиву, затем по
этому DTO. Если источника нет, состояние — `unavailable`; клиент не придумывает
название и не подставляет ID в пользовательскую подпись.

## Редактирование сохранённой связи

Для каждой из трёх связей действует одинаковый порядок:

1. В select остаются обычные доступные варианты и явный пустой вариант.
2. Если прежнего ID нет среди них, добавляется только прежняя связь данного
   дела. Архивная помечается «в архиве». Другие архивные сущности, даже если
   их подписи есть в DTO для других дел, в каталог выбора не попадают.
3. Сохранённый выполненный родитель также не пропадает: основной массив дел
   его содержит, но прежний каталог родителей показывал только незавершённые
   дела. Текущий выполненный родитель добавляется с пометкой «завершено».
4. Под полем архивной связи написано, что её можно оставить, заменить или
   убрать. Переключение на доступный или пустой вариант снимает эту подпись.
5. Обычное изменение названия, дат или текста сохраняет исходные ID. Клиент
   не обнуляет связанные поля вслед за архивированием контейнера.

Новую архивную связь клиент не разрешает. Серверная проверка дополнительно
сверяет ID с сохранённой строкой владельца; клиентский запрет служит объяснением,
а не границей доступа. Цель и проект не заменяются и не согласуются скрытыми
автоматическими изменениями. Несовместимую комбинацию проверяет сервер.

## Недоступная или чужая прежняя ссылка

Если сохранённый ID не разрешается, форма содержит выбранный нейтральный
вариант «Недоступная связь — уберите или замените». Его значение не пустое:
сама загрузка формы не является намерением отвязать дело.

Перед отправкой проверяются значения трёх полей. Недоступную ссылку нельзя
просто сохранить. Рядом указана причина, сообщение называет поле и предлагает
выбрать доступный вариант или явно пустой вариант. Фокус переводится к полю,
в том числе к видимой кнопке существующего кастомного select.

При попытке завершить такое дело из списка или деталей открывается его редактор
для явного исправления связи; PATCH завершения не отправляется. Архивная
собственная неизменённая ссылка этому не мешает: завершение продолжает отправлять
статус и версию, оставляя ID на сервере прежними.

В деталях неизвестная связь показана без названия источника и без его ID.
Это защищает сценарий со старой ошибочно сохранённой чужой ссылкой: пользователь
может исправить своё дело, не узнавая заголовок чужого родителя.

## Детали и список дел

В деталях доступны три вида отображения:

- Доступный проект и цель сохраняют обычные переходы в существующие редакторы.
  Доступный родитель открывает детали родительского дела.
- Архивная связь выводится статическим элементом с названием и пометкой
  «В архиве · связь сохранена». Кнопки открытия недоступного редактора нет.
- Недоступная связь выводится нейтральным текстом с предложением исправить её
  в редакторе дела. Название не раскрывается.

В краткой строке дела проект и цель также не исчезают: собственные архивные
подписи имеют пометку, недоступные — нейтральное состояние. Архивирование
контейнера не переносит само дело из активного списка.

Оформление использует существующие `personal-context-link`, фон, границы и
акцент платформы. Добавлены только перенос длинных названий, ограничение ширины,
вертикальное расположение пояснения и компактная группа связей. Новых вложенных
областей прокрутки, палитры или дополнительного центра настройки нет.

## Черновики и сохранность версии

Три select помечены `data-personal-plan-reference`. Для них `applyWorkingDraft`
перед восстановлением отсутствующего значения создаёт нейтральный option.
Таким образом, ID из черновика сохраняется даже после изменения доступных
вариантов. Это не превращает его в разрешённую связь: перед отправкой работает
та же проверка. Остальные select и формы используют прежний механизм черновиков.

Для существующего дела форма содержит скрытый `expectedUpdatedAt`. Обычный
`workingDraftValues` сохраняет это поле вместе с текстом и ID. После повторного
открытия исходная версия возвращается из черновика; PATCH использует её,
а не более новую версию только что загруженного дела. При 409 текст, ID и
исходная версия остаются в открытой форме и локальном черновике.

Старые черновики могли быть созданы до появления поля версии. Им нельзя
автоматически присвоить актуальный штамп. Поэтому:

1. Версия остаётся пустой; повторное сохранение такого локального черновика
   также сохраняет пустую версию.
2. Над формой появляется объяснение и раздел «Сравнить с сохранённым делом»:
   актуальное название, текст, даты, связи и плановое/фактическое время.
3. Отправка заблокирована до действия «Я сравнил, продолжить с черновиком».
   Это выбор применить восстановленные поля после сравнения, а не скрытое
   обновление версии при загрузке.
4. После явного выбора форма получает версию показанного сохранённого дела.
   Если сервер успел изменить его ещё раз, обычная проверка версии вернёт 409.

Версия не показывается пользователю как редактируемое поле. Раздел сравнения
нужен только старым черновикам без исходного штампа; новые черновики не требуют
дополнительного подтверждения.

## Контекст и поздние ответы

Редактор проверяет владельца, рабочее пространство, маршрут и наличие своей
формы перед отправкой. Эти же условия защищают подтверждение старого черновика.
Смена аккаунта или пространства не подтверждает сравнение и не очищает текст.

Сохранение передаёт `X-Outbox-Owner`. Запоздалый ответ не закрывает следующий
диалог и не очищает черновик уже другого контекста. После закрытия и обновления
обзора контекст проверяется снова перед открытием деталей. Завершение дела
тоже не обновляет чужой экран после смены контекста.

Прямое открытие редактора отсутствующей сущности теперь сообщает о её
недоступности вместо показа формы создания с пустыми полями. Это защищает
и старые кнопки, полученные до архивирования источника.

## Дополнение 14 сентября: выход из конфликта версий без потери черновика

При дополнительном ревью до экспорта candidate найден ещё один обязательный
сценарий. Первая версия исправления сохраняла непустой `expectedUpdatedAt` после
409, но показывала сравнение только у старого черновика без версии. Получалась
ловушка: сохранить дело в другом окне, получить 409 здесь, закрыть редактор,
снова восстановить черновик — и повторять запрос со старой версией бесконечно.
Предыдущее описание сохранности остаётся верным, но пользовательский путь выхода
из этого состояния теперь дополнен явно, без автоматического принятия новой
версии и без требования очищать хранилище браузера.

### Как работает сейчас

1. При открытии существующего дела редактор сравнивает версию восстановленного
   черновика с версией загруженного дела. Если они отличаются, сразу показывает
   панель сравнения и не отправляет форму до выбора пользователя. Непустой старый
   штамп сохраняется неизменным.
2. Панель показывает сохранённый заголовок, описание, даты, связи и оценку времени.
   Поля формы продолжают содержать локальный черновик. Доступны две явные команды:
   «Я сравнил, продолжить с черновиком» и «Удалить черновик и открыть сохранённое».
3. Первая команда принимает именно версию, показанную в этой панели. Она не
   читает автоматически более свежий штамп из фонового состояния. Если другое
   окно успело изменить дело ещё раз, следующий запрос снова получит 409.
4. Вторая команда удаляет только локальный черновик текущего дела и заново
   открывает сохранённую запись. Никакого PATCH эта команда не отправляет.
   Название кнопки прямо сообщает об отказе от локальных изменений.
5. Если 409 впервые приходит в уже открытом редакторе, поля и исходный штамп
   остаются на месте. Появляется команда «Загрузить сохранённое дело для
   сравнения». Повторный submit не обходит эту панель.
6. Загрузка сравнения сначала синхронно сохраняет черновик через существующий
   `flushDialogDrafts`. При ошибке локального хранилища загрузка не начинается,
   форма остаётся открытой. Затем используется обычный `loadPersonal` и та же
   форма заново открывается с сохранённым черновиком и новым серверным состоянием.
7. Во время отправки личного дела и загрузки сравнения поля формы временно
   `inert`: текст, набранный во время запроса, не может незаметно исчезнуть при
   замене формы. Кнопка закрытия остаётся доступной. Закрытие, смена аккаунта,
   пространства или маршрута делают поздний ответ неактуальным; он не очищает
   черновик и не открывает прежнюю форму поверх другого экрана.
8. При недоступной сети либо исчезнувшем/архивированном деле редактор сохраняет
   локальные поля и версию. Удаление или принятие черновика не предлагается от
   имени записи, которую не удалось получить.

### Ручной сценарий для проверки выпуска

1. В окне A открыть существующее личное дело, изменить заголовок и оставить
   редактор открытым.
2. В окне B изменить это же дело и сохранить.
3. В A нажать «Сохранить»: ожидать 409, сохранённый локальный текст и панель
   конфликта. Повторное нажатие «Сохранить» не отправляет ещё один PATCH.
4. Нажать «Загрузить сохранённое дело для сравнения»: заголовок формы остаётся
   локальным, в раскрываемом сравнении виден заголовок из B.
5. Выбрать продолжение с черновиком и сохранить: PATCH использует просмотренную
   новую версию. Альтернативная проверка — удалить черновик и открыть сохранённое:
   появляется текст из B, а запрос изменения записи отсутствует.
6. Отдельно закрыть конфликтующий редактор через ×, перезагрузить страницу и
   снова открыть дело: старый черновик восстанавливается со сравнением, без
   бесконечной петли 409.

### Пояснение зависимости цели и проекта

Сервер сохраняет правило наследования: если выбрана цель со своим проектом,
пустой `projectId` заполняется проектом цели. Поэтому выбор «Без проекта» сам по
себе не снимает связь, пока сохранена такая цель. При выбранной цели под полем
проекта теперь прямо написано: «Если цель связана с проектом, “Без проекта”
сохранит проект цели. Чтобы убрать обе связи, сначала выберите “Без цели”».
Смена цели обновляет пояснение; редактор не сбрасывает цель автоматически.
Новая несовместимая пара по-прежнему отклоняется сервером с объяснением, а поля
остаются для исправления. Редактор самой цели в этой работе не расширяется.

редактора: сравнение известной старой версии и явный отказ от черновика;
полный путь 409 → загрузка → сравнение → успешный PATCH; сохранность при ошибке
хранилища/загрузки/исчезновении записи и смене контекста; запрет очистки черновика
другого аккаунта, пространства или уже закрытой формы. Проверка пояснения о
