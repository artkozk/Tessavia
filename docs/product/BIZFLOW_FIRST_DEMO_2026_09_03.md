# Первая демонстрация команде: самостоятельная работа

## Подготовка

Использовать отдельную демонстрационную команду, не реальные клиентские карточки.
Проверить вход участников и выдать им доступ только к нужному проекту. Регистрация
пока работает в проверочном режиме: отображаемый тестовый код не является
подтверждением доставки письма. Не обещать боевую почтовую верификацию.

## Команда и CRM

1. В боковом меню открыть **Команды и проекты**, нажать **Новая команда**.
   Создаются команда и её первый проект. В **Участники и проекты** доступны
   приглашения и другие проекты. Для настройки прав нужен владелец/администратор.
2. Открыть **Доски**, нажать **Создать доску**. Ввести название процесса и название
   карточки, например «Заявки клиентов» и «Заявка». Следующая доска создаётся
   кнопкой **Новая доска** рядом с вкладками.
3. Через **Настроить** изменить этапы и добавить поля, например категорию и номер.
   Создать карточку, выбрать ответственного, приоритет и необязательный срок.
4. Открыть **Календарь** на доске. Он уже отфильтрован по этой доске. Выбрать день,
   открыть исходную карточку. Через **Назначить карточку** выбрать существующую
   запись и новый срок: карточка не копируется, срок меняется везде.
5. Показать фильтры ответственного/состояния, цвет по этапу или приоритету,
   переключение «Месяц / Расписание». «12 недель и год» открывает прежнее
   планирование. Не выдавать срок карточки за длительность занятости сотрудника.

## Личный помощник и связи

1. **Календарь → Личное**, выбрать субботу, создать план «К бабушке на дачу».
   Указать окончание в воскресенье и выбрать цвет. План показан в оба дня.
2. Открыть план, нажать **Заметка**, записать продукты. После сохранения список
   находится прямо внутри плана. Он также доступен среди личных заметок.
3. Отдельно создать заметку «Взять с собой». В списке заметок нажать **Связать**,
   выбрать поездку. Вернуться в поездку: обе заметки собраны вместе без копий.
4. Показать редактирование заметки и обратный переход по связи. Личный текст
   не виден другим участникам, даже если заметка ссылается на общую карточку.

## Персонализация и границы

Настройка доступна через кнопку **Настроить страницу** в верхней панели. Для
телефона и ПК сохраняются независимые настройки. **Настроить меню** управляет
видимыми разделами. Изменение видимости не удаляет данные и не меняет права.

В этом выпуске не обещать синхронизацию Google Calendar, повторяющиеся события,
автоматические связи без подтверждения, полный аналог Telegram или полностью
готовую произвольную CRM-интеграцию. Эти направления остаются в реестре задач.
Для первого клиента отдельно согласовать его поля, этапы, права и данные импорта.

## Дополнение 03.09.2026: актуальное название, регистрация и речь

Актуальное название продукта — **Tessavie**. Подготовлены [текст выступления для бизнеса и сотрудников](TESSAVIE_PRESENTATION_SCRIPT_2026_09_03.md) и [обоснованные приоритеты развития](TESSAVIE_PRODUCT_PRIORITIES_2026_09_03.md). Речь связывает командный процесс с самостоятельной личной пользой и заканчивается предложением выбрать один процесс для пилота.

Абзац о тестовом коде в начале этого документа описывает более ранний режим. По последующему выпуску [прямой регистрации](../operations/TESSAVIE_DIRECT_REGISTRATION_2026_09_03.md) новый пользователь входит сразу после заполнения формы, без ввода кода. Регистрация без приглашения создаёт только личное пространство. Проверка владения почтой и её реальная доставка этим не подтверждаются. Исторический абзац сохранён, чтобы объяснить отличие прежней демонстрации от актуального поведения.

Маршрут выше остаётся инструкцией для репетиции: подготовка речи не подтверждает создание демонстрационной команды, готовность каждого шага на текущем сервере или выполнение незакоммиченных изменений управления командами. Перед показом нужны проверенные учебные примеры, вход и доступы. Для привлечения личных пользователей отдельно показывать личный план со связанной заметкой и объяснять приватность; одной демонстрации корпоративной доски для этого недостаточно.
