# Изоляция дочерних узлов карты

Во время работы над `98781560e9a1ca14c22e187f00d67c5e` обнаружено: `/api/graph`
ограничивал основные карточки выбранным проектом, но четыре последующих запроса
вопросов, ответов, принятых итогов вопросов и вариантов исследований не имели
проверки `workspace_id`. Их узлы добавлялись в JSON непосредственно, поэтому
проверка концов связи не защищала от передачи содержимого другого проекта.

Это исправляется отдельным выпуском перед синхронизацией раскладок. Во всех
четырёх запросах ограничение проекта применяется в SQL через родительскую
карточку, включая режим с архивом. Права запроса самого проекта сохраняются.
Миграции и оформление не меняются.

Регрессионный тест создаёт два проекта и два аккаунта. Участник первого проекта
не имеет доступа ко второму. В каждом проекте создаются вопрос, ответ,
принятый итог и вариант исследования. Проверяются оба режима архива, отсутствие
чужих дочерних узлов/связей, сохранение своих объектов, переключение владельца
между проектами и 403 для запроса недоступного проекта. На прежнем обработчике
этот тест воспроизводит передачу чужого дочернего узла.

Раскладки и миграция 033 остаются отдельной незавершённой работой. Бинарник
исправления собирается из чистого checkout его commit, чтобы не включить
незавершённую функциональность. Скрипт проверяет копию БД, неизменность всех
таблиц и строк, исполнимость приложения, health и сохранность прежних функций.

Фактические commit, release, резервная копия и результат проверки production
добавляются после публикации. Доказательство добавляется в существующую задачу;
весь объём раскладок и сквозной приватности этим не считается завершённым.
