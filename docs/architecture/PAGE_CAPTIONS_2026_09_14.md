# Понятное редактирование подписей системных страниц

## Причина и граница

Пользователь нашёл настройку текста, но описал последовательное открытие
разных элементов как неудобное. На финансовом экране также смешивались
создание дохода и общее создание заметок. Изменение названия должно быть
действием оформления, а не исправлением записей или изменением формулы.

Текущий этап добавляет единый экран «Тексты и подписи» в редактор оформления.
В нём видны исходные подписи, доступен поиск, ввод своего названия и возврат
исходного. Применение обновляет черновик страницы; окончательное сохранение
остаётся общей кнопкой оформления. Это позволяет сначала проверить результат.
Клик по заголовку и статичной подписи в режиме настройки ведёт в тот же экран.
Поиск не считается изменением, введённый текст защищён проверкой закрытия.

## Хранение и совместимость

Используется существующий `PageLayout.texts`, отдельно для страницы,
пространства, аккаунта и устройства. Миграции данных нет. Ключ заголовка
остаётся прежним, например `heading`. Новые подписи имеют стабильные ключи
`label:finance-add-expense`, а не индекс элемента или хеш пользовательского
текста. Предел совпадает с сервером: 160 Unicode code points на подпись.
Пустой текст или исходное значение возвращает стандартную подпись.
Изменение доступных подписей не удаляет настройки отсутствующих элементов.

Старая настройка финансового заголовка `texts.heading` используется как
резерв для `label:finance-title`. Самостоятельный заголовок финансов заменяет
повторяющий внешний заголовок личного раздела. При явном применении подписей
выбор переносится в новый ключ; чтение страницы не перезаписывает профиль.
Публикация набора оформления по прежнему контракту не переносит личные
текстовые настройки. Текст собственного блока страницы хранится в его схеме.

## Контракт элементов

`web/page-labels.js` обрабатывает только явные `data-page-label` на текстовых
элементах без вложенных контролов. Иконки и обработчики кнопок сохраняются.
Суммы, даты, значения полей, имена отправителей и содержимое записей не
подбираются автоматически как подписи. Два элемента с одним ключом получают
одинаковое название. Начальный текст хранится для возврата без перезагрузки.
Новые модули должны помечать статичные подписи стабильными ключами.

Это не заявляет редактирование всех слов во всех диалогах приложения.
Сейчас доступны заголовки зарегистрированных блоков и размеченные подписи
финансов. Общее оформление вложенных элементов и состав собственных блоков
остаются задачей конструктора с собственными схемами и редакторами.

## Финансовый контекст и меню

На финансовой странице убраны общее «Создать» личного пространства и
«Записать во входящие» в верхней панели: операции дохода/расхода принадлежат
финансовому модулю. Остальные страницы сохраняют свои действия.
«Финансы» больше не добавляются в меню по умолчанию без выбора пользователя.
Если человек явно сохранил этот пункт, `navOrder` сохраняет его видимость;
скрытый пункт остаётся скрытым. Добавление доступно в общем редакторе меню.
Профили существующих пользователей не переписываются пакетно.

## Приёмка

Обязательны: изменить и сбросить подпись, проверить несколько её экземпляров,
сохранить оформление/reload, повторно открыть редактор, отменить ввод,
проверить отдельные телефонные настройки и длинный текст на 320 px.
Исполняемые тесты проверяют сохранение исходной подписи, исключение полей,
отсутствие изменения исходного объекта и границы Unicode. Результаты реального
браузера и выпуска дописываются в операционный отчёт после выполнения.
