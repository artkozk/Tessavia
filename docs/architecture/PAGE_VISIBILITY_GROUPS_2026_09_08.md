# SC-87 — несколько условий показа блока

## Зачем это нужно

У пользователя должна быть возможность самостоятельно собрать последовательность работы. Например, следующий материал открывается после подготовки и чтения, либо после любого из двух альтернативных этапов. SC-83 позволял связать показ только с одним показателем. Теперь в разделе «Когда показывать блок» можно добавить до 8 проверок и выбрать «Все условия» или «Любое условие». Это настройка обычного конструктора, а не отдельная запрограммированная страница. Пользовательский набор за пользователя не собирался.

Рабочая задача: `5e183e1823ab514034b9c7fce636d418`, родитель `2ad192a4298615883945e23a87d8ecd2`. Создание на сервере подтверждено VISIBILITY_GROUPS_TASK_2026_09_08.json.

## Контракт и совместимость

Старый объект visibility с source, metric, operator, value сохраняет прежний смысл. Группа хранит mode=all/any и conditions из 1–8 одиночных проверок. Каждая проверка ссылается на другой блок tracker этой же страницы. Метрики: выполнено, осталось, процент; сравнения: равно, не равно, больше, не меньше, меньше, не больше. Порог — целое 0–500 пунктов или 0–100 процентов. Проценты вычисляются без округления. Источник без видимых пунктов не выполняет условие. Скрытые пункты исключены из подсчёта.

Сервер проверяет каждую ветку, даже если логика «Любое» могла бы завершиться раньше. Граф учитывает все ссылки. DFS различает текущий путь и уже проверенные вершины: цикл во второй ветке отклоняется, а общий предок двух этапов разрешён. Самоссылки, вложенные группы, неизвестные режимы/метрики/операторы, смешивание свойств группы и одиночного правила отклоняются. Ручное скрытие блока имеет приоритет; его зависимости также проверяются.

Удаление первого условия не меняет значения остальных. Оставшееся одно условие преобразуется в совместимый одиночный объект. Удаление последнего удаляет visibility целиком и показывает блок сразу. Это явно объясняется рядом с настройкой. Размеры, отступы и цвета используют существующее оформление платформы.

Предпросмотр предлагает отдельный счётчик для каждого уникального источника из всех веток. Счётчики создают временные отметки только для отображения; настоящие отметки не записываются. На обычной странице используются личные отметки текущего человека. Правило показа не является контролем доступа: имеющий доступ к странице получает её определение, а права на изменение страницы и действия с данными проверяются отдельно.

Сохранение набора переносит все правила и связи. Установка создаёт независимую страницу без отметок автора. Изменение условий в копии не меняет оригинал или сохранённый набор. Проверка expectedRevision и отказ устаревшему редактору 409 сохраняются.

## Проверенные сценарии

1. Через интерфейс собрана синтетическая страница с подготовкой из двух пунктов, чтением из одного пункта и следующим текстовым этапом. Настроены две проверки «Осталось равно 0». Закрытие, reload и восстановление черновика сохранили группу.
2. В предпросмотре подготовка=2 при чтении=0 не открывает этап; чтение=1 открывает. После сохранения настоящие отметки обоих источников остались пустыми.
3. В обычном использовании отмечены оба пункта подготовки: этап скрыт. Отмечено чтение: этап появился. Чтение отменено: этап скрылся. Переключение на «Любое» показало этап при завершённой подготовке; отмена одного пункта подготовки снова скрыла его.
4. Приватный набор сохранён через UI, просмотр показывает оба условия и текст. Установлена отдельная копия без отметок. Первое условие удалено, страница сохранена и перезагружена: остался источник «Чтение». Затем последнее условие удалено с сохранением/reload: текст виден без отметок. Локальный API подтвердил, что оригинал сохранил any и оба условия, а копия не содержит visibility.
5. Проверены редактор, длинная подпись, меню и результат при 320×800; обычная ширина восстановлена. Физические телефоны не проверялись.

Go integration: все ветки, общий предок, цикл, ошибки группы, права участника, изоляция личных отметок, перенос набора, независимость копии, stale409. Node: all/any, оба источника симуляции, ручное скрытие, удаление первого/последнего. Полный go test ./...: internal/app 64.014 s, web 0.369 s; go vet ./... успешен. 271 Node-тест прошёл за 762.9317 ms. После уточнения текста ошибки целевые Go прошли за 0.821 s. Доказательства: VISIBILITY_GROUPS_LOCAL_2026_09_08.json. Проверки выполнены на синтетических данных; клиентские данные с сервера не переносились.

## Выпуск и границы

Изменения не требуют миграции: 117 таблиц, схема 065. Штатный скрипт делает резервную копию на текущем сервере, dry run со сравнением всех строк, проверяет HTTPS/assets/health/401/nginx/integrity/FK. Откат на SC-86 блокируется при наличии сохранённой группы visibility в страницах или наборах: прежняя версия не понимает такой объект. Проверка выполняется после остановки службы, чтобы не пропустить запись во время переключения. Фактическая квитанция дополняется после выпуска.

Родительские задачи остаются открыты. Пока источники условий — блоки личных отметок, группы плоские; произвольные данные, привязки текста/цвета/размеров к значениям, вложенные компоненты и настройка всех встроенных элементов требуют следующих этапов. Этот выпуск не закрывает универсальный конструктор, чат и команды.
