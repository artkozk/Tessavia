# SC-76. Связанный список записей и переносимые схемы

## Зачем этот этап

Следующий критерий 26c54f79aa1c9110536670ae8371a868 — дать пользовательской странице реальные типизированные данные и действия. SC-74 создавал самостоятельные блоки, а SC-75 защитил поля от потери конкурентных правок. Новый этап соединяет страницу с существующими коллекциями/records и переносит зависимую схему вместе с набором. Отдельная задача 5bf22f7a33f2cee34ab73fd3a6d62329 «P0 · Подключать записи к странице и переносить схемы набором», in_progress до фактического выпуска.

## Что меняется

В библиотеке блоков появляется «Список записей». Администратор выбирает доску своего пространства, заголовок, отображаемые поля, видимость кнопки создания и её подпись. Размеры и оформление блока работают как у других блоков. Список показывает действующие карточки выбранной доски, поиск по названию и выбранным значениям полей, порции по20 записей и «Показать ещё». Клик открывает существующую карточку с правами/историей. Кнопка создания открывает существующую проверенную форму доски; после сохранения запись появляется в списке.

Это **ещё не произвольный конструктор формы**. Название, описание, ответственный/приоритет и расположение формы пока следуют прежней форме доски; пользовательские поля настраиваются в разделе «Доски». Свободный выбор/порядок/подписи всех полей формы и произвольные действия остаются следующим этапом. Встроенная читалка не считается полностью воспроизводимой данным блоком.

Недоступный или архивный источник показывает понятное состояние, а не чужие записи. Сохранение конфигурации проверяет принадлежность доски и выбранных полей пространству, отсутствие повторений и действующий состав. Удаление блока не удаляет источник или записи. Скрытые блоки остаются в наборе со своими зависимостями. Заголовок страницы больше не говорит о личных отметках, если на странице нет трекера.

## Набор с источниками

При сохранении набора сервер снимает схемы всех используемых досок в одной читающей транзакции: названия/описания, тип карточки, этапы, активные поля, варианты и начальные значения. Две ссылки на одну доску дают один снимок источника. В definition.collections нет строк records, отметок пользователей, счётчиков исходных карточек и привязки к исходному workspaceId. В диалоге объясняется перенос схем/начальных значений и отсутствие данных; предпросмотр показывает имя источника и раскрываемый список полей.

Установка создаёт новые доски, этапы, поля и варианты с новыми ID. Названия копий человекочитаемые: «… · копия», «… · копия 2». Идентификаторы выбранных полей и источников страницы переназначаются. Начальный select/multi_select переписывается на новые ID вариантов; числа, false и другие скалярные значения сохраняются как JSON. Начальная ссылка user/relation не переносится. Обычные поля связи остаются пустыми для явного заполнения пользователем.

Страница и все её источники устанавливаются в одной транзакции. Отсутствующая/повреждённая зависимость откатывает также уже вставленные доски/поля. Существующие доски и их записи не обновляются. После установки UI перечитывает страницы и коллекции текущего пространства; поздний ответ после смены пространства не записывает старые данные в новое. Установленная копия пригодна для новых записей сразу, без перезагрузки браузера.

Границы первой реализации: до40 выбранных полей блока, до100 полей/этапов в переносимом источнике, сериализованная структура набора до2МБ. Ограничения возвращают явную ошибку, не обрезают схему. Произвольные SQL/JavaScript не исполняются. Новых таблиц и миграций нет: используется схема064 с116таблицами.

## Проверки

Интеграционный тест TestPageAppRecordSourcesInstallIndependentSchemasWithoutData проверяет источник другого пространства, снимок одной доски для двух блоков, отсутствие исходной записи/ID/пространства в наборе, независимые новые IDs, перенос начального select на новый вариант, создание записи с перенесённым значением по умолчанию, сохранность оригинала, отклонение отсутствующего поля и rollback повреждённой зависимости без лишней доски. Предыдущие тесты прав/приватности/отметок/публикации остаются в прогоне.

Локальная UI-приёмка и фактический выпуск дописываются после завершения. Само наличие этого документа не закрывает задачу и не означает завершение общего конструктора данных/форм/действий.
