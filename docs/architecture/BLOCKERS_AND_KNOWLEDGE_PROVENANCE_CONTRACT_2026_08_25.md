# Контракт блокеров и происхождения знаний

Дата: 25 августа 2026 года.

## Инварианты

1. Направление зависимости всегда читается как `source зависит от target`.
2. Активный блокер вычисляется из актуального состояния target и не хранится отдельным флагом в source.
3. Терминальные состояния блокера: `completed`, `cancelled`, `archived`, `rejected`.
4. Смена статуса target немедленно меняет вычисляемый список блокеров без фоновой задачи и без изменения source.
5. Блокер не меняет официальный статус source автоматически.
6. Карточка знания остаётся обычной единственной записью типа `criterion` или `decision`; метаданные расширяют, но не дублируют её.
7. Точный источник совместного вывода сохраняется одновременно в неизменяемой цепочке происхождения и в доступном для чтения `sourceExcerpt`.
8. AI и поиск обязаны получать новые поля, иначе пользователь видит знание, которое не видит система.

## Модель ответа карточки

Каждый объект `Record` содержит массив `blockers`. Пустой массив возвращается явно, чтобы клиент не различал `не загружено` и `нет блокеров` по отсутствию свойства.

Элемент блокера содержит ID, публичный предметный тип, название, статус, ID и логин ответственного. Полное содержимое не дублируется: пользователь открывает исходную карточку по ID.

`RecordBusinessDetails` дополнен полями:

- `applicability`;
- `sourceExcerpt`;
- существующий `reviewAt` используется также критериями и рисками.

## Вычисление

Список и детальный API после чтения карточек выполняют один общий запрос активных зависимостей и распределяют результаты по source ID. Для списка не выполняется отдельный запрос на каждую строку. Это сохраняет предсказуемое число обращений к БД и устраняет N+1-поведение.

## Транзакционность происхождения

При создании правила, вывода, предпочтения или ограничения из совместного вопроса в одной транзакции создаются:

1. итоговая карточка;
2. специальные предметные данные с исходной формулировкой;
3. связь `produced`;
4. неизменяемая запись происхождения;
5. события истории источника и результата.

Если любой шаг не выполнен, карточка результата не появляется частично.

## Изменения схемы и экспорт

Миграция `013_blockers_and_knowledge_provenance.sql` добавляет текстовые поля знания и индекс активных зависимостей. Полный JSON-экспорт имеет текущую версию 9. Указанная в более раннем документе версия 8 остаётся исторической версией релиза business memory; версия 9 требуется, потому что форма `recordBusinessDetails` расширилась.

## Проверки

Автоматические тесты подтверждают:

- незавершённая target-карточка возвращается как блокер source;
- после терминального статуса target блокер исчезает;
- область применения, источник и дата пересмотра сохраняются;
- исходный фрагмент участвует в глобальном поиске;
- правило из совместного вопроса получает точную формулировку общего итога.
