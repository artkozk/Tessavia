# Конструктор: варианты, несколько значений и предпросмотр

Новый прямой запрос пользователя 07.09.2026: продолжать работу без остановки
после отдельного этапа, улучшать кастомизацию конструктора и понятность для
разных процессов. Этот документ дополняет прежний контракт; старые ограничения
и решения в предыдущих документах не удаляются.

Проверяемые сценарии: изменить справочник выбора без потери уже заполненных
карточек; выбрать несколько значений обычным нажатием на телефоне; попробовать
обязательные поля до создания рабочей записи; вернуться к незавершённому вводу;
открыть прежний разговор после перезагрузки. Изменения относятся к общей схеме
выбранной доски, черновики и выбор разговора — к пользователю и проекту.

Варианты select/multi_select редактируются с сохранением ID. Поле передаёт
expectedUpdatedAt, весь существующий набор ID и новые имена без ID. Сервер
атомарно проверяет версию, принадлежность, повторённые ID/имена, непустые имена
до 80 символов, набор до 1000 вариантов. Удаление прежнего варианта этим
действием не допускается: отдельный понятный архив вариантов ещё не реализован.
Переименование, включая обмен двумя названиями, и добавление не переписывают
record_field_values. Новые варианты получают новые ID. История фиксирует
изменение поля; неудачная операция откатывает и метаданные поля, и варианты.
Миграции нет. Прежний PATCH без options остаётся совместимым.

Несколько значений представлены группой флажков с количеством выбранных.
Обязательность означает хотя бы один выбор, а не все флажки. Payload содержит
ID вариантов. Длинный список ограничен по высоте, названия переносятся.
Используется одна форма полей в создании, изменении, прикреплении к доске и
предпросмотре. Ctrl/Cmd для выбора больше не нужен.

Предпросмотр открывается в конструкторе и использует текущие сохранённые поля
и колонки. Пользователь может проверить заполнение; ни карточка, ни значения
на сервере при этом не создаются. Редактор схемы остаётся под окном предпросмотра.
Черновики карточек и настройки вариантов восстанавливаются отдельно по доске/
карточке/полю; после успешного сохранения соответствующий черновик очищается.

Выбранный разговор сохраняется по пользователь/проект как один ID. После
загрузки свежего разрешённого списка ID проверяется; недоступный разговор не
восстанавливается, выбирается доступный. Недоступность localStorage не ломает
вход в чат. Содержимое переписки в настройку выбора не записывается.

Это ограниченный этап конструктора. Собственные типы объектов, вычисляемые
поля, зависимости обязательности, архив вариантов и шаблоны процессов остаются
в работе; переименование базовой задачи не считается собственным типом.
Фактические проверки и выпуск дополняются после выполнения.
