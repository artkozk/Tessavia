# Поиск и командный фильтр очереди работы

## Запрос и причина

Пользователь показал наложение лупы на начало строки поиска и попросил
заменить «Партнёра»: продукт рассчитан на команду, а не на двух человек.
Предыдущие контракты и выпуски не удаляются. Этот документ уточняет только
панель очереди, не объявляет выполненной всю переработку командной модели.

В CSS общий input с двумя :not([type=...]) получил специфичность 0,2,1,
поэтому перекрывал padding-left:36px у .work-search input (0,1,1).
Текст начинался на 12 px, в области значка. Аналогично затрагивались
глобальный поиск и поиск карты. Теперь условия исключения checkbox/radio
помещены в :where: общий стиль снова имеет специфичность обычного input,
а компонентные отступы и размеры действуют штатно. Исключение флажков
и их отдельные размеры 18×18 остаются; !important не добавлен.

## Поведение

- Подписи: «Вся», «Моя», «Других участников».
- «Вся» включает текущего пользователя; «Моя» только его работу;
  «Других участников» всех остальных, без привязки к одному человеку.
- Результат одинаков в списке, доске и календаре; выбор конкретного
  ответственного по-прежнему имеет приоритет над группой.
- Внутренний ключ partner сохранён для ссылок, истории навигации и
  сохранённых представлений. Миграция данных не нужна, права не меняются.
- Добавлены доступное имя поиска, имя группы и aria-pressed для кнопок.
  Длинная подпись может переноситься, не расширяя экран.

## Проверки и выпуск

Добавлены регрессионные тесты приоритета CSS, подписи и фильтров для трёх
участников. Браузерная проверка должна охватить ПК, 390/320 px, ввод,
нажатие в зоне значка, результаты фильтра, глобальный поиск и флажки.
Физические телефоны не проверяются в рамках эмуляции ширины браузера.

Перед публикацией: все Go/Node-тесты, vet, синтаксис, commit/push.
Деплой под блокировкой со сверкой предыдущего release и SHA-256, резервной
копией и запуском на копии БД. Миграций нет; строки всех таблиц должны
совпасть. Фактические результаты и задача платформы дополняются ниже.

## Уточнение: только «Вся» и «Моя»

После первого выпуска пользователь указал, что третий переключатель
избыточен. Актуальное решение отменяет его, а не подбирает ещё одну
подпись. Предыдущие разделы остаются историей изменения требований.

1. На панели остаются две кнопки: «Вся» и «Моя».
2. Для конкретного человека используется существующий фильтр
   «Ответственный». Он сохраняет приоритет и не дублируется новой кнопкой.
3. Старые сохранённые представления и история навигации с scope=partner
   открываются как «Вся». Обе функции выборки (список/доска и календарь)
   больше не исключают текущего пользователя по этому устаревшему ключу.
   При построении панели значение нормализуется до all, поэтому «Вся»
   подсвечивается корректно. БД и сохранённые определения не переписываются.
4. Исправление отступа лупы, доступные имена, мобильная адаптация и
   пользовательские настройки остаются. Версия ресурсов увеличена до

## Уточнение: режим только для совместного проекта

После двухкнопочного выпуска пользователь уточнил границу требования.
В проекте разработки с другим участником нужен быстрый отдельный просмотр
его работы. В остальных проектах третья кнопка не нужна, но двухкнопочный
контейнер не должен сохранять под неё пустое место. Это уточнение не
возвращает подпись «Партнёра» и не предполагает, что в проекте всегда
ровно два человека.

Актуальный контракт панели:

1. В командном проекте, где API проекта возвращает хотя бы одного другого
   участника, доступны «Вся», «Моя», «Других». Последний режим показывает
   работу всех остальных участников и поэтому подходит и для пары, и для
   растущей команды.
2. В личном пространстве и командном проекте без других доступных
   участников отображаются только «Вся» и «Моя». Контейнер использует
   `width:max-content`, а сегменты не растягиваются в зарезервированную
   ширину: справа не остаётся визуальной пустоты.
3. Внутренний ключ `partner` снова используется для режима «Других», чтобы
   не мигрировать старые сохранённые представления. Он действует только
   когда в текущем командном проекте действительно есть другой участник;
   в остальных контекстах безопасно нормализуется в `all`.
4. Фильтрация исключает текущего пользователя одинаково в списке, доске и
   календаре. Явно выбранный «Ответственный» по-прежнему имеет приоритет.
5. Та же задача `7b488651ab289fe206645aef8a295b7c` переоткрывается новым
   уточнением, а не дублируется. Старые разделы этого журнала сохраняются
   как история изменения требования и не описывают актуальное поведение.

Маркер ресурсов `20260903-work-scope-1` принудительно обновляет JS, CSS и
service worker. Автотесты, адаптивная проверка, commit, release, backup и
production-подтверждение будут дописаны ниже после фактического выполнения.
