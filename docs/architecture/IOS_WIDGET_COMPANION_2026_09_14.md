# Нативный iPhone-виджет Tessavie — этап 14–15.09.2026

## Основание и результат этапа

Пользователь напомнил, что ранее просил приложение и виджеты для iPhone,
а web-установка и ярлыки не заменяют меняющийся блок на домашнем экране.
Прежняя оценка в [мобильном исследовании](MOBILE_WIDGETS_AND_NOTIFICATIONS_2026_09_14.md)
сохранена; этот документ описывает конкретный проект приложения и расширения
в `mobile/ios`, который использует уже реализованный
[серверный протокол виджетов](WIDGET_DEVICE_GRANTS_2026_09_14.md).

Созданы SwiftUI companion, WidgetKit extension, AppIntent-выбор источника,
общий Keychain, зашифрованный локальный снимок, XcodeGen-спецификация и тесты.
Они не являются переносом сайта в WebView. Основной сайт и настройка структуры
остаются прежними. Код предназначен для iOS/iPadOS 17 и новее; это явная граница
первого этапа, а не утверждение о поддержке всех старых iPhone.

Поддерживаются обычные `tracker` и `progress` из конструктора. Пользователь
сам создаёт их на странице, выдаёт код для выбранного блока и подключает его.
Каждый экземпляр системного виджета может выбрать свой ранее подключённый
источник. Разработчик не создаёт страницы или наборы в его пространстве.

Виджет только читает отметки и итог. Нажатие открывает корень сайта в браузере.
Изменение отметок, произвольные формы, финансовые таблицы, отдельный личный
модуль привычек, native APNs и WidgetKit push этим этапом не реализованы.
Уже существующие PWA/Web Push продолжают быть отдельным работающим каналом;
данный проект не выдаёт наличие `.swift` файлов за готовую доставку уведомлений.

## Пользовательский путь и единое место настройки

1. В Tessavie открыть единые настройки → «На телефоне» → «Виджеты».
   Выбрать текущую страницу и блок, назвать устройство, создать код.
2. Открыть Tessavie Widgets и вставить код в защищённое поле.
   Сайт-пароль, email и браузерная cookie приложению не нужны.
3. После успешного обмена приложение получает первый снимок и показывает
   название блока, итог, дату обновления и срок доступа. Если сеть пропала
   после обмена, сохранённый доступ остаётся доступен для повторного обновления.
4. Через системное меню iPhone добавить «Блок Tessavie» на экран «Домой».
   В стандартном «Изменить виджет» выбрать подключённый источник.
5. Структуру, текст и пункты менять в конструкторе сайта. Телефон перечитывает
   тот же блок. Список подключений в companion не становится вторым редактором.

В приложении есть только подключение кода, список собственных локальных
подключений, ручное обновление, удаление локальных данных и ссылка на сайт.
Настройки блока, выдача и отзыв серверного доступа остаются в общем центре
настроек Tessavie. В боковое меню ничего не добавляется.

Код хранится только в SwiftUI-state. После нажатия «Подключить» поле очищается;
при уходе приложения из активного состояния введённый код также очищается.
Он не попадает в URL, UserDefaults, App Group-файлы или журнал. Если сервер
принял код, а сохранение в Keychain не удалось, приложение прямо сообщает,
что надо отозвать этот доступ на сайте и создать новый код. Повторное получение
того же одноразового секрета не имитируется.

«Убрать с телефона» удаляет локальный токен и копию данных. Перед действием
показано, что серверный grant надо отдельно отозвать на сайте. Read-only token
не получает скрытых дополнительных прав для управления всем аккаунтом.

## Оформление и поддерживаемые размеры

Светлая палитра совпадает с Android companion: основной фон `#F4F3EE`, зелёный
акцент `#126B58`. Тёмный вариант использует тёмный зелёный фон и светлый зелёный
акцент, основной/вторичный текст — системные семантические цвета. Это сохраняет
контраст, вместо прямого применения произвольного пользовательского фона,
который может скрыть текст. Серверные `color/background` не включены в первый
native-renderer; размеры и оформление страницы не обещаны пиксельной копией.

`systemSmall` показывает заголовок и крупное «выполнено из всего» с полосой
прогресса. `systemMedium` добавляет до двух подписей, `systemLarge` — до пяти.
Полный итог остаётся серверным, а не пересчитывается по отображаемым строкам.
Для progress нет списка исходного tracker, поскольку сервер намеренно выдаёт
только выбранный агрегат. Длинные подписи ограничены строками внутри виджета;
название читается VoiceOver, итог имеет отдельное цельное описание.

Пользовательские заголовки, подписи и прогресс помечены `privacySensitive()`.
Физический крупный шрифт, тонированный режим, VoiceOver и системное скрытие
при блокировке должны пройти отдельную проверку на устройстве. Исходники
самого UI не являются доказательством этой проверки.

## Обмен без браузерных полномочий

`WidgetAPI` использует ephemeral URLSession. Отключены cookie storage,
автоматические cookies, credential storage и URLCache. Pairing идёт JSON-телом
на `POST /api/mobile/widgets/redeem`, чтение — Bearer-заголовком на
`GET /api/mobile/widget`. Другие API-пути этим клиентом не принимаются.

Разрешены только HTTPS, точный hostname `control.e-rd.ru`, отсутствие userinfo,
query и fragment, стандартный порт. Redirect delegate возвращает `nil` для
любого редиректа, в том числе на тот же origin: Authorization не пересылается.
Окончательный response URL и путь перепроверяются до разбора JSON. TLS-проверки
системы не отключаются, исключений ATS нет. `openUrl` принимается только `/`;
внешние ссылки, схемы и будущие query-параметры нельзя молча добавить в allowlist.

Ошибка провайдера не показывается как произвольная строка ответа. Для
пользователя используются фиксированные сообщения. `WidgetGrant.description`
и debugDescription редактируют токен; production-код не печатает запросы,
ответы, pairing или ключи. Полученный snapshot проверяется по widgetId,
допустимому типу, границам total/completed, длинам подписи и списка, формату
даты и разрешённому переходу. Некорректный ответ не превращается в нулевой
«успешно обновлённый» прогресс.

## Keychain, App Group и кеш

Bundle ID приложения — `ru.tessavie.widgets.ios`, расширения —
`ru.tessavie.widgets.ios.WidgetExtension`. Оба используют App Group
`group.ru.tessavie.widgets` и Keychain group
`$(AppIdentifierPrefix)ru.tessavie.widgets.shared`.

Настоящий AppIdentifierPrefix подставляется при подписи. Его значение также
присутствует в Info.plist обоих targets для явного Keychain query. Никаких
Team ID, сертификатов, профилей и ключей публикации в репозитории нет.
Provisioning профили должны разрешать одинаковые capabilities обоим targets.
Unsigned simulator compile этого не доказывает.

Каждый grant хранится отдельным Keychain item, `WhenUnlockedThisDeviceOnly`,
без синхронизации в iCloud. Общий ключ AES-256 также находится в Keychain.
App Group содержит только список технических grant-ID и AES-GCM ciphertext
снимков. Каталог исключён из backup, файлы защищены Complete File Protection.
В них нет токена, кода, открытого пользовательского заголовка или подписи.

Операции приложения и расширения сериализуются файловым lock. Сохранение
снимка повторно сверяет наличие того же grant и токена: сетевой ответ,
пришедший после локального отключения, не восстанавливает удалённый кеш.
Неожиданный ID не используется как путь. Повреждённая или не прошедшая
AES-GCM проверку копия удаляется и не отображается.

При `401/403` токен и кеш удаляются, виджет просит подключить источник заново.
Невозможность прочитать Keychain на заблокированном телефоне не обходится
копией секрета в UserDefaults: выдаётся нейтральное состояние. Обычный выход
из веб-сессии не удаляет независимый grant; отзыв в настройках, истечение
90 суток и смена пароля проверяются сервером при следующем чтении.

## Время, offline и системный планировщик

Snapshot хранит отдельно серверный `updatedAt` и локальный `fetchedAt`.
Виджет показывает дату получения данных. При сетевой ошибке или rate429
показывается явно подписанная сохранённая копия, если она ещё допустима.
Она ограничена одновременно сроком grant и 24 часами с последнего получения.
Существенный перевод часов назад делает копию недопустимой.

Timeline запрашивает следующее обновление через 30 минут; это пожелание,
не гарантия точного расписания. В него также включены заранее подготовленные
записи для пометки старого снимка и скрытия после предельного срока, чтобы
постоянная сеть не была условием локального истечения. Обновление из приложения
вызывает `WidgetCenter.reloadTimelines`, но iOS сохраняет право выбрать время.

Мгновенный отзыв уже показанного изображения на отключённом от сети устройстве
не обещается. Сервер отзывает grant сразу; приложение узнаёт при следующем
успешном обращении. WidgetKit сохраняет собственное представление во внешнем
процессе — это ещё одна причина физической приёмки блокировки, privacy и срока.

## Сборка, тесты и что ещё нужно для раздачи

`mobile/ios/project.yml` — источник XcodeGen-проекта. Генерируемый `.xcodeproj`
и локальные build-артефакты не коммитятся. Есть отдельные schemes:
`TessavieWidgets` собирает приложение и extension, `TessavieWidgetTests`
запускает hostless unit tests без аккаунта пользователя и production-секретов.

`bash mobile/ios/ci-test.sh` выполняет:

1. `xcodegen generate --spec project.yml`;
2. unsigned simulator build приложения и расширения;
3. выбор доступного iPhone simulator через simctl JSON;
4. hostless тесты Foundation, сетевого allowlist и защищённого store с
   MemoryVault вместо настоящего Keychain entitlement;
5. сохранение build/test логов, DerivedData и `WidgetTests.xcresult` в
   `$RUNNER_TEMP/tessavie-ios` либо локальный `.build/tessavie-ios`.

Тесты проверяют pairing/токен и редактирование debug-вывода, RFC3339 с дробными
секундами, URL allowlist, redirect refusal, изоляцию snapshot ID, неверные
значения прогресса, срок кеша/перевод часов, AES-шифрование, повреждённый кеш,
отключение до позднего ответа, path traversal и фиксированные ошибки.

На Windows Xcode не запускался. Root организует macOS GitHub Actions с
Xcode 16.4; фактический статус сборки и тестов должен быть добавлен по результату
job. Наличие ci-test.sh не является отметкой PASS. Для установки на физический
iPhone и раздачи TestFlight/App Store потребуются подписанные capabilities,
собственный Apple Developer account, проверка реального устройства и оформление
пакета публикации (включая иконки/метаданные). Аккаунт и покупки данным этапом
не создаются, App Store/TestFlight upload не выполняется.

## Проверенные первичные источники

WidgetKit предполагает отдельное расширение и поддерживает выбор источника,
системные размеры и отдельные обновления. App Group предоставляет общий
контейнер, Keychain Sharing — явную общую группу доступа. Используются
[стратегия WidgetKit](https://developer.apple.com/documentation/WidgetKit/Developing-a-WidgetKit-strategy),
[обновление WidgetKit](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date/),
[создание extension](https://developer.apple.com/documentation/widgetkit/creating-a-widget-extension),
[Keychain Sharing](https://developer.apple.com/documentation/security/sharing-access-to-keychain-items-among-a-collection-of-apps)
и [App Groups](https://developer.apple.com/documentation/xcode/configuring-app-groups).
Формат генерации проверен по [XcodeGen ProjectSpec](https://github.com/yonaskolb/XcodeGen/blob/master/Docs/ProjectSpec.md).

### Проверка хранилища до использования кода

Первоначальный вызов `store.grants()` не проверял доступность Keychain при
пустом списке источников. Это могло сжечь одноразовый код на первой установке,
а проблему capability обнаружить только при сохранении токена. Сейчас общий
`WidgetPairing.redeem` сначала проверяет формат кода и локальное имя, затем
вызывает `WidgetStore.verifyWritable`, и только после успеха отправляет код.

Проверка выполняет под межпроцессной блокировкой следующие операции:

1. проверяет индекс и лимит активных источников;
2. записывает случайный служебный probe в общую Keychain-группу;
3. читает и сравнивает probe, удаляет его, подтверждает удаление;
4. записывает, читает и удаляет тестовый файл с полной защитой данных в App Group;
5. при ошибке убирает доступные служебные артефакты и запрещает запрос обмена.

Probe содержит только случайную служебную строку. Код подключения и токен
никогда не участвуют в этой проверке. Асинхронные тесты моделируют отказ записи,
чтения и удаления в первом пустом хранилище и проверяют нулевое число обменов.
Отдельный тест проверяет очистку успешного probe. Это не доказывает исправность
подписи на физическом устройстве, но исключает заведомо неработающий local store
до использования кода. Если состояние телефона изменилось после preflight,
сообщение о неудачном сохранении по-прежнему объясняет отзыв использованного
доступа на сайте и создание нового.

### Имена источников и путь к настройкам

Правильный путь: **Настройки → Личные настройки → На телефоне**. Уточнение
дополняет сокращённый путь из первого варианта инструкции. На опубликованном
сайте общий код пока расположен в разделе «Виджеты Android». Разработчик
iOS-прототипа использует тот же контракт, например с именем доступа «iPhone»;
публичного подписанного iOS-пакета этот этап не создаёт и интерфейс сайта не
обещает пользователю готовую установку iOS-виджета.

В приложении можно задать необязательное название подключения до 80 символов
в одной строке: «Привычки дома», «Прогресс команды». Оно записывается как
`WidgetGrant.localName` только в общий Keychain. App Group индекс содержит
идентификаторы без названий; кеш названий блоков остаётся зашифрованным AES-GCM.
Локальное название показывается и в приложении, и в AppIntent выборе источника;
без него к заголовку добавляются первые шесть символов несекретного ID, чтобы
одинаковые блоки различались. Данные старых grant без `localName` читаются.
Название самого блока на сайте не изменяется.

### Размеры виджетов и проверка изображений

`Shared/ConstructorWidgetContent.swift` теперь содержит общий SwiftUI-контент
для WidgetKit и тестового рендера. В системном расширении остаются widget family,
container background и переход на сайт. Средний размер разделён на две колонки:
прогресс слева, два пункта справа. Это сохраняет дату обновления при длинных
заголовках; прежняя вертикальная схема могла вытеснять её за пределы карточки.
Маленький виджет показывает счётчик и прогресс, большой — до пяти пунктов.
Длинные подписи ограничены строками, полное значение остаётся доступным через
системную доступность и на сайте. Временная ошибка теперь подписана
«Не удалось обновить · сохранённая копия», потому что причиной может быть и
непроверенный ответ, а не только отсутствие сети. На малом размере подпись
сокращена до «Сохранённая копия», дата видна отдельно.

`WidgetAppearanceTests` рендерит те же компоненты через SwiftUI ImageRenderer:
170×170, 364×170, 364×382 points, светлая и тёмная палитры, длинные русские
заголовки и пункты, счётчик 499 из 500, отдельные состояния сохранённой копии
и недоступного источника. Десять PNG сохраняются как постоянные XCTest
attachments. Автоматические проверки подтверждают рендер и размеры;
отсутствие наложений подтверждается отдельным просмотром PNG после CI.
Это не подмена проверки на реальном экране «Домой» — её проводят после подписи.

`ci-test.sh` теперь выбирает конкретный runtime iOS 18.5, соответствующий
Xcode 16.4, а не первый произвольный iOS simulator. После тестов
`xcresulttool export attachments` кладёт изображения в `Renders/` рядом
с `WidgetTests.xcresult`. Root workflow сохраняет эти артефакты и фактический
результат повторной проверки; при отсутствии runtime скрипт завершается
понятной ошибкой, без молчаливого переключения версии.
