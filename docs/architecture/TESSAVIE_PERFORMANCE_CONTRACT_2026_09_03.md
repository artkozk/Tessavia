# Устранение задержек Tessavie — 03.09.2026

## Причина и границы

Пользователь сообщил о постоянных загрузках при работе. Замер действующего
релиза `4ad01c3` на рабочем хосте показал 177 карточек, 512 событий и 3 аккаунта.
Обычные API-чтения занимают медианно 7,5–21,8 мс на loopback; пачка bootstrap
из 14 параллельных запросов — 175,64 мс. CPU load average 0,00, память процесса
около 17 МБ. Это не подтверждает перегрузку процессора или медленные SQL-запросы
в текущем объёме. Проверка тысяч карточек остаётся отдельной задачей.

Подтверждены три усилителя задержек:

1. Nginx сжимал только HTML. JavaScript 789550 байт, список карточек 429048 байт
   и 200 событий истории 522831 байт передавались несжатыми. Почти мегабайт JSON
   загружался до показа проекта; сжатие полезно и без изменения структуры данных.
2. HTTP/2 выключен, для ресурсов интерфейса нет явного Cache-Control. Поэтому
   очереди запросов зависят от нескольких HTTP/1.1-соединений, а повторный вход
   заново передаёт неизменённые файлы. HTTP/2 уменьшает потребность в отдельных
   соединениях, но сам по себе не гарантирует конкретное время каждого клика.
3. После записи `syncProjectChanges` ожидал синхронизацию, уведомления, ожидающие
   вопросы и чат в одном Promise.all. Зависание чата задерживало подтверждение
   уже выполненного сохранения. У fetch не было ограничения времени ожидания.

На компьютере пользователя 17 из 18 простых HTTPS-проверок занимали примерно
0,10–0,15 с; один запрос не завершился за лимит 5 с. Также периодически зависают
новые SSH-соединения. Это свидетельство непостоянной сетевой задержки на пути,
но не доказательство её причины у провайдера или на устройстве. Массовую потерю
пакетов и конкретный сбой сетевого оборудования этим измерением не утверждаем.

## Изменение запросов клиента

GET ограничен 6 секундами на попытку, включая чтение JSON-тела. При сетевой
ошибке, timeout или HTTP 502/503/504 он повторяется один раз. Ошибки прав,
валидации, отмена внешним AbortSignal и операции записи не повторяются.
Обычная запись ждёт до 20 секунд; AI — до 120 секунд, FormData — до 180 секунд.
Если ответ записи потерян, пользователь получает сообщение о неподтверждённом
результате. Сам факт timeout не означает, что запись не состоялась.

Одновременные одинаковые GET используют один выполняющийся запрос. Ключ включает
аккаунт, проект, путь и заголовки; это не постоянный кэш API. До записи и после
её подтверждения объединение сбрасывается, чтобы новое чтение не использовало
ответ, начатый до изменения. Завершённые запросы удаляются из Map.

Уведомления, вопросы и чат обновляются независимо от основного sync; их ошибки
не превращают успешную синхронизацию карточек в ошибку сохранения. Поздние ответы
проверяют аккаунт и проект перед применением. Активный редактор не перерисовывается
этими ответами, обновляются только навигация и счётчик уведомлений.

## Передача и кэш

`deploy/tessavie-performance.nginx.conf` подключается только в HTTPS server
control.e-rd.ru. Включены HTTP/2, gzip уровня 5, порог 1024 байта, Vary и типы
JSON/JavaScript/CSS/SVG/TTF. Конфигурация остальных сайтов, TLS и права доступа
сохраняются. JSON только сжимается, серверный или общий кэш личных ответов не вводится.
Директивы сверены с официальной документацией:
https://nginx.org/en/docs/http/ngx_http_gzip_module.html и
https://nginx.org/en/docs/http/ngx_http_v2_module.html.

Приложение задаёт immutable на год только существующим публичным app.js,
styles.css и brand-ресурсам с параметром версии. Vendor/fonts кешируются на сутки.
HTML и manifest каждый раз проверяются заново, чтобы увидеть новые версии.
API не проходит через этот обработчик. Новый маркер — `20260903-performance-1`.

## Проверки и оставшаяся работа

Нужны тесты объединения и разделения GET по проектам, timeout JSON-тела,
однократного повтора только чтения, отказа от повторной записи, явной отмены,
инвалидации после изменения, независимости sync от медленного чата и отбрасывания
ответов прошлого проекта. Отдельно проверяется отсутствие длительного кэша у
HTML, manifest и несуществующих ресурсов. Затем штатные Go/Node-проверки,
браузер с обычным и узким экраном, длинный текст и восстановление черновика.

Выпуск резервирует БД/uploads/env и конфигурацию Nginx на том же сервере,
проверяет сохранность каждой таблицы на копии, применяет nginx -t перед reload,
проверяет HTTP/2, gzip с побайтовым сравнением распакованного JS и cache headers.
При ошибке возвращаются предыдущий бинарник и конфигурация, БД не откатывается.
Фактические результаты: `docs/operations/TESSAVIE_PERFORMANCE_2026_09_03.md`.
