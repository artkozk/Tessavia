# Сброс пароля владельца 3 сентября 2026

## Причина

Владелец учётной записи `artkozk` запросил немедленно восстановить вход и
разрешил установить переданный им временный пароль. Глобальный вход без
пароля не включался: он снял бы проверку личности не только для владельца,
но и для любого посетителя страницы авторизации. Точечный сброс сохраняет
действующую модель доступа и имеет меньшую область риска.

## Выполнение

Изменена только строка пользователя `artkozk` в production SQLite на
основном сервере `159.194.231.150`. Новый пароль преобразован bcrypt с
cost 12 и записан транзакционно. Открытый пароль не записывался в файл,
репозиторий, документацию или вывод проверки.

Перед изменением создана точечная резервная копия прежних полей
`id`, `username`, `password_hash` и `updated_at`:
`/var/lib/business-control/backups/pre-artkozk-password-reset-20260903T173058Z.json`.
Файл принадлежит серверному контуру и имеет режим `0600`. Такая копия
достаточна для точного отката одной изменённой строки без восстановления
остальной базы и без потери последующих пользовательских данных.

## Проверка

После записи новый открытый пароль сопоставлен с сохранённым bcrypt-хешем.
Затем выполнен реальный POST на публичный
`https://control.e-rd.ru/api/auth/login` с логином `artkozk`; сервер вернул
HTTP 200. `PRAGMA integrity_check` рабочей БД вернул `ok`, а публичный
`/api/health` вернул `status=ok`.

Код приложения, конфигурация механизма входа и production release при этом
не менялись. Остальные учётные записи и их пароли не затрагивались.
