# Развёртывание выбранной даты начала цикла

Дата: 31 августа 2026 года.

## Причина

Основатели приняли решение начать первый 12-недельный цикл 1 сентября 2026 года. Текущий API допускал только понедельник, хотя такое ограничение не было пользовательским требованием.

Релиз снимает weekday-проверку, но сохраняет строгую проверку существования даты, аудит, оптимистическую блокировку и единственный активный цикл.

## Изменения

- сервер принимает любую корректную календарную дату;
- форма объясняет, что семь дней отсчитываются от выбранного старта;
- название поля изменено с `Первый понедельник` на `Первый день`;
- следующий цикл предлагается после полной недели анализа;
- тесты проверяют вторник 1 сентября и отклоняют 31 сентября;
- версия клиентских ресурсов: `20260831-flexible-cycle-start-2`.

Миграция базы не требуется. Таблица `planning_cycles`, добавленная предыдущим релизом, уже поддерживает выбранную дату.

## Проверки до переключения

1. `node --check web/app.js`.
2. `go test ./...`.
3. `go vet ./...`.
4. Создание цикла с `2026-09-01` через тестовый сервер.
5. Проверка границ `2026-09-01` — `2026-11-23`.
6. Проверка начала анализа `2026-11-24`.
7. Проверка обновлённого asset marker.

## Production-порядок

1. Создать задачу выпуска от `artkozk`.
2. Сделать SQLite backup и архив вложений на основном сервере `159.194.231.150`.
3. Проверить backup через `integrity_check` и `foreign_key_check`.
4. Запустить новый binary на копии базы и временном локальном порту.
5. Проверить health, marker и авторизованный API циклов.
6. Атомарно переключить release и перезапустить сервис.
7. Создать общий активный цикл с датой `2026-09-01` и причиной, отражающей решение основателя.
8. Проверить рассчитанные границы и событие истории.
9. Добавить доказательство к задаче выпуска и завершить её.

## Rollback

Возврат symlink на предыдущий binary безопасен для схемы. Уже созданный цикл не удаляется: предыдущий binary сможет его прочитать, но будет отклонять изменение даты на непонедельник. Поэтому при rollback карточки и история сохраняются, а повторное редактирование цикла откладывается до восстановления исправленного релиза.
