# Развёртывание мобильной надёжности BizFlow

Дата: 25 августа 2026 года.

## Разрешённый production-контур

Приложение, база данных, вложения, резервные копии и конфигурация разрешены только на `159.194.231.150` для домена `control.e-rd.ru`. Ни один другой сервер не используется для сборки production-данных, хранения backup или запуска BizFlow.

## Характер релиза

Релиз меняет встроенный frontend и один HTTP-заголовок безопасности. Новых таблиц и миграций БД нет. Пользовательские данные не преобразуются и не создаются автоматически.

## Проверки до переключения

1. Выполнить форматирование изменённых Go-файлов.
2. Проверить синтаксис `web/app.js`.
3. Выполнить `go test ./...` и `go vet ./...`.
4. Проверить `git diff --check`.
5. Убедиться, что в diff отсутствуют API-ключи, пароли и прокси.
6. Собрать статический Linux-бинарник `CGO_ENABLED=0 GOOS=linux GOARCH=amd64`.
7. Проверить текущий release, сервисы, свободное место и целостность production SQLite.
8. Создать согласованный SQLite backup и архив uploads только на основном сервере.

## Переключение

1. Поместить бинарник в новый каталог `/opt/business-control/releases/<release>`.
2. Остановить только `business-control`.
3. Атомарно переключить `/opt/business-control/current` на новый release.
4. Запустить сервис и дождаться локального health.
5. Проверить внешний HTTPS health и загрузку assets с версией `20260825-mobile-reliability-2`.
6. Проверить `Permissions-Policy`: микрофон и камера должны быть разрешены только для `self`.
7. Проверить активность `business-control`, `nginx`, `coturn` и таймера резервного копирования.

## Обязательный smoke

- штатная страница входа открывается без общего nginx-пароля;
- `/api/health` отвечает локально и по домену;
- основные JS/CSS отдаются без секретов;
- меню, поиск, карточка, календарь, чат и карта загружаются;
- service log после переключения не содержит новых ошибок;
- `PRAGMA integrity_check` возвращает `ok`;
- `PRAGMA foreign_key_check` не возвращает строк;
- текущий backup остаётся на основном сервере.

## Откат

Если локальный или внешний health не проходит, сервис останавливается, symlink возвращается на предыдущий release, после чего повторно запускаются локальный и внешний smoke. База в этом релизе не меняется миграциями, поэтому восстановление backup требуется только при отдельном подтверждённом повреждении данных.
