## Исходные измерения

`deploy/profile-latency.py` запускается на рабочем сервере, создаёт временную
сессию владельца, читает существующие API и выводит только время, размер и статус.
Пользовательские записи не экспортируются. Сессия удаляется в finally.
На каждый endpoint выполнено три чтения, затем одна пачка из 14 запросов.
Это короткий профиль, не длительный нагрузочный тест.

Пачка bootstrap: 175,64 мс loopback и 273,45 мс через публичный HTTPS с самого

`/tmp/tessavie-latency-before.jsonl`, `/tmp/tessavie-latency-public-before.jsonl`.

На рабочем компьютере один health-запрос из 18 не уложился в 5 секунд,

В конфигурации типы gzip закомментированы, HTTPS server не включает HTTP/2.

Контракт причин и изменений:
`docs/architecture/TESSAVIE_PERFORMANCE_CONTRACT_2026_09_03.md`.

## Подготовка исправления

Клиент отделяет побочные обновления от sync, ограничивает ожидание и повторяет
только безопасное чтение. Новые GET после записи не объединяются со старым
выполняющимся чтением. Кэширование ограничено публичными файлами; API и HTML
не получают immutable. Nginx меняется отдельным include только для Tessavie.
Реквизиты и проверки фактического выпуска будут добавлены после выполнения.
