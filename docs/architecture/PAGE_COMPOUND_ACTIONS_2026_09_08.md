# SC-85. Несколько изменений одной кнопкой

## Зачем это нужно

SC-84 позволил копировать значение одного поля. Для согласования заявки пользователь всё ещё должен был отдельно переносить оценку и ставить отметку согласования. При втором сбое запись могла остаться наполовину обработанной. В рамках родительской задачи `f4dd60e96ccb69635a2faa05a60fd058` после чтения её фактических критериев создан этап `6f727d718fdc52acb1396084600e9108`: настроить несколько изменений одной записи, проверить их вместе и применить целиком.

Пользователь сам собирает свой набор. Приёмка выполняется на синтетическом аккаунте; готовый набор владельцу не устанавливается. Этот этап расширяет поведение конструктора, а не заменяет пользовательскую сборку специальной страницей разработчика.

## Как настроить

1. В «Досках» подготовить пользовательские поля, например «Оценка», «Подтверждено» и «Согласовано».
2. На своей странице добавить список записей и выбрать доску. В «Действиях с записью» добавить кнопку и задать её понятную подпись.
3. Первым изменением настроить «Подтверждено» → «Взять из другого поля» → «Оценка».
4. Нажать «Добавить изменение», выбрать «Согласовано» и установить флажок. При необходимости добавить другие изменения. Одна кнопка содержит от одного до восьми изменений; сам список по-прежнему поддерживает до восьми кнопок.
5. Каждое изменение можно удалить, включая первое. После удаления первого следующее занимает его место, подпись кнопки и общее условие сохраняются. Последнее изменение удаляется вместе с кнопкой через «Убрать действие».
6. Условие относится ко всей кнопке. При невыполненном условии она видима с объяснением и недоступна. Условие можно изменить или убрать.
7. Сохранить страницу. Открыть действия записи: предпросмотр показывает каждое поле, прежнее и новое значение, источник копирования. Отмена не меняет запись. Подтверждение сохраняет все изменения вместе.

Редактор не предлагает уже выбранную цель ещё раз. Когда свободных полей больше нет, добавление отключено; имеющиеся изменения остаются редактируемыми. Разделители и небольшие группы полей сохраняют стилистику платформы. На узком экране поля и сравнения идут последовательно. Фон закреплённых кнопок подтверждения сделан непрозрачным: текст карточек больше не просвечивает сквозь кнопки. Последний результат и пояснение доступны при прокрутке. Заголовок оболочки теперь синхронизируется с переименованием страницы сразу после сохранения.

## Однозначное вычисление

Все операции читают **исходную запись до выполнения всей кнопки**. Промежуточные результаты не являются источниками других операций. Пример: исходно «Оценка»=3, «Подтверждено»=1; кнопка устанавливает «Оценка»=9 и копирует «Оценка» в «Подтверждено». Итог — 9 и 3. Перестановка этих изменений не меняет результат. Это правило написано рядом с настройками и общим предпросмотром.

Так пользователь может согласовать текущую оценку и подготовить новое значение для следующего цикла без зависимости от скрытого порядка. Настоящие цепочки, где следующий шаг читает результат предыдущего, пока не включены: для них нужен явный выбор источника результата шага и проверка зависимостей. Нельзя выдавать данный этап за такие цепочки.

Поддержаны существующие операции set/add/copy. Копирование сохраняет ограничения совместимости SC-84; установка поддерживает переносимые варианты select/multi_select. Пользователи, связи, основные статус/исполнитель/срок не включены. Ноль и false сохраняются, пустой источник может очистить необязательное поле, обязательное поле не очищается. Прибавление к пустому числу отклоняется.

## Формат, проверки и транзакция

Первое изменение хранится в прежних fieldId/operation/sourceFieldId/value действия. До семи дополнительных — в массиве `changes`, каждый с теми же четырьмя свойствами. ID, подпись и condition принадлежат кнопке, а не отдельным изменениям. Такая форма сохраняет все ранее записанные одиночные действия без миграции. Повтор целевого поля запрещён сервером, даже если клиент обошёл ограничение редактора.

Перед выполнением проверяются все целевые поля, источники и общее условие, принадлежность доске, активность и совместимость типов. Все результаты вычисляются и нормализуются до записи. Хеш схемы включает каждую использованную схему, в том числе источники поздних изменений и поле условия. Версии страницы и записи сохраняют защиту от устаревшего подтверждения; при конфликте человек обновляет предпросмотр и принимает новое решение.

Предпросмотр возвращает массив `changes` с результатами всех операций, сохраняя прежние поля первого результата для совместимости чтения. При применении составной кнопки сервер требует `expectedChangeCount`, равный числу просмотренных изменений. Старый клиент, умеющий показать только первое поле, не сможет применить всю кнопку, даже получив новый schemaHash. Ему предлагается обновить приложение и предпросмотр. Для прежней одиночной кнопки это новое подтверждение не требуется.

Обновление версии записи, все значения полей и одна запись истории находятся в одной транзакции. Ошибка записи любого поля откатывает предыдущие изменения и версию. История содержит массив сравнений всех полей, источник и значения до/после. Повтор старого успешного подтверждения отклоняется версией записи и не создаёт повторной истории. Составная операция не расширяет права редактирования записи.

## Наборы и выпуск

Сохранение набора проверяет все операции. Установка переводит ID каждой цели и источника, а также варианты select/multi_select и поле условия в новые ID собственной доски. Исходные записи не переносятся. Установленная страница сохраняет независимую редактируемую конфигурацию.

Новых таблиц или миграций нет: 117 таблиц, последняя схема065. Деплой создаёт серверную резервную копию, выполняет dry run и сравнивает все старые строки. SC-84 игнорирует дополнительные изменения, поэтому откат на него блокируется, если при остановленной службе найдены страницы или наборы с непустыми changes. Замена пользовательской базы старой копией для обхода проверки недопустима.
