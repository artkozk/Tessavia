# Личные входящие и быстрый ввод

Дата: 3 сентября 2026. Дополняет
[PERSONAL_WORKSPACE_PRIVACY_CONTRACT_2026_09_01.md](PERSONAL_WORKSPACE_PRIVACY_CONTRACT_2026_09_01.md);
прежние договорённости и история не удаляются.

## Зачем отдельный путь ввода

Проектная карточка inbox требует рабочего контекста. Для личной мысли это лишний
выбор и риск случайной публикации. Новый ввод использует существующие личные
заметки, а не общий тип records с условной меткой «личное».
Это позволяет начать с текста и структурировать позже без потери идентичности.

## Пользовательский путь

1. В личном разделе верхний плюс открывает быстрый ввод; в общем меню создания
   есть «Личное входящее», а в личном меню «Записать» есть «Входящее».
2. Вводится только текст. Enter переносит строку; Ctrl/Cmd+Enter отправляет.
   Название выводится из текста, срок и проект не обязательны.
3. До ответа сервера кнопка заблокирована от повторного нажатия, текст доступен
   для копирования. При ошибке форма сохраняет текст и показывает сообщение.
4. В «Личное → Входящие» заметку можно открыть и отредактировать существующим
   редактором, связать с личным планом/записью или доступной карточкой проекта.
5. «Сохранить в заметках» убирает только признак неразобранного. Заметка остаётся,
   дата создания и связи сохраняются. «Вернуть» отменяет разбор.
6. После сохранения доступен переход «Открыть» к входящим. При создании запись
   не переключает рабочий проект сама.

Календарный плюс сохраняет прежний сценарий записи на выбранный день.
Дата создания проставляется сервером автоматически, но не превращается в срок.
Существующий календарный fallback по дню создания остаётся прежним.
Обычные старые и новые заметки не становятся неразобранными автоматически.

## Хранение и доступ

Миграция `030_personal_inbox.sql` добавляет `personal_notes.in_inbox`
(boolean, по умолчанию 0) и таблицу `personal_capture_requests`.
Владелец извлекается только из сессии, не из тела запроса или активного проекта.

- `POST /api/personal/capture`: body, requestKey; 201 при первом сохранении,
  200 при безопасном повторе.
- `PATCH /api/personal/notes/{id}/inbox`: inInbox, expectedUpdatedAt; 204 при успехе.
- Очередь читается через прежний приватный overview.
- Чужая или архивная заметка не изменяется; отсутствие сессии даёт 401.
- При конфликте версии разбор даёт 409, не перезаписывая чужое редактирование.
- Связывание с проектом не публикует личный текст и не добавляет публичную
  обратную ссылку. Полный контракт личных связей сохраняется.

## Повторная отправка и черновики

requestKey состоит из 16 случайных байт в hex. Пара (owner_id, request_key)
уникальна. SHA256 текста и ID заметки записываются в той же транзакции, что сама
заметка. Поэтому потерянный ответ не создаёт вторую закоммиченную запись.
Другой пользователь может использовать такой же ключ только в своём пространстве.

Неизменённый повтор возвращает существующую заметку, в том числе уже
отредактированную или разобранную; не восстанавливает старый текст/статус.
Другой текст под тем же ключом и повтор для архивной заметки дают 409.
После изменения текста клиент выдаёт новый ключ, включая восстановленный
после перезагрузки черновик. Намеренно новая запись того же текста допустима:
это не глобальная дедупликация заметок.

Перед отправкой черновик синхронно передаётся существующему механизму сохранения
на устройстве. При позднем ответе очищается только совпадающий текст и ключ:
новая запись, открытая за время запроса, не должна исчезнуть.
Если локальное хранилище недоступно, прежняя защита закрытия формы сохраняется.
Черновик привязан к аккаунту. Это не автономная очередь синхронизации:
без сети серверного сохранения нет.

## Миграция и откат

Перед релизом обязательны резервные копии SQLite, uploads и env. Прогон на копии
разрешает только новую колонку с нулями, пустую таблицу ключей и строку миграции 030.
Остальные строки сравниваются целиком. Незавершённые локальные миграции
жизненного цикла команд не входят в эту поставку.

Предыдущий бинарник может работать с добавленной колонкой и таблицей:
при откате новые записи останутся обычными личными заметками, но очередь разбора
и идемпотентный endpoint будут недоступны. Автоматически откатывать БД нельзя:
после публикации могли появиться настоящие записи. Восстановление backup требует
отдельного окна и решения о более новых данных.

## Проверки и границы

Go-тест: ввод/валидация, приватность, ключи двух владельцев, повтор/конфликт,
редактирование, дата, связи, оптимистическая версия, отмена, архив.
JS-тесты: состав очереди, неизменность исходного массива, защита нового черновика,
приватный endpoint и отсутствие обязательных дополнительных полей.
Браузер: запись из проекта, восстановление после закрытия, разбор/отмена,
связь с проектной задачей, длинная ссылка на мобильном экране, сетевой сбой.

Не включены: AI, файлы, голос, системный Share, native-виджеты, автоматическое
превращение в проектную работу, серверная офлайн-очередь. Родительские задачи
не считаются завершёнными этим релизом.
