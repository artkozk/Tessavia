# Вложения диалога — SC-70

Этап существующего чата e402d353a684b074f852fa1fd277d895, перечитанного через API.
Найти ранее присланный файл сложно, если название забыто: приходится листать весь
разговор. Добавляем «Файлы и медиа» в меню открытого диалога. Режим показывает
сообщения с вложениями, их авторство, дату и привычный предпросмотр. Через меню
сообщения можно вернуться к месту в переписке, через плашку — ко всем сообщениям.

GET history получает attachments=true. Фильтр применяется в SQL до ограничения
страницы, поэтому старые вложения не пропадают за 50/200 новыми текстовыми
сообщениями. Старые страницы догружаются тем же курсором created_at/id. Поиск
работает по существующим полям сообщения и имени файла. Только доступный разговор,
только неархивированные сообщения; фильтр не расширяет права скачивания.

Просмотр вложений не отмечает весь разговор прочитанным. Черновик остаётся на
месте. Фильтр сбрасывается при смене диалога/проекта, не наследуется соседним
разговором. Поиск вложений не совмещается в UI с «Сохранёнными», чтобы не получить
неочевидное пересечение фильтров. API совместное чтение допускает. Продолжение
вперёд в режиме вложений не используется; возвращение к сообщению открывает
обычную историю и её двустороннее продолжение.

Это единый список вложений, а не законченная медиатека Telegram: отдельные сетки
фото, ссылки, альбомы, пакетные действия и нативная запись остаются будущими этапами.
Проверить 60+ вложений за длинной историей, имя кириллицей, курсоры/архив/чужой
разговор, неизменность прочтения; в UI файл/изображение, пустой режим, возврат,
черновик и 320/1280 px. Новых таблиц нет.


## Проверки и уточнения реализации

Интеграционный тест создал 60 файлов с равными отметками времени и 240 более
новых текстов. Вложения прочитаны страницами 50+10 без потерь, поиск кириллического
имени нашёл старый файл, архив исключён. Проверены чужой участник, некорректный
фильтр/курсор, запрет after с attachments и сохранность обычной истории. GET не
изменил last_read_at. Браузерный тест подтвердил отсутствие POST /read в режиме
вложений и сохранённых сообщений, но наличие в обычном видимом разговоре.
При этом исправлен существовавший дефект: просмотр «Сохранённых» раньше мог
погасить непрочитанные всего разговора.

Ожидающий текст не подмешивается в отфильтрованный список вложений. После явной
отправки текста из этого режима интерфейс возвращается к обычной переписке,
чтобы результат отправки оставался виден. Незавершённый ввод при простом просмотре
не меняется. Подтверждённое текстовое сообщение не вставляется в список файлов
через callback очереди. Ожидающие вложения по-прежнему показываются рядом.

Локальный ручной сценарий: новая синтетическая группа SC-70, owner 1 и коллега 2,
два вложения (текст и существующий тестовый знак платформы) и текст контекста.
В файлах показаны только два вложения. Поиск «отчёт» оставил один файл; действие
«Открыть в переписке» вернуло исходное место, «Следующие сообщения» догрузило
изображение и обсуждение. Черновик SC-70 сохранился. Отдельное тестовое сообщение
отправлено через UI из режима вложений: оно появилось в обычной переписке, ввод
очистился, затем синтетический черновик восстановлен. Это локальные тестовые
аккаунты; рабочим участникам сообщения не отправлялись.

На 320×740 найдено обрезанное имя документа. В режиме файлов оно теперь переносится
целиком, включая расширение; обычный чат сохраняет прежнюю компактность. Просмотрены
документ, изображение и кнопка возврата на 320 и 1280×800. При смене на прежний DM
снова открылась обычная история; пустой режим вложений объясняет отсутствие файлов,
черновик SC-65 не изменился. Возврат «Все сообщения» проверен, viewport возвращён.
Физические телефоны, микрофон и камера этим этапом не проверялись.

Полный Go сначала обнаружил независимую временную ошибку теста сводок: фиксированная
сводка 06.09 истекла по реальным часам 07.09 в 18:00 UTC, поэтому SQL inbox правильно
скрывал её. Тест теперь сначала проверяет ожидаемый исторический срок, затем
перемещает только срок тестовых записей относительно часов SQLite для проверки
inbox. Добавлена проверка реального истечения; production-код уведомлений не менялся.
После исправления полный Go прошёл (internal/app 54.713 s, web 1.001 s), все
230 Node-тестов прошли. Данные и схема выпуска не требуют миграции.
