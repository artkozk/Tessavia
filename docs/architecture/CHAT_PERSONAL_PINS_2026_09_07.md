# Личное закрепление разговоров — SC-68

Следующий этап существующего направления e402d353a684b074f852fa1fd277d895,
прочитанного 07.09 через production API. При большом числе разговоров важная
группа теряется под более новыми сообщениями. Человек может закрепить разговор
вверху своего списка через «Действия диалога» → «Закрепить в списке» и снять
закрепление там же. Это персональная настройка на сервере, доступная с другого
устройства. Она не равна общему закреплённому сообщению или сохранённому сообщению.

Закреплённые разговоры идут первыми, в порядке времени закрепления; остальные
сохраняют порядок активности. Повторная установка true не меняет порядок.
Открытый разговор, позиция чтения и черновик сохраняются при перестановке списка.
Другим участникам не отправляется сообщение, их список не меняется. Архив,
отключение уведомлений и ручная отметка непрочитанным остаются отдельной работой.

PUT /api/chat/threads/{id}/personal-pin принимает явный boolean pinned. Проверяет
участие и текущий проект. Нет доступа — 403; отсутствие boolean — 400. Таблица
chat_personal_pins с составным FK на chat_members удаляет настройку при выходе
или исключении из разговора. Утрата доступа к проекту закрывает чтение и запись
через общий auth-контекст. После возвращения в проект прежняя настройка допустима,
если членство в разговоре сохранялось. Последняя явная операция человека побеждает
при действиях с нескольких устройств. Действия идемпотентны.

До выпуска проверить личную изоляцию, чужой проект/разговор, идемпотентность,
выход и повторное вступление, порядок, непрочитанные и неизменность сообщений.
Ручной путь: заполненная длинная переписка → черновик → закрепление → другая
вкладка → перезагрузка → открепление. Визуал: 320/1280, длинная группа, меню,
значок закрепления рядом со временем без перекрытия счётчика.


## Проверка и найденный визуальный дефект

Интеграционный тест проверил права третьего участника, чужой проект, неверные
параметры, независимость списка собеседника, порядок двух закреплений, повторные
операции без изменения времени, сохранность непрочитанных/сообщений и очистку
настройки при выходе с последующим добавлением в группу. Полный Go прошёл:
internal/app 54.032 s. После финальной правки UI web Go 0.966 s и 228 Node прошли.

Ручной путь выполнен в локальном синтетическом проекте: длинный DM с черновиком
SC-65 → закрепить → длинная группа SC-62 → закрепить → перезагрузка → DM → снять
закрепление. Оба закрепления сохранились после reload, черновик SC-65 остался
неотправленным после перестановки и открепления. Ни одного нового сообщения не
создавалось. Отдельно в локальной фикстуре временно восстановлены пять непрочитанных
группы: на 320 px счётчик и значок не пересекаются. Исходная отметка чтения возвращена.

В мобильном списке обнаружена потеря полезной ширины: полная дата с годом оставляла
названию около 7 символов. Теперь время показывается для сегодняшнего сообщения,
день и месяц для текущего года, короткая дата с годом для старой переписки.
Полная дата сохранена в подсказке и datetime элемента time. Заголовок получил
больше места без изменения ширины панели. Меню на 320 px занимает 304 px,
границы 8–312; длинная группа и кнопка закрепления доступны. На 1280 px просмотрены
полная переписка и закреплённый DM. Физические телефоны не проверялись.
