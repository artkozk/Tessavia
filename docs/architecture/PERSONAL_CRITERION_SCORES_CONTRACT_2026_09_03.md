# Независимые оценки участников

Каноническая задача `aa7c0389686c6955947685f0092396d5` начата вслед за полной
выдачей. Основание: уникальность только пары «карточка — критерий» позволяла
одному участнику незаметно заменить оценку другого.

## Принятое решение

1. Уникальность личной оценки включает автора: карточка, критерий, участник.
   Миграция сохраняет ID, автора, значение, пояснение и даты каждой существующей
   строки. Ранее потерянные голоса не восстанавливаются предположениями.
2. Личная оценка изменяет только строку текущего пользователя. Клиент передаёт
   ожидаемую версию, сервер проверяет её внутри транзакции. Две вкладки одного
   участника не затирают друг друга без сообщения о конфликте; разные участники
   могут оценивать одновременно. Правила доступа к самой карточке сохраняются.
3. Пустое поле означает отсутствие оценки; 0 — явная оценка, входящая в расчёт.
   Сервер не подставляет ноль при пропущенном поле. Собственную оценку можно
   снять отдельным действием, оставив факт и прежнее значение в истории.
4. У критерия есть общий вес, первоначально 1. Его меняет тот, кому разрешено
   редактировать критерий. Вес 0 исключает критерий из агрегата; допустимы
   конечные значения от 0 до 100. Изменение веса отражается в истории критерия.
5. Среднее по критерию считается только по имеющимся личным оценкам. Общий
   показатель — сумма произведений этих средних на веса, делённая на сумму
   весов оценённых критериев. Неоценённые критерии не становятся нулями.
   Если знаменатель равен нулю, показателя нет. Формула видна рядом с результатом.
6. Принятый итог хранится отдельно от голосов и среднего. Его явно фиксирует
   ответственный карточки или назначенный принимающий решение при наличии
   права редактирования. Нужны значение и основание. Интерфейс показывает,
   кто утвердил итог; это не выдаётся за единогласие всех участников.
7. Новые личные оценки не переписывают принятый итог. Если после утверждения
   появились более новые оценки/изменился критерий, интерфейс предлагает
   пересмотреть итог. Изменение требует нового явного действия с основанием.

## Проверка и выпуск

До завершения требуются два аккаунта, одновременные записи, конфликт одного
автора, сохранность миграции, отличие нуля от отсутствия, веса/формула,
права утверждения и история. Браузерная проверка включает узкий экран.
Экспорт должен содержать личные оценки, принятые итоги и веса.

Фактические команды проверки, версия приложения, резервная копия и запись
результата добавляются в `docs/operations/ACTIVE_TASKS_RELEASES_2026_09_03.md`.
Этот контракт описывает реализацию в работе, а не подтверждает её публикацию.

## Уточнение реализованного протокола

Миграция `032_personal_criterion_scores.sql` копирует восемь исходных колонок
оценок без изменения значений и меняет ограничение уникальности. Вес добавляется
в `records`, явные итоги — в `criterion_decisions`. Прежняя версия приложения
не умеет писать в эту схему: после допуска новых голосов исправления выпускаются
вперёд. Автоматический возврат старой БД запрещён, поскольку потерял бы новые
действия участников. Резервная копия нужна для проверяемого восстановления
при остановленном сервисе и отдельном учёте записей после копии.

- `PUT /api/records/{id}/criteria/{criterionId}` принимает `score`, обязательное
  `note` и `expectedUpdatedAt` собственной оценки. Пустая ожидаемая версия
  означает создание. Для старого клиента создание без версии допустимо;
  изменение существующего голоса без версии получает 409.
- `DELETE` того же URL снимает только собственную оценку, требует её версию и
  `reason`. Прежние значение, обоснование и версия остаются в истории.
- `PUT .../decision` требует `score`, `reason`, `expectedUpdatedAt` итога,
  `expectedRecordUpdatedAt` и `expectedCriterionUpdatedAt`. Это не позволяет
  утвердить результат из окна, которое ещё не увидело новые оценки или вес.
- `PATCH /api/records/{criterionId}` принимает `criterionWeight` и обычную
  ожидаемую версию карточки. Версия дополнительно проверяется в самом UPDATE,
  чтобы две одновременные правки веса не прошли предварительную проверку вместе.
- Личные записи обновляют версию оцениваемой карточки для общей синхронизации.
  Признак `needs_review` сохраняет необходимость пересмотра даже при снятии
  последней оценки; изменение самого критерия проверяется по времени с точностью
  RFC3339Nano. Утверждение снимает признак только явным действием.

На вкладке «Критерии и связи» идеи показаны все участники и обоснования.
Собственная форма пустая до первой оценки. Архивные критерии с оценками/итогами
остаются видимыми для истории и исключаются из агрегата. Вес 0 тоже исключён.
Несохранённые формы используют существующий механизм черновиков, включая
ожидаемую версию, чтобы восстановленный текст не перезаписал более новую запись.
На время отправки форма защищена от повторного сохранения и новой правки текста.

Экспорт версии 16 включает `criterionScores`, `criterionDecisions` и веса
в записях критериев. Контекст AI содержит личные позиции с авторами и весами,
а принятые итоги — отдельным массивом с признаком необходимости пересмотра.
На графе подпись каждой оценки содержит её автора.

При смене открытой карточки запоздалый ответ сохранения не открывает прежнюю
карточку обратно. Это защита пути сохранения, использованного новыми формами.
