# Доступ к конструктору личных страниц — 13.09.2026

Документ дополняет контракты единого центра настроек, личного пространства и
жизненного цикла редактора. Исторические решения в них не удаляются. Изменение
следует запросу пользователя: самостоятельно создавать несколько страниц для
разных сценариев, разгрузить основную страницу и понимать, что именно остаётся
личным. Готовые пользовательские страницы и утренние наборы этим кодом не создаются.

## Доступ через единое место настроек

В личном пространстве «Настройки → Текущая страница → Мои страницы» открывает
существующий список страниц через действие `pages`. На этом же экране остаётся
оформление текущей стандартной страницы либо конструктор текущей страницы из
блоков. Дубликат «Свои страницы» в разделе «Пространство» для личной области убран.
Для команды прежний пункт «Пространство → Свои страницы» сохраняется. Это одна
точка управления внутри центра настроек, а не отдельная конкурирующая система.

Действие `pages` продолжает использовать существующий редактор списка. Создание,
названия и архивирование работают с прежними страницами; новая сущность страницы
или миграция для этого доступа не вводится. Размещение ссылок на личные разделы
и страницы в боковом меню, а также маршрутизация реализуются интеграцией `app.js`
и должны проверяться отдельно в общем выпуске.

## Личная страница и набор

Тип области определяется по `state.workspaces` и конкретному `workspaceId`,
а не по названию маршрута. Поэтому открытая страница `page:<id>` продолжает
считаться личной, когда находится в личном пространстве.

1. Создание подписано «Новая личная страница» и объясняет доступ только владельцу.
   Пользователь начинает с пустой структуры или сам выбирает готовый набор.
2. Конструктор личной страницы больше не пишет «общая страница»; просмотр
   подписан «Личная страница · только вы». В командном пространстве сохраняется
   общая структура страницы и отдельные личные отметки пользователей.
3. Библиотека указывает целевое пространство. Предпросмотр в личной области
   подписан «Личная копия», кнопка — «Добавить в мои страницы».
4. Публикация набора не открывает исходную личную страницу другим людям. Набор
   передаёт выбранную структуру и тексты блоков; человек явно выбирает доступ
   к набору. Личные отметки, записи и введённые числа автора не копируются.

Серверный путь уже поддерживает личную область: POST `/api/workspace/pages`,
PUT `/api/workspace/pages/:id/app` и POST `/api/page-app/templates/:id/install`
проверяют владельца/администратора активного пространства. Они не ограничены
пространствами команды. UI передаёт захваченный `X-Workspace-ID`; права на
чужие пространства проверяются сервером, а не надписью в интерфейсе.

## Сохранность контекста создания и установки

Создание, библиотека, публикация и установка используют отдельные сессии общего
диалога. Ожидающая загрузка не лишает действующую форму её сессии. Перед заменой
содержимого и после каждого асинхронного этапа проверяются аккаунт, пространство,
раздел, контейнер, его содержимое и порядок открытия окна. Старый ответ не должен
открыть личный набор в новой команде, закрыть другое окно или продолжить создание
следующим запросом после выхода из аккаунта.

При записи форма становится `inert`; `settingsSaving` включает штатную защиту
закрытия. Запросы получают `X-Outbox-Owner` захваченного аккаунта. После успешного
подтверждённого создания страницы её ID сохраняется в этой форме: повтор после
ошибки следующего этапа не создаёт вторую пустую страницу. Подтверждённый результат
установки также повторно используется, если не удалось обновить список страниц.
Это не обещание идемпотентности неизвестного сетевого результата: если сервер
записал POST, а ответ полностью потерян, существующий API не предоставляет
clientRequestId для этого пути. Новые серверные гарантии этим выпуском не заявляются.

## Проверки

Исполняемые тесты вызывают настоящие обработчики UI с управляемыми ответами API:

- личное пространство правильно определяется на маршруте собственной страницы;
- пункт «Мои страницы» присутствует ровно один раз; командное меню сохранено;
- пустая личная страница проходит POST → PUT → переход → открытие конструктора;
- смена аккаунта или пространства между POST и PUT останавливает следующий этап;
- поздняя библиотека не заменяет закрытое или уже занятое окно;
- установка набора указывает личное назначение и переходит в созданную копию;
- поздний результат установки не закрывает другое окно и не меняет новую область;
- прежние проверки сохранения редактора, публикации и путей настроек продолжают
  исполняться. В старом тестовом контексте публикации добавлены настоящий аккаунт
  и `dialog.dataset`, поскольку новый guard требует их, как реальный интерфейс.

Целевая команда: `node --test web/page-apps-editor.test.cjs web/settings-hub.test.cjs
web/page-apps.test.cjs web/settings-module-paths.test.cjs`. На этом этапе 30/30 PASS.
Минимальная DOM-поверхность теста проверяет события и сохранность контекста,
а не геометрию экрана. Браузерная приёмка, узкий экран, интеграция нового бокового
меню и фактический деплой фиксируются общим выпуском отдельно.

## Исправление ранее предложенного черновика до выпуска

Дополнительная проверка обнаружила потерю локального черновика: при повторном
открытии редактор предлагал восстановление, но закрытие крестиком без выбора
вызывало сохранение исходной версии. Поскольку эта версия совпадала с серверной,
очистка «ненужного» черновика удаляла именно ту работу, которую ещё предлагали
восстановить. Репро исполнялся через настоящий обработчик `edit`.

Теперь ожидающий решения черновик не удаляется и не перезаписывается. Пока
пользователь не выбрал существующие действия «Восстановить» или «Убрать черновик»,
поля текущей версии, Save и отмена текущих изменений недоступны. Крестик остаётся
доступным и сохраняет предложенный черновик. Это не дополнительное подтверждение
каждого действия: выбор требуется лишь при уже обнаруженной второй версии.
После восстановления редактируется прежняя работа; после явного удаления
можно начать новый черновик от сохранённой серверной страницы.

Добавлены проверки закрытия без выбора, запрета перезаписи Save/Cancel и обоих
явных вариантов продолжения. Целевой набор выше теперь проходит 32/32 теста.
Переходы кнопок конструктора остаются ограничены блоками той же страницы в этом
этапе: прямые ссылки `personal:*` и другие страницы не заявляются существующей
функцией. Их расширение требует согласованного контракта UI и сервера.
