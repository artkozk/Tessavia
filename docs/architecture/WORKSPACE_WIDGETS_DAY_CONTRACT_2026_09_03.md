# Добавляемые блоки и рабочий экран дня

## Изменение прежнего решения

Этот контракт дополняет ALL_PAGES_LAYOUT_CONTRACT_2026_09_02.md и CALENDAR_LIFECYCLE_UX_CONTRACT_2026_09_03.md, не отменяя историю изменений. Раньше редактор только переставлял заранее отрисованные блоки внутри их родительских контейнеров. Поэтому пользователь не мог добавить мини-календарь и расположить его рядом с заметками. Наличие настроек ширины страницы не решало эту задачу.

## Сохранение и границы

1. Каталог добавляемых блоков содержит календарь, расписание и списки записей. Блоки отображают существующие данные, а не создают их копии. У каждого зарегистрированного блока есть положение в порядке страницы, ширина в колонках, начальная колонка, необязательная фиксированная высота. Списки дополнительно имеют ограничение количества записей, мини-календарь имеет вид и масштаб.
2. Настройки остаются независимыми для пользователя, проекта, страницы и устройства. Дата не входит в ключ настроек рабочего дня: один и тот же экран используется для всех дат. Личный и проектный календарь имеют разные ключи.
3. Изменения редактора применяются в черновик. Сохранение отправляет только выбранный профиль; отмена возвращает прежний вид. При ошибке сохранения черновик остаётся на экране. Старые настройки главной сохраняются как исходная конфигурация до первого сохранения нового редактора.
4. Положение задаётся адаптивной сеткой, а не абсолютными координатами. Это предотвращает перекрытие блоков при переносах текста. На узком экране блок занимает доступную ширину; его порядок, высота и состав сохраняются отдельно. Чат и карта связей не превращаются в свободную сетку: их основные интерактивные поверхности имеют собственные ограничения.
5. Переносимый набор включает только известные ключи блоков и ограниченные числовые настройки. В нём нет идентификаторов записей, содержимого заметок или произвольных запросов.

## День и приватность

1. Нажатие на дату открывает рабочий экран дня с возвратом назад и переходом между днями. В личном режиме показываются планы, перекрывающие дату, заметки с собственной датой и заметки, связанные с этими планами. Одна заметка отображается один раз даже при нескольких связях.
2. В проектном режиме используются только записи текущего проекта, уже отфильтрованные сервером по доступу. Личные заметки туда автоматически не подмешиваются. Завершённые записи дня не исчезают, их состояние видно.
3. Дата заметки необязательна. Миграция 026 добавляет scheduled_date со значением по умолчанию без изменения существующего текста. Старый клиент, не передавший дату при редактировании, не снимает назначенную дату. Пустая переданная строка снимает дату явно. Проверка владельца выполняется на сервере.

## Масштаб

Стандартный календарь соответствует 100%, это верхняя граница. Значения старого диапазона 60–180% при чтении ограничиваются 100%. Ползунок убран. Ctrl с колесом действует только над конкретным календарём; компактный выбор размера остаётся доступен без мыши. Изменение масштаба не должно подменять открытие дня растягиванием календаря.

## Проверка выпуска

Проверяются нормализация настроек и переносимых наборов, независимость профилей, валидация даты и запрет доступа к чужим заметкам, объединение заметок дня, добавление и сохранение мини-календаря, изменение геометрии, отмена, открытие дня, масштаб до 100%, узкий и широкий экран. Фактические результаты и ограничения фиксируются в операционном отчёте выпуска, отдельно от этого контракта.

## Уточнение даты создания

Во время реализации пользователь уточнил: заметки по умолчанию имеют дату создания. Поэтому scheduled_date в миграции 026 допускает NULL. NULL означает календарный день created_at в локальном времени пользователя, пустая строка означает явное снятие даты, конкретная дата означает перенос. Новая заметка из обычного редактора получает сегодняшний день; новая заметка из рабочего дня получает открытый день. created_at создаётся сервером и никогда не меняется при переносе или редактировании; updated_at продолжает отражать последнее изменение. В списке заметок основной датой стала дата создания, время изменения доступно в подсказке. Включение старых заметок в календарь не требует переписывать их данные.

## Фактическая библиотека первого выпуска

- Общие блоки: мини-календарь и расписание дня. Личные: заметки, планы, привычки. Проектные: задачи, исследования, риски, цели. Каждая разновидность добавляется один раз на страницу; повторное добавление скрытого блока восстанавливает его.
- Библиотека доступна на личной странице, обзоре, рабочей странице, досках, календарях, рабочем дне, пользовательских страницах и стандартных разделах записей. Это не свободное размещение любых DOM-элементов: карта, живой чат, история, уведомления, качество и редактор шаблонов сохраняют свои специализированные поверхности. Они не объявлены полностью универсальным конструктором.
- Старые блоки и новые виджеты располагаются в общей сетке. Скрытие не удаляет данные. Обязательные элементы управления остаются доступными. Перетаскивание меняет порядок, ручка размера меняет ширину и высоту, точная начальная колонка задаётся в настройках блока. Пустая высота возвращает размер по содержимому; фиксированная высота допускает внутреннюю прокрутку, не обрезая данные без доступа.
- Мобильная колонка занимает ширину экрана. Панель настроек телефона не предлагает ширину ПК или номер колонки; высота, порядок, скрытие и набор виджетов независимы. Параметры плотности и ограничения списка не подменяют настройку самих данных.
- Ctrl+колесо применяется только к календарю под указателем. Рабочий диапазон 40–100%; минимальная область дня дополнительно ограничена для читаемости и нажатия. Основной календарь и мини-календарь хранят собственный размер. Вне редактора размер мини-календаря сохраняется на устройстве, внутри редактора входит в черновик страницы. Явный выбор размера в настройках отменяет локальное переопределение.

## Исправление выпадения из окна

При браузерной проверке обнаружено: меню select может выйти за прямоугольник dialog, оставаясь его DOM-потомком в верхнем слое. Прежняя проверка только координат воспринимала выбор нижнего пункта как нажатие на фон и закрывала настройки. Теперь сначала проверяется принадлежность цели диалогу. Нажатие на настоящий фон обрабатывается по-прежнему. Для этого добавлена отдельная регрессионная проверка; содержимое рабочего редактора не используется как фон.

## Дополнительные граничные случаи

Прерванный resize (pointercancel или lostpointercapture) восстанавливает точные исходные карты настроек, включая отсутствие значения. Он не оставляет ложный признак изменённого черновика и снимает блокировку повторной отрисовки. При входе в редактор локальный размер календаря включается в черновик выбранного устройства. Успешное сохранение переносит его в профиль и снимает только локальные переопределения виджетов этой страницы/устройства, чтобы сохранённый вид не менялся после выхода из настройки.
