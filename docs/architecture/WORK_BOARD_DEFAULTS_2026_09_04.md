# Пять колонок и прокрутка без видимых полос

## Запрос

04.09.2026 пользователь прислал два скриншота: на первом мешают горизонтальная
полоса доски и вертикальные полосы внутри колонок; на втором показан желаемый
стандартный набор. Это уточнение к ранее выпущенной компактной очереди,
каноническая задача `7323301b79de2fc339d11144e81a313d` перечитана и повторно
открыта. Исходный контракт `CONSTRUCTOR_AND_BOUNDED_WORK_2026_09_04.md`
сохраняется как история предыдущего решения.

## Поведение доски

По умолчанию «Вся работа проекта» показывает в указанном порядке:
«Не начато», «В работе», «Завершено», «Отложено», «Отменено».
Состояния «Разобрать», «Заблокировано», «На проверке» скрыты из этого
представления. Сами состояния и записи не удаляются и не перемещаются.
Их можно показать через «Настроить вид → Поля и элементы» или открыть работу
в списке. Фильтр состояния продолжает действовать независимо от видимых колонок.

Внешняя горизонтальная и внутренние вертикальные полосы не рисуются.
Прокрутка колёсиком, тачпадом, жестами, клавиатурой и существующим перетаскиванием
доски сохранена: overflow остаётся auto, используется scrollbar-width: none
и скрытие ::-webkit-scrollbar. Место под вертикальную полосу больше не
резервируется. Это важно, чтобы освободившаяся ширина досталась карточкам.

Высота колонок по-прежнему ограничена 58dvh с прежними верхним/нижним пределами;
карточки раскрываются порциями по 20. Заголовок и общий счётчик видны постоянно.
На обычном широком экране пять колонок делят доступную ширину. На телефоне
сохраняется удобная ширина карточек и горизонтальное пролистывание жестом.
Пользовательские доски сохраняют свои этапы; правило скрытия полос применяется
и к ним, но их схему новый стандартный набор не заменяет.

## Настройки и совместимость

`defaultWorkBoardLayout` дополняет вид страницы только если ещё не сохранён
собственный набор системных колонок. Другие поля, плотность и геометрия
сохраняются. Скрытые этапы пользовательской доски не считаются выбором системных
колонок. Ранее сохранённые сочетания системных колонок остаются прежними.

Явный выбор всех восьми колонок должен переживать перезагрузку. Для отличия
«ещё не настраивал» от «показать все» в существующий JSON настроек добавлен
логический признак `workBoardColumnsConfigured`. Он устанавливается при
изменении системной колонки в редакторе и сохраняется штатным API. Миграция
SQLite не требуется. Сброс текущей страницы возвращает стандартные пять.

Наборы интерфейса сохраняют этот признак и ключи восьми системных колонок.
ID этапов пользовательских досок по-прежнему исключаются из переносимого
набора. Это позволяет переносить стандартное представление без раскрытия
идентификаторов чужой схемы. Профили ПК/телефона и разных проектов независимы.

## Проверка и выпуск

Проверяются стандартные пять колонок, сохранение восьми после перезагрузки,
сброс к пяти, сохранение прочих полей, независимость пользовательской схемы,
большая колонка и прокрутка без полос, ширина 320 px. Проверки JSON и наборов
подтверждают сохранение явного выбора всех колонок и фильтрацию чужих ID.
Физические мобильные устройства не использовались.

Версия оболочки приложения фиксируется в index/app/styles/service worker.
Штатный `deploy/deploy-board-defaults-20260904.sh` создаёт резервную копию,
запускает кандидат на копии БД на том же сервере и сравнивает все таблицы.
После переключения проверяются сайт, защищённые API, палитра, логотип и
ресурсы. Фактические commit/release/backup добавляются в журнал
`docs/operations/ACTIVE_TASKS_RELEASES_2026_09_03.md` после успешного выпуска.
