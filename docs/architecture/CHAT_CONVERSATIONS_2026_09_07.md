# Разговоры, история и черновики — 07.09.2026

Документ дополняет прежние контракты чата и приёмку повседневных сценариев.
Причина изменения: существующий чат позволял создать только ветку карточки,
обрезал историю до 200 сообщений и искал только в загруженной части. Общий
разговор мог показывать имя одного коллеги, что создавало ложное ощущение
приватности. Черновик и позиция чтения терялись при повторной отрисовке.

## Разговор и доступ

`POST /api/chat/threads` сохраняет совместимость с `recordId` и принимает
`kind=direct` с `partnerId` либо `kind=group` с `title` и `memberIds`.
Создатель включается в состав. Для личного диалога нужен другой действующий
участник текущего проекта; группа содержит 2–100 человек и название до 100
символов. Проверка всех участников выполняется в транзакции. Повтор личной
пары в том же проекте открывает прежний ID, а не создаёт копию.

Миграция 056 добавляет `conversation_kind` и `direct_key` без пересоздания
старых таблиц. Legacy `kind=record` с пустым `record_id` используется для
новых разговоров из-за прежнего CHECK; внешнее API возвращает фактический
`direct`/`group`. Уникальный индекс пары включает workspace. Старые IDs,
сообщения, вложения, связи, авторство и прочтение сохраняются.

Общий разговор подписан «Общий чат проекта», имеет реальный счётчик состава
и не получает чужой личный статус присутствия. Получатель личного разговора
определяется по составу этого разговора, а не первым пользователем проекта.
Третий участник проекта не получает список, историю и закрепления закрытой
группы/пары. Отзыв доступа к проекту закрывает API через общий auth-контекст.
Приватность здесь — серверный контроль участников. E2EE не реализовано.

Управление составом уже созданной группы, назначение администраторов и выход
остаются отдельным зарегистрированным этапом; создание группы не закрывает
эту работу. Административные данные команды не меняются созданием разговора.

## История, поиск и закрепления

`GET /api/chat/threads/{id}/history` выдаёт до 50 сообщений, `hasMore` и
`nextBefore`. Курсор принадлежит этому разговору, сортировка использует
`created_at,id`, поэтому равные временные метки не теряют элементы.
`before` загружает более раннее, `q` ищет текст, автора, название связанной
карточки и файла. Поиск русских букв нечувствителен к регистру через Go,
не ограничен прежними 200 сообщениями; сканирует SQL-строки до получения
страницы совпадений. Это корректная начальная реализация, но не готовый
полнотекстовый индекс для очень больших архивов. Нагрузочная задача остаётся.

`around` открывает страницу до выбранного сообщения включительно. В UI есть
возврат «К последним сообщениям»; двусторонняя непрерывная прокрутка вокруг
результата ещё не реализована. Старый endpoint `/messages` сохраняет контракт
для совместимости, новый интерфейс использует `/history`.

`GET/PUT /api/chat/threads/{id}/pins` читают и изменяют общие закрепления.
`chat_pins` сохраняет автора и время закрепления; ID сообщения проверяется
внутри разговора. Любой участник текущего состава может закрепить/открепить.
Архивированное сообщение не появляется в закреплениях и цитате ответа.
Сохранённые сообщения по-прежнему персональны и не равны закреплённым.

## Черновик и обновление экрана

Ключ localStorage включает пользователя, проект и разговор. Сохраняются текст,
ответ, карточка, nonce и незавершённая правка. При смене разговора восстанавливается
только соответствующий черновик. Очередь доставки остаётся существующим
механизмом IndexedDB с серверными квитанциями; localStorage не заменяет очередь.
Ошибка локального хранения показывается пользователю. Успешное помещение
сообщения в очередь очищает соответствующий ввод, а ошибка оставляет текст.

История догружается с сохранением позиции чтения, текущего текста и фокуса.
Опрос не перерисовывает открытое меню, запись медиа, воспроизведение и IME.
Отметка прочтения ставится в видимом разговоре у нижнего края, не в поиске.
Мгновенная доставка, набор текста и полноценные delivery-квитанции пока
остаются в существующей задаче realtime; текущая частота опроса — 3 секунды.

## Визуальная модель

Текстовое поле, вложения и одна контекстная кнопка: пустой ввод показывает
микрофон, заполненный — отправку. Высота ввода адаптируется до 160 px.
На desktop Enter отправляет, Shift+Enter добавляет строку; IME и coarse pointer
не используют этот shortcut. Реальная экранная клавиатура проверяется отдельно.

Меню сообщения перенесено внутрь пузыря. Прежнее внешнее расположение с зазором
создавало потерю hover до достижения кнопки. Меню позиционируется в пределах
viewport; редкие проектные действия остаются внутри. На узком экране основная
кнопка меню имеет цель 44 px. Календарь/палитра/логотип не заменяются стилем Telegram.
Высота чата учитывает фактическую верхнюю панель и visualViewport, чтобы ввод
не уходил ниже видимой области. Это проверяется по геометрии, а не только CSS.

## Проверяемость

Новый интеграционный тест создаёт три аккаунта, закрытые диалоги/группы,
236 сообщений, проходит все страницы без дублей, находит старый русский текст,
проверяет чужой курсор и права закреплений. Модульные тесты проверяют сохранение
и изоляцию черновиков, повреждённый JSON, объединение страниц и правки.
Браузерные результаты и ограничения — в отчёте выпуска и реестре сценариев.
Откат бинарника допускает добавочную схему, но старый интерфейс не понимает
новую семантику direct/group; восстановление старой БД поверх новых сообщений
недопустимо. Старые группы/состав при откате не расширяются автоматически.
