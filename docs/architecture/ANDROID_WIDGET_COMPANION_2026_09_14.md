# Android: виджет выбранного блока конструктора — 14.09.2026

## Зачем нужен отдельный небольшой APK

Пользователь просит видеть свои привычки, чтение и другие собранные им блоки
на домашнем экране телефона. Ярлык PWA открывает страницу, но не показывает
живые данные рядом с иконками. Поэтому добавлен отдельный Android App Widget,
а существующие страницы, конструктор и авторизация остаются на сайте.
Это первый работающий клиент контрактов мобильных блоков, а не обещание
безграничного HTML внутри системного виджета и не полная замена веб-приложения.

Исходники находятся в `mobile/android`. Название приложения — **Tessavie Widgets**,
пакет `ru.tessavie.widgets`, версия `0.1.0-preview`. Используется текущая иконка
`web/brand/tessavie-192.png`, светлый нейтральный фон и зелёный акцент Tessavie.
Новый знак или палитра не вводились. Действующие исторические мобильные отчёты
сохраняются: их утверждение «APK пока нет» относится к прежнему выпуску PWA.

## Пользовательский путь

1. Настройка источника выполняется на сайте в одном месте:
   **Настройки → Личные настройки → На телефоне**. Пользователь выбирает
   доступный блок конструктора и получает одноразовый код.
2. Пользователь устанавливает предварительный APK. Его стартовый экран
   объясняет добавление виджета и открывает Tessavie через обычный браузер.
   Приложение не просит пароль от сайта и не встраивает ещё одну форму входа.
3. В системном выборе виджетов Android пользователь выбирает Tessavie,
   размещает его на домашнем экране и вставляет код в стандартном экране
   подключения виджета. Для каждого экземпляра создаётся отдельное подключение.
4. Виджет показывает название, выполненное/общее число, полосу прогресса
   и несколько пунктов. На компактном размере остаётся обзор прогресса;
   на более высоком — до четырёх подписей. Длинные подписи обрезаются внутри
   своего блока. Кнопки имеют высоту 48 dp.
5. «Обновить» запрашивает свежий снимок. «Открыть Tessavie» открывает сайт,
   где пользователь отмечает пункты и редактирует свой набор.

Первый контракт возвращает `openUrl: "/"`. Переход в конкретный блок и отметка
прямо в виджете остаются отдельными расширениями общего контракта. Пользователь
не выбирает структуру набора второй раз в Android: клиент только подключает
выбранный на сайте блок. Поэтому настройки не размножаются по боковому меню.

## Контракт и границы данных

`POST https://control.e-rd.ru/api/mobile/widgets/redeem` получает JSON `{code}`.
Код — 32 строчных hex-символа. Успешный ответ содержит `token`, `expiresAt`,
`widgetId`. Токен — 64 hex-символа; дата — RFC3339 UTC, в том числе с дробными
секундами. Код одноразовый; повторный запрос после его принятия не должен
создавать вторую независимую привязку. При отмене во время сетевого обмена
код может уже оказаться использованным: экран явно просит новый код, если
подключение не завершилось. Токен незавершённой конфигурации на диск не попадает;
оставшееся серверное разрешение можно отозвать в настройках сайта.

`GET https://control.e-rd.ru/api/mobile/widget` использует `Authorization: Bearer`.
Ответ: `widgetId`, `title`, `kind` (`tracker` или `progress`), `completed`,
`total`, `items: [{label, checked}]`, `updatedAt`, `openUrl`. Клиент проверяет
идентификатор ожидаемого блока, тип, неотрицательный целый прогресс не более
500 элементов, ограничение списка восемью элементами и адрес открытия.
Для `progress` пустой `items` корректен. Полный список не нужен на малом
домашнем виджете; сервер агрегирует его, сохраняя правила видимости.

`updatedAt` означает последнее изменение данных. Локальное `fetchedAt`
записывается только после успешного GET и отдельно показывается как
«Обновлено». Поэтому давно неизменённая привычка не выдаётся за сетевую ошибку.
Поля внешнего оформления `color` и `background` пока не применяются: первый
клиент сохраняет проверенную читаемую палитру. Произвольный HTML, JS, URL картинок
и CSS из блока не выполняются. Это ограничение отображения маленького системного
экрана, а не скрытая замена универсального конструктора готовыми сценариями.

## Хранение доступа и приватность

Каждый Android `appWidgetId` имеет собственный AES-256-GCM ключ в Android
Keystore. Токен, срок доступа, снимок с приватным текстом и время обновления
хранятся только в зашифрованном виде в приватных настройках приложения.
Идентификатор экземпляра включён в authenticated additional data: перенос
зашифрованного значения к другому виджету не открывает его данные.

Автоматическое резервирование и перенос приватных файлов между устройствами
отключены в manifest/data-extraction-rules. Токен не передаётся в URL, системные
Intent, логи, буфер обмена или обычные настройки. Экран ввода одноразового кода
защищён FLAG_SECURE, код не сохраняется через состояние Activity и не отдаётся
автозаполнению. Снимок на домашнем экране видим окружающим — пользователь
получает об этом контекстное пояснение при подключении.

Сеть разрешена только к фиксированному HTTPS-хосту `control.e-rd.ru`.
Перенаправления HTTP не выполняются; пользовательские credential/host/port,
внешние ссылки, query с токенами и fragment не принимаются. Первый `openUrl`
разрешает только корень сайта. Системная проверка TLS не отключается.
Ответ ограничен 64 KiB; используются таймауты подключения и чтения по 12 секунд.

401/403 удаляют и токен, и сохранённый снимок, затем предлагают подключение
заново. Ошибка сети или сервера сохраняет последний снимок с явной пометкой
и временем получения. Удаление виджета отменяет его задачу и удаляет локальный
ключ/данные. Стартовый экран позволяет отключить конкретный виджет локально;
отдельный отзыв серверного разрешения доступен в общем центре настроек сайта.

Запоздалый результат старого запроса не восстанавливает удалённые данные
и не удаляет новую привязку: запись/очистка сверяют текущую capability.
Локальный выход из браузера сам по себе не равен отзыву отдельного подключения
виджета; управлять разрешениями нужно в разделе телефона на сайте.

## Фоновое обновление

Используются AppWidgetProvider + RemoteViews и JobScheduler. Сетевой запрос
выполняется вне BroadcastReceiver, в ограниченном пуле фоновых работ.
`updatePeriodMillis` — 30 минут; пользовательская кнопка ставит внеочередную
задачу с требованием подключения к сети. Нет постоянно работающего сервиса,
точных будильников, обхода Doze или отдельной подписки FCM.

Android управляет моментом фоновой работы; период не является гарантией
обновления ровно каждые полчаса. Ручное обновление также может быть отложено ОС.
После пропуска обновлений остаётся явное время снимка, а при отображении старого
снимка — пометка о возможной неактуальности. Этот выпуск не заявляет realtime.

Официальные основания: [App Widget configuration](https://developer.android.com/develop/ui/views/appwidgets/configuration),
[App Widget updates](https://developer.android.com/develop/ui/views/appwidgets/advanced),
[Android cryptography](https://developer.android.com/privacy-and-security/cryptography).

## Сборка и распространение

Требуются JDK 17, Android SDK Platform/Build Tools 34 и Gradle 8.13.
AGP закреплён на 8.5.2, Gradle wrapper проверяет SHA256 дистрибутива.
`local.properties` с путём SDK не входит в Git; можно использовать
`ANDROID_HOME`. Минимальная версия Android — 8.0/API26, target/compile — API34.
Это APK для прямого тестирования, не заявление о соответствии текущим
требованиям приёмки Google Play.

Команды из `mobile/android`:

```text
gradlew.bat :app:assemblePreview :app:testPreviewUnitTest :app:lintPreview
gradlew.bat :app:connectedDebugAndroidTest
```

Первая создаёт `app/build/outputs/apk/preview/app-preview.apk`. Вариант `preview`
имеет `debuggable=false`, подписан локальным Android debug-сертификатом и явно
помечен предварительной версией. Постоянная защищённая signing identity,
обновления через магазин и публикация — последующие задачи. Приватный ключ
не включён в репозиторий; подмена сертификата при обновлении потребует нового
решения по распространению. Файлы APK/build/local.properties/keystore исключены
из Git. Сборка `release` остаётся неподписанной, пока не настроена постоянная
схема выпуска; секреты не встроены в Gradle.

## Проверки, подготовленные для этой версии

- JVM: допустимые адреса и запрет внешних/credential/query URL, код и токен,
  границы прогресса, даты, парсинг реального формата снимка, несовпадение блока,
  неизвестный тип, слишком длинный список и пустой агрегат.
- Android instrumentation: фактический Keystore AES-GCM round-trip,
  удаление, независимые экземпляры, невозможность переноса шифротекста,
  очистка на 401/403 и сохранность новой привязки после старого отказа.
- Android RemoteViews: инфляция и измерение малого/большого виджета с длинным
  названием, доступность 48 dp действий и отсутствие выхода за границы.
  Тест сохраняет изображения собственного синтетического layout для осмотра.
- Lint выполняется без baseline, скрывающего ошибки API/вёрстки.

Факт выполнения, версия эмулятора, SHA256 и остаточные ограничения дополняются
ниже после проверки финального APK. Наличие тестового файла само по себе
не считается прохождением проверки.

## Что этим этапом не заявляется

Нативного iPhone WidgetKit клиента, установки на физический телефон, проверки
конкретного launcher производителя, полноценных нативных редакторов,
действий отметки прямо в виджете и APNs/FCM этот APK не предоставляет.
Уведомления установленного веб-приложения используют существующий Web Push
и настраиваются на сайте. Работа iPhone остаётся отдельным нативным этапом;
Android APK нельзя установить на iOS.

## Фактическая проверка первого APK — 14.09.2026

Сборка `assemblePreview`, 10 JVM-тестов и `lintPreview` завершились успешно.
Lint: ноль ошибок и два совета обновить только тестовые зависимости AndroidX
runner/core; API34-совместимые версии закреплены явно, baseline не создавался.
Gradle сообщает об устаревающих внутренних возможностях плагина перед Gradle9;
используемый wrapper закреплён на 8.13, самопроизвольного перехода на9 нет.

Для проверки установлен официальный Android Emulator 37.1.11.0 и образ
Android14/API34 `default/x86_64`, revision2. Они загружены Android SDK Manager
в существующий SDK с уже принятыми лицензиями. Включённая ранее Windows
Hypervisor Platform оказалась доступна; настройки виртуализации и безопасности
Windows не менялись. Создан отдельный AVD `tessavie_widget_api34` и запущен
с `-no-window -no-audio -no-snapshot -gpu swiftshader`, порт5580.

На этом эмуляторе **выполнены и прошли все четыре instrumentation-теста**:
Keystore/удаление, изоляция экземпляров, отказ доступа со сменой привязки,
RemoteViews с размерами180×180,180×300,320×180,320×300dp. Результат получен
через AndroidJUnitRunner; это выполнение Android-кода в ОС, не только проверка
текста Java. Синтетические изображения малой и большой компоновки просмотрены:
название остаётся в пределах виджета, индикатор и дата читаемы, кнопки не
перекрываются. Подпись открытия на узком виджете сокращена до «Открыть»,
accessibility-описание остаётся «Открыть Tessavie».

Исходный layout отрисовывался самой системой Android внутри теста; это не
снимок реальных приватных данных пользователя. Изображения и отчёты находятся
в игнорируемом `mobile/android/app/build`, повторяются описанными тестами.
Проверка на физическом Android8, конкретном телефоне пользователя и launcher
производителя ещё требуется. Эмуляторная проверка не подтверждает фактическую
доставку push на заблокированный телефон.
