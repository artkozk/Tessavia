# Организация личных заметок — 04.09.2026

Каноническая задача: `55f55a231e05ee5e2653b8b902be5aba`.
Основание: существующие заметки уже имеют цельный редактор, закрепление и связи,
но большой набор невозможно удобно разложить по темам или создавать по образцу.
Расширение использует текущие цвета и редактор, не вводит отдельный визуальный стиль.

## Сценарии и причины решений

1. Папка и метки необязательны. Заметка без них остаётся полноценной записью.
   Папки личные и плоские; метки позволяют одной заметке находиться в нескольких
   тематических выборках без дублирования текста. Закрепление используется как
   существующее избранное, без второго конкурирующего флага.
2. Переименование папки сохраняет её ID; перемещение меняет только принадлежность
   заметки. Связи с планами, привычками и записями продолжают ссылаться на ID заметки.
   Удаление папки переводит записи в «Без папки» и архивирует саму папку; тексты
   и связи не удаляются. Устаревшие редакторы получают конфликт версии.
3. Список фильтруется по тексту, папке, метке и закреплению. Поиск учитывает название,
   содержание и организационные признаки; приватный общий поиск расширяется теми
   же признаками, не создавая новый поисковый сервис.
4. «Заметка дня» открывает единственную активную запись владельца на выбранную дату.
   Повтор, два окна и потеря ответа не создают второй экземпляр и не перезаписывают
   написанное. Дата передаётся календарной строкой из локального дня пользователя.
5. Шаблон — личный образец названия, текста, папки и меток. Его можно создать из
   текущего текста, изменить и архивировать. Новая заметка получает копию; дальнейшее
   изменение шаблона не меняет прежние заметки. Подстановка `{{date}}` вставляет
   выбранную дату, без исполнения выражений. Повтор создания с прежним ключом
   возвращает уже созданную заметку.

## Приватность и совместимость

Все новые запросы ограничены владельцем из сессии. Чужие ID папок, шаблонов и
заметок не раскрывают их существование. В командные экспорт, поиск, уведомления
и AI личные данные не добавляются. Миграция дополняет схему и не переписывает
старые значения, ID или связи. Старые запросы редактора без новых полей сохраняют
имеющиеся папку и метки; новые записи прежнего outbox остаются совместимыми.

## Проверки перед выпуском

Папки/метки: создание, переименование, перенос, удаление папки с сохранением
заметок и связей, нормализация меток, конфликт версии и чужой владелец.
Заметка дня: повтор и разные даты/пользователи, существующий текст не меняется.
Шаблоны: независимая копия, подстановка даты, повтор после изменения шаблона,
архивирование, приватность и сохранность редакторского черновика. Проверить
прежние сценарии заметки из плана и offline outbox, поиск и фильтры, длинные тексты
и ширину 320 px. Фактические результаты и выпуск добавить после проверки.

## Реализованный путь пользователя

В «Личное → Заметки» расположены поиск, папка, метка и переключатель
закреплённых. Условия пересекаются; поиск без учёта регистра включает текст,
название папки и метки. Первая порция содержит 24 карточки, кнопка «Показать ещё»
раскрывает следующие 24. Счётчик отражает всю выборку. Это ограничивает первичный
объём DOM, но не прячет записи после условного лимита. Данные заметок пока приходят
в прежнем personal overview целиком; серверная пагинация заметок в этот выпуск
не входит. При смене аккаунта фильтры сбрасываются.

В редакторе остаётся прежний цельный документ. «Папка и метки» раскрывает
необязательные поля. «Без папки» убирает принадлежность; пустая строка меток
удаляет метки. Метки разделяются запятыми, точкой с запятой или переносом;
сервер допускает 20 меток по 40 символов, удаляет начальный `#`, пробелы и
повторы без учёта регистра, включая кириллицу. Папка имеет до 80 символов;
одноимённые активные папки одного владельца запрещены. У разных владельцев
одинаковое название допустимо.

«Папки» открывает существующее рабочее окно приложения. Создание и переименование
используют разные области черновиков: переход к другой папке сохраняет введённый
текст предыдущей формы. Удаление явно объясняет, что тексты и шаблоны сохранятся.
«Сохранить как шаблон» открывает форму поверх редактора заметки, не заменяя его
DOM. Можно сохранить несохранённый текст как образец и затем продолжить исходную
заметку. При невозможности записать черновик в хранилище переход блокируется.

У шаблона есть собственное название для списка, заголовок будущей заметки,
текст Markdown, папка и метки. В общем списке передаются только метаданные
шаблонов; тело загружается при редактировании. Нажатие названия создаёт копию
на сегодня. «Заметка дня» открывает существующий день либо создаёт пустой
документ с заголовком; запись не создаётся автоматически в фоне.

## API и схема хранения

Миграция `039_note_organization.sql` добавляет `personal_note_folders`,
`personal_note_templates` и поля `folder_id`, `tags_json`, `daily_date`
в `personal_notes`. Индексы ограничивают одно активное имя папки владельца и
одну активную заметку владельца на календарный день. Старые данные не переписываются.

| Запрос | Назначение |
| --- | --- |
| `POST /api/personal/note-folders` | Создать личную папку |
| `PATCH /api/personal/note-folders/{id}` | Переименовать по `expectedUpdatedAt` |
| `DELETE /api/personal/note-folders/{id}` | Архивировать папку и снять принадлежность |
| `POST /api/personal/note-templates` | Сохранить новый образец |
| `GET /api/personal/note-templates/{id}` | Прочитать полный собственный образец |
| `PATCH /api/personal/note-templates/{id}` | Обновить по версии |
| `DELETE /api/personal/note-templates/{id}` | Архивировать по версии |
| `POST /api/personal/notes/daily` | Открыть/создать день по `date` |
| `POST /api/personal/note-templates/{id}/instantiate` | Создать копию по `date` и `requestKey` |

Прежние `POST/PATCH /api/personal/notes` принимают `folderId` и `tags`.
Отсутствующее поле PATCH сохраняет старое значение; пустое снимает его.
Переименование/перенос не меняет идентификатор заметки. Удаление папки одной
транзакцией снимает её с заметок и шаблонов, обновляет их версии и архивирует папку.
Поиск по старому названию папки перестаёт находить запись, по новому начинает;
связи продолжают работать. Чтения не выполняют запрос внутри незакрытого
итератора: SQLite использует одно подключение.

Повтор создания копии использует общую таблицу квитанций личного outbox.
Ключ связан с владельцем, ID шаблона и датой; возврат квитанции происходит до
проверки текущей версии/архива шаблона. Поэтому потерянный ответ можно повторить
даже после изменения или архивирования образца. Возвращается актуальная копия,
её последующие ручные правки не заменяются исходным текстом. Ключ ожидающего
подтверждения хранится на устройстве отдельно по владельцу/шаблону/дню и
переживает перезагрузку. После подтверждения следующий клик создаёт новую копию.
При недоступном хранилище запрос не отправляется. Подстановка даты повторно
проверяется на ограничения длины заголовка и текста.

Для старых outbox-запросов без организации сохранён прежний алгоритм отпечатка.
Это необходимо, чтобы после обновления ранее отправленная запись не стала
конфликтовать сама с собой. Новые папка/метки включаются в отпечаток только при
наличии. Обычное создание заметок продолжает проходить через долговечную очередь;
управление папками/шаблонами и открытие дня требуют связи с сервером.

## Результаты автоматических проверок

`go test ./...`, `go vet ./...` и 157 Node-тестов прошли. Новые серверные
сценарии проверяют чужого владельца, конфликт версии, поиск кириллицей по четырём
источникам, сохранность связей при переименовании/удалении, старый редактор без
новых полей, повтор старой квитанции после удаления папки, независимость копии
от шаблона. Шесть одновременных запросов дня создали ровно одну заметку;
архивированный день не возвращается как активный. Клиентские тесты проверяют
пересечение фильтров, нормализацию меток, порцию 24 из 85 и сохранение ключа
после перезагрузки с изоляцией аккаунтов.

В локальном браузере проверены создание папки, меню над редактором, метки,
закрепление, поиск, дневная запись и её черновик после закрытия. Создание
шаблона из несохранённой заметки сохранило исходный текст и метаданные.
После намеренной потери ответа создания копии, перезагрузки и повторного
применения в тестовой БД осталась ровно одна копия. Использовались только
синтетические данные стенда. Подробности узкого экрана и фактического выпуска
дополняются в операционном журнале после проверки.
