# Начало процесса в конструкторе

Продолжение прямого запроса 07.09.2026 об удобной настройке для разных команд.
Пустая форма с названием не объясняла, как получить доску под конкретную работу.
Теперь новая доска предлагает свой процесс, продажи, подбор команды, публикации
и обращения. Перед созданием показаны колонки и поля; карточки-примеры и чужие
данные не создаются. Общая палитра и обычные элементы формы сохраняются.

Это стартовые схемы, а не запрет на собственную структуру. После создания
администратор может менять/архивировать/восстанавливать/переставлять поля и
колонки существующим конструктором. Каждая копия получает собственные ID.
Ни одна другая доска не меняется. Все дополнительные поля по умолчанию
необязательны; команда сама определяет обязательность. Ответственный, срок,
приоритет, связи, файлы и обсуждение используют существующую модель карточек.

GET /api/collection-templates требует авторизацию и возвращает общий каталог.
POST /api/collections принимает templateId, только owner/admin конкретной
команды. Доска, колонки, поля, варианты и история создаются одной транзакцией.
Неизвестный templateId отклоняется до записи. Старый запрос без templateId
сохраняет обычную доску с четырьмя колонками и без дополнительных полей.
Данные существующих досок не мигрируются. Переключение примера до создания
обновляет предложенные значения, но сохраняет уже изменённый пользователем
текст. Выбранный пример и все поля формы входят в черновик пользователя/проекта.

Дополнительно устранено молчаливое удаление неверных вариантов при создании
поля. Выбор требует 1–1000 разных непустых названий до 80 символов. Ошибка
отклоняет всё создание; обязательное поле с пустым справочником не появляется.
Названия обрезаются по краям, а не теряются. У старого клиента при смене типа
скрытый список вариантов для текстового поля игнорируется. Старые поля и
заполненные значения не исправляются догадками.

Ограничение: шаблоны не заменяют собственные типы объектов и формулы; базовая
модель записей сохраняется. Финальная колонка означает завершённый этап,
а не обязательно выигрыш сделки/положительное решение. Расширение набора
шаблонов и библиотека собственных процессов остаются последующей работой.

Приёмка фиксируется после ручного прохождения. Серверные проверки создают
две независимые копии каждого процесса, меняют поля, создают запись, проверяют
отсутствие общих ID, права и неизвестный шаблон. Отдельно проверяется отклонение
неправильных вариантов без частичной записи. Node проверяет сохранение своего
текста при переключении процесса и восстановление предпросмотра.

## Приёмка SC-58 и исправление присланного наложения, 12:54 МСК

В браузере выбраны «Продажи», введено своё название, затем «Публикации».
Своё название осталось; предлагаемые описание и тип подписи обновились.
После отмены/повторного открытия восстановились шаблон, предпросмотр и текст.
Создана синтетическая доска «SC-58 Редакционный процесс команды»: 4 колонки,
3 поля, 0 карточек. Созданный пользователем материал с Сайт + Telegram
сохранил оба значения. Соседняя доска сохранила прежние 13 карточек.

Пользователь прислал наложение названий досок прямо во время проверки.
Воспроизведение при 320 px: кнопки сжались до 57–76 px, текст имел ширину
176–277 px и рисовался поверх соседей. Исправлено сжатие вкладок: каждая
имеет свою ширину до 290 px, подпись ограничена многоточием, полное имя
доступно в title. Полоса прокрутки видима; выбранная вкладка остаётся в поле
зрения. До 600 px используется один выбор доски с полным списком названий
и отдельным плюсом. Поиск получил отдельную строку. Проверены оба длинных
названия, смена доски, список поверх содержимого при 320 px; при 1280 px
ширины вкладок 249/290/140 px, их содержимое не выступает наружу.

Устранено «Новая материал»: форма использует «Создать: <название карточки>»
с экранированием названия. Закрытие формы новой доски имеет доступное имя
и кнопку не меньше 44 px. Поля нескольких значений используют реальные
переменные палитры платформы.

При создании поля «Сайт, сайт» сервер вернул понятную ошибку; поля не появилось,
форма и введённый текст остались. 218 Node прошли; полный Go прошёл, после
последнего изменения шаблонов повторены профильные серверные и asset-проверки.
Тест искусственного отказа записи поля подтвердил откат всей доски.

## Уточнения по визуалу пользователя, 12:59 МСК

По двум новым снимкам устранены нативные рамки/заливка вкладок конструктора
и стандартные полосы прокрутки. Общие вкладки настроек команды теперь используют
прозрачный фон, шрифт платформы, зелёное подчёркивание активного раздела,
заметный клавиатурный фокус. На 320 px три вкладки помещаются в одну строку.
Общие полосы прокрутки имеют ширину 6 px, цвет разделителей платформы,
скруглённый ползунок без стрелок. Колесо/жесты и прокрутка вложенных блоков
сохраняются. В Chromium стандартные scrollbar-свойства отключены в пользу
псевдоэлементов, иначе возвращались нативные стрелки. Где полоса уже скрыта
компонентом, его прежний режим сохраняется. Для других движков используется
стандартный thin; реальная приёмка выполнена в Chromium, не во всех браузерах.

На дополнительной мобильной проверке найдено сжатие заголовка кнопками
предпросмотра. Заголовок и действия конструктора разделены на строки.
При ширине 320 px clientWidth/scrollWidth диалога равны 314, все три действия
находятся внутри границ (правая граница последнего 288 px), заголовок читается
целиком. У предпросмотра теперь настоящая иконка глаза вместо запасного знака
вопроса. Финальный просмотр выполнен на assets templates-5.
