# SC-74. Пользовательские страницы и переносимые наборы

## Требование и границы первого выпуска

Уточнение владельца: пользователь должен сам собирать сценарии и делиться работающей настроенной страницей, чтобы получатель установил её и пользовался без повторной настройки. Набор — структура, содержимое и поведение страницы, а не только тема оформления. Это меняет приоритет с отдельных косметических параметров на общий конструктор приложений. Исторические решения в ELEMENT_APPEARANCE_EDITOR_2026_09_07.md сохраняются; этот контракт описывает фактический первый срез.

В текущем срезе доступны пять примитивов: заголовок, текст, пункты с личными отметками, прогресс по выбранному блоку пунктов и кнопка перехода к выбранному блоку. Можно создать пустую страницу без разработчика, добавить/переименовать/переставить/скрыть/восстановить блоки, изменить тип, подписи пунктов и оформление. Пример — собственный план чтения или обучения. Это **не полная замена** готовой читалки с книгами, дневником, рейтингом, группами и расписанием и не полный конструктор произвольных бизнес-приложений.

## Пользовательский путь

1. В настройке меню/страниц выбрать «Создать страницу». Начать пустую, открыть наборы либо прежний редактор списка/доски карточек.
2. В конструкторе задать название страницы, добавить нужные блоки. Для пунктов ввести свои подписи, по одному пункту в строке. Недобавленные строки сохраняются в черновике и включаются при сохранении страницы.
3. Выбрать представление пунктов: список, плитки, круги. Связать прогресс с нужным трекером и кнопку с целевым блоком.
4. Настроить ширину из 12 колонок, высоту/размер текста, отступы, скругление и цвета. Ноль высоты и размера текста означает автоматический размер. На узком экране блоки занимают полную ширину.
5. Проверить предпросмотр, сохранить. Отмена оставляет серверную страницу без изменений. Черновик привязан к пользователю, пространству и странице; устаревшая ревизия не восстанавливается автоматически.
6. Сохранить страницу как набор: название, описание, доступ только себе или всем пользователям платформы. В набор входят также скрытые блоки/пункты — это явно написано перед сохранением. Личные отметки не входят.
7. В «Наборы страниц» посмотреть состав и установить независимую копию в выбранное пространство. Владелец набора может опубликовать его и снять с публикации. Уже установленные копии сохраняются.

## Данные, права и совместимость

Миграция 064 добавляет page_app_definitions, page_app_marks, page_app_templates. Существующие страницы, карточки, доски и их данные не переписываются. Список workspace_pages получает вычисляемый признак app. Старые списки/доски продолжают использовать прежние источники данных. Новые страницы не получают бессмысленный счётчик всех карточек проекта. Общая кнопка настройки на новой странице открывает её конструктор.

Definition version=1 хранит стабильные идентификаторы блоков и пунктов. Отметки хранятся отдельно по странице, блоку, пункту и пользователю. Скрытие/возврат и переименование сохраняют личные отметки; скрытые пункты не входят в видимый прогресс. Смена типа сохраняет остальные свойства и пункты, а сервер проверяет корректность связей. Произвольные JS/HTML/CSS не исполняются; текст экранируется, цвет ограничен HEX. Лимиты первого среза: 40 блоков, 500 пунктов в блоке, подпись 160 символов, текст 8000. Эти лимиты ограничивают нагрузку первой реализации, а не определяют конечный масштаб продукта.

Изменение общей страницы и установка набора доступны администратору пространства; участник может использовать страницу и менять только свои отметки. GET и PUT страницы проверяют её принадлежность активному пространству и отсутствие архива. PUT структуры использует expectedRevision, конфликт возвращает 409. Название страницы сохраняется в той же транзакции и не перезаписывается устаревшим редактором. Изменение отметки проверяет текущую ревизию и доступность пункта, принимает явный boolean, а не переключает значение вслепую.

Набор содержит снимок декларативной структуры, без пользовательских результатов и зависимости от исходного page_id. Установка транзакционно создаёт новую страницу с новой ревизией и без отметок. Редактирование копии не меняет оригинал/набор. Приватный набор виден только владельцу; публичный — авторизованным пользователям платформы. Только владелец может менять публикацию. Снятие с публикации ограничивает новые просмотры/установки, не отзывает уже выданные независимые копии.

Создание пустой страницы пока состоит из двух запросов: метаданные страницы и пустая композиция. Повтор в том же диалоге использует уже созданную страницу. Если соединение потеряно между запросами и диалог закрыт, может остаться пустая обычная страница; данные не удаляются, но атомарное создание — следующая доработка. Установка готового набора уже атомарна.

## Проверки и найденные дефекты

SC-74 в локальном браузере на синтетическом аккаунте: создана пустая страница «SC-74 Чтение и обучение», вручную добавлены три главы, ширина трекера 8, прогресса 4, шрифт 20, цвета #176b58/#e5e8e4, круги. Отметка главы показывает 33%, 1 из 3. Предпросмотр набора показывает 0 из 3. Установка создала отдельную страницу, затем через редактор она переименована в «SC-74 Независимая копия» и получила четвёртый пункт; reload сохранил 0 из 4. Повторный переход к исходной странице подтвердил прежнее название, три пункта и 33%, 1 из 3. Узкая ширина 320 px: страница, предпросмотр набора, установка и свойства редактора доступны без горизонтального наложения. Широкий экран проверен на 1280 px. Физические телефоны не проверялись.

В ходе проверки исправлены: отсутствие нового JS в embed; счётчик всех карточек у произвольной страницы; конфликт общей настройки с конструктором; select отправлял change, а свойства слушали только input; недоступность переименования самой страницы; потеря не добавленных строк при переключении; отсутствие снятия публикации; бледный предпросмотр из-за disabled-opacity; исключение первого модуля из offline allowlist. Версия ресурсов 20260908-page-apps-4. Кеш не хранит API и личные ответы.

Интеграционные тесты покрывают состав/ревизии, роль участника, изоляцию пространства и личных отметок, скрытие/возврат блока и пункта без потери результата, ошибочный цвет/boolean, приватность наборов, независимую установку в своём/другом пространстве, права публикации и сохранение установленной копии после снятия публикации. Node проверяет стабильные IDs, прогресс скрытых/пустых пунктов, экранирование и неинтерактивный предпросмотр. Дополнительно исправлена дата фикстуры прежнего personal-теста: фиксированная дата 1 сентября вышла из его семидневного окна после полуночи; теперь используется вчерашний день. Продуктовый алгоритм этого окна не менялся.

## Следующие приоритеты — не закрыты этим выпуском

- Источники пользовательских данных, типизированные поля, формы, списки/детали, связи и действия изменения записей; предпросмотр последствий и права.
- Конфигурация вложенных элементов и всех встроенных страниц, отдельные профили устройств, условная видимость, адаптивное расположение. Пять новых блоков не выполняют требование «абсолютно всё».
- Сборка полноценного аналога читалки вручную, затем бизнес-сценария с данными/правами, без закрытой конфигурации разработчика.
- Наборы с переносом зависимых схем/действий, версии и обновление копий с предпросмотром; импорт/экспорт файлом, управление библиотекой. Текущая «установка» — копирование внутри платформы, не скачивание файла.
- Безопасные преобразования заполненных полей (2092665a817cc23073154bc1adf06377), оставшиеся дефекты визуала/чата/команд из живой очереди.

Большие задачи 66da4e412e714f4ea85c56ff85de03ec, a288364706d6c9f0ff683003aea39009 и визуальный аудит остаются открытыми. Задача оформления b8a99823ccf3f3a9f39093fe3c1af2bf не считается выполненной свойствами только новых блоков.

## Выпуск

Штатный скрипт deploy-page-apps-20260908.sh требует точный предыдущий релиз, commit и SHA. Backup БД, uploads, env и nginx остаётся только на рабочем сервере. Dry run на копии проверяет 113 старых таблиц и все их строки, допускает только три новые пустые таблицы и запись миграции 064. Cutover имеет отдельный снимок; при ошибке возвращается предыдущий бинарник, который игнорирует добавленные таблицы. После переключения проверяются HTTPS, assets, отсутствие анонимного доступа, health, nginx, integrity и FK. Фактические commit, SHA и backup дописываются в операционный отчёт после проверки, а не выдаются заранее за состоявшийся релиз.
