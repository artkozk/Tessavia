# Проектная работа в личном «Сегодня» — 05.09.2026

## Основание

Каноническая задача `cf22d3a3a52d33eef11e8118a232d9a4` требует собрать
утренний сценарий из личных дел и работы доступных проектов. Ранее выпущенные
этапы уже дали фокус дня, события, свободное время, личные просрочки, привычки,
ожидания, напоминания, отдельный календарь, Review и независимую раскладку.
Повторная сверка показала незакрытый пункт: проектные карточки на сегодня,
приёмка и критические риски оставались только внутри каждого проекта.

Этот выпуск добавляет их в существующий экран. Палитра, логотип и структура
личного раздела не меняются. Используются те же строки, границы и типографика,
что у уже выпущенных блоков «Сегодня».

## Что попадает на экран

`GET /api/personal/day` возвращает две ограниченные секции по шесть строк.

«Моя работа в проектах» содержит только карточки, назначенные текущему
пользователю:

- со сроком в выбранный локальный день;
- в состоянии «В работе»;
- в состоянии «Заблокировано».

Карточка с истёкшим сроком показывается в «Требует внимания», поэтому не
дублируется в обычной проектной работе. На проверке и критические риски также не
дублируются. Завершённые, отменённые, архивные, отклонённые и отложенные записи,
а также обычная работа с прогрессом 100% не считаются активными.

«Требует внимания» объединяет прежние личные просрочки со следующими проектными
сигналами:

- прошёл срок карточки, назначенной пользователю;
- результат ждёт приёмки пользователя как `decision_maker`, либо автора при
  отсутствии отдельного принимающего;
- активный риск имеет критический приоритет и назначен пользователю либо требует
  его решения.

Причина показана перед названием: «Срок проекта прошёл», «Нужна ваша приёмка»
или «Критический риск проекта». Пустое состояние перечисляет эти три категории,
чтобы нулевой счётчик был понятен. Если строк больше лимита, видны полный счётчик
и количество показанных записей; длинный список не растягивает страницу.

## Дата, часовой пояс и порядок

Начало и конец выбранного дня вычисляются как гражданские полуночи в личном
часовом поясе из настроек дня. Сравнение срока выполняется по UTC-моменту с этими
границами. Поэтому срок около полуночи относится к тому дню, который видит
пользователь, включая переходы DST.

Сначала показываются сроки выбранного дня, затем блокировки и текущая работа.
В сигналах выше располагаются прошедшие сроки и приёмка, затем остальные
критические риски. При равных признаках используются сохранённое время изменения
и ID, что даёт стабильный порядок после перезагрузки.

## Переход к источнику

Строка хранит ID карточки и её проекта. Нажатие использует общий проверенный
переход Review: при необходимости клиент переключается в точный проект и только
после успешной проверки доступа открывает карточку. Произвольный ID из другого
проекта не строится на клиенте и не даёт обхода серверных прав.

## Приватность

Сервер начинает выборку с активного членства текущего пользователя в проекте и,
если проект связан с командой, с активного членства в этой конкретной команде.
Архивный проект или отозванный доступ исключают строку уже при следующем чтении.

Проектный участник видит только доступные ему общие карточки. Личный фокус,
планы, привычки, ожидания, свободное время и настройки дня по-прежнему выбираются
по `owner_id` текущей сессии. Владелец команды не получает личный экран другого
участника. Ответ проектных секций не содержит описаний, результатов, заметок или
личных связей: только данные, необходимые для короткой строки и перехода.

## Настройка и пустой аккаунт

Блок «Моя работа в проектах» добавлен в существующий конструктор личной страницы
как `day-project-work`. Его можно скрыть, переставить и настроить отдельно на ПК
и телефоне. Блок «Требует внимания» остаётся одним блоком и получает общий
счётчик личных и проектных сигналов.

Новый пользователь без команды получает обе секции с пустыми массивами и
нулевыми счётчиками. Экран не требует открыть конструктор: оба блока входят в
стандартную раскладку. Узкая строка переносит длинное название и не создаёт
горизонтальную прокрутку.

Стартовый экран «С чего начнём?» появляется только после загрузки сводки дня и
только когда нет ни личных сущностей, ни ожиданий, ни проектной работы, ни
проектных сигналов. До ответа сервера показывается загрузка обычных блоков дня.
Это сохраняет простой первый шаг для действительно нового аккаунта и закрывает
отдельный сценарий участника проекта без личных записей: такой пользователь
сразу видит назначенную ему работу, приёмку и риски.

## Производительность и проверка

Сервер сначала считает полный размер каждой секции, затем получает не более
шести строк. Он не загружает описания, историю, файлы и содержимое недоступных
проектов. Изменение схемы данных не требуется.

Серверный сценарий проверяет срок сегодня, текущую и заблокированную работу,
просрочку, отдельного принимающего, критический риск, завершённую запись,
назначение другому человеку, отзыв доступа, изоляцию аккаунтов и ограничение
длинного списка. Браузерные тесты фиксируют понятные причины, переход в точный
проект и наличие блока в конструкторе. Перед production-выпуском выполняются
полные `go test ./...`, `go vet ./...`, все Node-тесты и проверка реального
браузера на обычной и мобильной ширине.
