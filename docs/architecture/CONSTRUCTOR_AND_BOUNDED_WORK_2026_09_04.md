# Управление схемой и большие списки работы

## Почему нужен выпуск

Пользователь показал общую доску с 82 завершёнными карточками и сообщил, что
ненужные поля невозможно удалить. Сверка production: 82 активные задачи,
конструктор `a288364706d6c9f0ff683003aea39009` всё ещё postponed.
Новый прямой запрос владельца разрешает начать этот блок; прежняя отсрочка
сохраняется в истории задачи, но не блокирует явно запрошенные действия.

Добавление и переименование поля уже есть, жизненного цикла поля/колонки нет.
Общая доска статусов и пользовательская доска ошибочно имеют одну кнопку,
хотя первая является представлением работы, а вторая имеет общую схему.

## Реализуемые сценарии

1. Администратор выбранной команды может убрать пользовательское поле с доски.
   Оно исчезает из форм и фильтров, включая обязательность; сохранённые значения
   остаются в БД. В разделе удалённых элементов поле можно восстановить с теми
   же ID и значениями. Удаление не меняет соседнюю доску и личное представление.
2. Колонку можно удалить. Если в ней есть карточки, пользователь сначала
   выбирает другую действующую колонку той же доски. Перемещение выполняется
   атомарно, сохраняет статус, тип, результат, сроки и доказательства карточек.
   Последнюю колонку удалить нельзя. Восстановление колонки не перемещает
   карточки назад без запроса пользователя.
3. Порядок полей и колонок меняется в конструкторе и сохраняется для команды.
   Чужие и повторяющиеся ID, неполные наборы и устаревшие версии отклоняются.
   История фиксирует изменение схемы и размещения, данные не удаляются физически.
4. Общая доска «Вся работа» настраивается как личное представление. Её системные
   статусы можно скрыть/вернуть, не удаляя сами состояния и карточки. Кнопка
   объясняет, что меняется вид, а не схема произвольной другой доски.
5. Работа в списке показывается страницами по 25, с выбором 10/25/50 и полным
   счётчиком. Поиск/фильтр обрабатывают весь доступный набор до разбиения на
   страницы. Смена фильтра возвращает первую страницу; уменьшение набора
   ограничивает номер страницы. Поиск, экспорт и статистика не усекаются.
6. Доски имеют ограниченную высоту и прокрутку внутри колонок. Заголовок и полный
   счётчик остаются видны; большое количество карточек раскрывается порциями.
   После раскрытия/обновления восстанавливается позиция, переключение команды
   не переносит пагинацию и настройки другого аккаунта.

## Сохранность и проверки

Архивные даты уже существуют в схеме SQLite: миграция пользовательских данных
для этого выпуска не нужна. API изменения схемы требует роль владельца/admin
в конкретной команде и проверяет принадлежность всех ID. Изменение строки схемы
защищено updatedAt. Новые операции ведут историю, не создают тестовые записи
на production. В сухом прогоне релиза все таблицы до/после должны совпасть.

Тесты: удалить заполненное обязательное поле, сохранить карточку без него,
вернуть поле с прежним значением; чужая команда и обычный участник; удаление
пустой/заполненной/последней колонки; отмена выбора переноса; stale version;
перестановка без потерь; 82/1201 записей, фильтр последней записи, изменение
числа страниц, порции колонок и сохранение прокрутки. Браузер: desktop, 320 px,
длинные имена, меню поверх карточек, клавиатура, закрытие формы с черновиком.

Большие задачи конструктора и библиотеки не закрываются целиком этим этапом:
произвольные типы сущностей, формулы, преобразование заполненных полей,
сложные правила и несколько источников остаются отдельными критериями.
Текущий выпуск должен завершить именно удаление/восстановление/порядок схемы
и работу с длинной очередью, а не переименовать существующую функцию в конструктор.

## Реализация и проверяемое поведение

Канонический дочерний этап на платформе: `7323301b79de2fc339d11144e81a313d`.
Родитель `a288364706d6c9f0ff683003aea39009` переведён из postponed в in_progress
с дополнением прежнего описания. Родитель не закрывается по этому выпуску.

API: `GET /api/collections/{id}/schema` возвращает действующие и удалённые
элементы; `DELETE .../fields/{fieldId}` и `DELETE .../stages/{stageId}` убирают
элемент; `POST .../restore` восстанавливает; `PUT .../schema-order` сохраняет
порядок. Все эти операции требуют owner/admin текущей команды. Схема и значения
остаются в существующих таблицах; версии проверяются внутри транзакции.
PATCH редактирования имени/настроек также проверяет переданный expectedUpdatedAt.
Старые клиенты PATCH без этой опции поддерживаются; новые операции требуют версию.

Счётчик при удалении колонки включает архивные карточки: они тоже должны ссылаться
на действующую колонку. Подсчёт выполняется только при открытии конструктора,
а обычная загрузка досок не пересчитывает все записи. Транзакция сначала закрывает
SQL rows и лишь затем обновляет записи: это обязательно для SQLite с одним
соединением. История фиксирует операции со схемой и отдельные переносы карточек.

Список обрезается только после полного поиска/фильтрации/сортировки. Размеры
10/25/50, диапазон и переход на номер страницы доступны под ограниченным блоком.
Доска сначала выводит 20 карточек каждой колонки; кнопка раскрывает следующие 20.
Прокрутка колонок и горизонтальное положение восстанавливаются после работы
наблюдателя компоновки, иначе перестановка DOM-блоков сбрасывала позицию вверх.
Фильтр по удалённому полю очищается, чтобы он не продолжал незаметно скрывать записи.

Черновики создания поля и колонки используют существующее локальное хранилище
черновиков: ключ включает пользователя, команду, доску и вид формы. Escape и ×
сохраняют незавершённый ввод; повторное открытие раскрывает восстановленную форму.
Черновик удаляется после успешного создания. Переименование/удаление соседнего
элемента предварительно сохраняет обе незавершённые формы. При сбое локального
хранилища закрытие не уничтожает ввод.

Проверки браузером на синтетическом локальном проекте: поле создано, заполнено,
удалено и восстановлено с исходным значением; удаление Бэклога отменено, затем
карточка перенесена в «Открыто», её тип idea и статус review сохранены; порядок
колонок изменён, восстановление Бэклога не вернуло карточку назад. На 1201 записи
проверены 49-я страница, поиск последней записи, размер 50, порция 20→40 и
сохранение scrollTop=3157.6. Скрытие «Завершено» сохранилось после перезагрузки.
На ширине 320 px нет горизонтального выхода страницы/конструктора, список и
колонка ограничены по высоте, меню размера страницы доступно. Физические телефоны
не проверялись. Автоматическая проверка также компилирует весь JS, а не только
извлечённые функции: это выявило ошибку в склейке шаблона до публикации.

Пагинация интерфейса не меняет протокол начальной загрузки проекта: весь доступный
набор по-прежнему приходит существующими серверными страницами. Это решение
ограничивает длину страницы и число DOM-карточек, сохраняя полноту локального
поиска; оно не заявляет устранение всех причин сетевых задержек.

Итоговая локальная проверка: `go test ./...`, `go vet ./...`, 145 Node-тестов и
компиляция Python-процедур выпуска успешны. Отдельно на 320 px введено новое
название поля, нажата Escape, конструктор открыт снова: название восстановлено,
форма раскрыта, показано «Восстановлен несохранённый текст». Данные создавались
только в синтетическом локальном проекте. Операционный результат деплоя дополняет
`docs/operations/ACTIVE_TASKS_RELEASES_2026_09_03.md` после проверки сервера.

Дополнение проверки истории: запись переноса использует настоящий тип карточки,
поэтому попадает в фильтр истории идей/задач, а операции схемы имеют русские
названия и название доски. Добавлена проверка типа/команды события и подписей;
итоговый набор включает 146 Node-тестов. Пользовательские данные и прежние
события не переписываются.
