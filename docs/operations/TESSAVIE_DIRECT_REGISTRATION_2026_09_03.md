# Временная регистрация без ввода кода

## Новое решение пользователя

После открытия регистрации пользователь отдельно попросил убрать необходимость
кода вообще. Это дополнение к BIZFLOW_PUBLIC_REGISTRATION_2026_09_03.md:
предыдущий тестовый двухшаговый режим остаётся историческим этапом.

## Текущий контракт

BUSINESS_REGISTRATION_SKIP_VERIFICATION=true разрешает прямое завершение
регистрации. POST /api/auth/register возвращает пользователя и сессию с HTTP 201.
Браузер сразу открывает приложение, не показывает код и не делает второй запрос.
При отсутствии флага сохраняется прежний ответ 202 с обязательным кодом.

Оба режима используют одну серверную процедуру завершения: существующую
одноразовую внутреннюю заявку, проверку уникальности и действительности
приглашения, атомарное создание аккаунта и выдачу прав. В прямом режиме
внутренняя заявка завершается и удаляется в том же HTTP-запросе, её код не
возвращается клиенту. Это сохраняет проверки приглашения и не создаёт второго
набора правил регистрации. В истории честно записывается «Регистрация без
проверки почты», а не подтверждение почтового адреса.

Ссылка приглашения расходуется сервером один раз. Браузер убирает её из адреса
после успешной регистрации и не пытается принять повторно. Регистрация без
приглашения создаёт только личное пространство. Вход по существующему логину и
паролю не меняется; дубликаты и недействительные приглашения отклоняются.

## Проверки

TLS-интеграционный тест проверяет HTTP 201 и авторизованный /api/me, одно личное
пространство, отказ доступа постороннему в проект, одноразовое приглашение,
запрет повторного/недействительного приглашения, отсутствие оставшихся заявок
и честную причину в истории. Отдельно проверено, что флаг выключен по умолчанию.
Три браузерных модульных теста проверяют прямой вход, отсутствие двойного принятия
приглашения и совместимость с обычным ответом, требующим код.

## Выпуск и возврат проверки

Изменение выпускается вместе с исправлением кнопок личной страницы из
BIZFLOW_PERSONAL_HEADER_FIX_2026_09_03.md, поверх текущего Tessavie. Незавершённые
командные изменения и миграции 027/028 не входят в сборку. На копии рабочей базы
проверяется реальная прямая регистрация без записи проверочных людей в production.
Скрипт включает только новый флаг, сохраняя пустой список разрешённых логинов.
При неуспешном переключении восстанавливаются прежний бинарник и env.

Для возврата к прежнему тестовому подтверждению установить флаг в false и
перезапустить сервис. Для настоящей почтовой проверки дополнительно нужен
реализованный провайдер доставки, которого пока нет. Ни прямой режим, ни
показанный браузеру тестовый код не подтверждают владение почтой.

## Подтверждённый результат

SHA и переключении: BIZFLOW_PERSONAL_HEADER_FIX_2026_09_03.md. Проверочный запрос
на копии рабочей базы вернул 201 и только личное пространство. Искусственный
аккаунт этого прогона не создавался в рабочей базе. Локальный браузер прошёл
от формы с тремя полями сразу к приложению; экран кода не появлялся.

BUSINESS_REGISTRATION_SKIP_VERIFICATION=true. Прежний тестовый флаг сохранён,

Go-тесты, vet и 67 Node-тестов прошли. Для TLS проверены отдельные сессии
пользователей и граница доступа к проекту, не только наличие кнопки в браузере.
