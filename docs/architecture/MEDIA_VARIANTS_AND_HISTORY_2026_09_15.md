# Варианты материалов и история версий — 15.09.2026

## Основание и завершённый сценарий

Пользователь уточнил, что рабочая разработка логотипа требует нескольких
именованных вариантов, сохранения предыдущих изображений и понятного выбора
подходящего результата. Плоский список вложений из выпуска 074 не выражает эти
отношения. Этот этап добавляет общую модель к любой карточке, личной заметке
и медиаблоку собственной страницы. Отдельная страница логотипа, скрытая настройка
одного аккаунта или копирование личных материалов в команду не используются.

1. Пользователь открывает файлы существующей карточки, личной заметки или
   медиаблок и загружает материал с названием варианта и необязательной пометкой.
2. Первый файл образует вариант. Название описывает направление работы, а пометка
   относится к конкретной версии. Уже загруженные до выпуска файлы также видны
   отдельными вариантами; чтение не переносит и не переписывает их.
3. «Новая версия» добавляет новый файл к выбранному варианту. Старые байты,
   подпись, автор и дата не перезаписываются. У каждого варианта собственная
   последовательность версий; два альтернативных эскиза не требуется объединять.
4. История позволяет открыть или скачать доступную версию. Сравнение двух
   изображений использует те же защищённые адреса. Изменение истории не меняет
   статус самой рабочей карточки.
5. Пользователь может явно выбрать версию. Это выбор материала, а не одобрение
   администратором или автоматическое завершение задачи. Изначально выбор пустой.
   Добавление следующего файла сохраняет прежний выбор, если он был сделан.
6. Архив скрывает вариант из текущей работы с возможностью восстановления.
   Файлы и история сохраняются. Переименование и выбор тоже записываются в журнал.
7. После обрыва передачи повторяется незавершённый шаг: подтверждённый файл
   повторно не загружается, а незавершённая привязка повторяется с сохранённым ключом.
   Конфликт ревизии требует перечитать состояние и явно повторить изменение.

Примитив добавления рабочих файлов находится в рабочем материале. Изменение
структуры страницы по-прежнему относится к общему центру настроек. Свойства
медиаблока и его файлы являются разными сущностями.

## Области доступа

Общая реализация обслуживает три заранее разрешённые области; имена таблиц
или SQL не принимаются из запроса.

| Область | Коллекция API | Кто читает / изменяет |
| --- | --- | --- |
| Все типы карточек | `/api/records/{id}/media-variants` | Действующий участник пространства / существующая политика редактирования карточки |
| Личная заметка | `/api/personal/notes/{id}/media-variants` | Только владелец заметки |
| Медиаблок страницы | `/api/workspace/pages/{id}/app/media/{blockId}/variants` | Участник доступного блока / автор варианта или owner/admin |

Участник команды не получает доступ к личной заметке другого пользователя.
В варианте можно использовать только вложение того же родителя, а для страницы
также того же блока. Один файл не входит в две цепочки. Выбранная версия должна
принадлежать этой цепочке и быть доступной. Возможность управлять чужим файлом
проверяется отдельно от возможности читать его. Роль команды перечитывается
внутри транзакции; старый экран не сохраняет отозванные права.

Для `owner_only` карточки правила остаются прежними: автор/ответственный
могут изменять, обычная административная роль не обходит это условие сама по себе.
В общем медиаблоке автор версии сохраняется отдельно от автора варианта. Автор
первого исторического файла — его первоначальный загрузчик; журнал создания или
переименования указывает пользователя, выполнившего действие сейчас.

Архив карточки и личной заметки оставляет разрешённую историю доступной для
чтения, но запрещает изменения. Архивная либо скрытая страница доступна для
истории owner/admin; участникам возвращается отсутствие доступного блока.
Если блок удалён из определения полностью, его история недоступна до возврата
того же стабильного блока. Новый блок с другим ID не наследует материалы.

Архивный вариант страницы доступен его автору и owner/admin. Отдельно удалённый
старым API файл страницы доступен только его загрузчику и owner/admin.
Для остальных версия получает общее название «Файл недоступен», без подписи,
автора и адреса байтов. Нельзя раскрыть закрытый файл, угадав URL версии.
Прежний список вложений страницы и прежние адреса файлов также учитывают архив
варианта: сохранённая старая ссылка не обходит ограничение нового списка.

Если архивирован единственный исходный файл, вариант выглядит архивным и до
создания метаданных. Восстановление такого варианта также восстанавливает исходное
вложение в той же транзакции, в том числе после переименования в архиве.
В многоверсийной цепочке восстановление варианта не восстанавливает автоматически
отдельно удалённые файлы. Лимит медиаблока проверяется и при восстановлении.

## Контракт API

Далее `collection` означает один из трёх маршрутов таблицы выше.

| Запрос | Поля | Ответ |
| --- | --- | --- |
| `GET collection` | Нет | `{items, canCreate}` |
| `POST collection` | `requestKey`, `attachmentId`, `name`, необязательный `note`, `expectedRevision:0` | Весь вариант, 201; подтверждённый повтор 200 |
| `POST collection/{variantId}/versions` | `requestKey`, `expectedRevision`, `attachmentId`, необязательный `note` | Весь вариант, 201; подтверждённый повтор 200 |
| `PATCH collection/{variantId}` | `requestKey`, `expectedRevision`, `name` и/или `archived` и/или `selectedVersionId` | Весь вариант, 200 |
| `GET collection/{variantId}/history` | Нет | `{items:[{id,action,revision,actorId,actorName,details,createdAt}]}` |
| `GET collection/{variantId}/versions/{versionId}/file` | Для команды явный `workspaceId`; `download=1` для скачивания | Защищённые байты |

Вариант содержит `id`, `name`, `revision`, `archived`, `selectedVersionId`,
`canManage`, `createdBy`, `createdAt`, `versions`. Версия содержит `id`,
`attachmentId`, `version`, `name`, `contentType`, `size`, `preview`, `note`,
`createdAt`, `createdBy`, `createdByName`, `fileUrl`, `available`, `removed`.
`createdBy` — числовой ID аккаунта; `createdByName` — его имя пользователя.

Имя варианта: 1–160 символов Unicode после обрезки внешних пробелов. Пометка:
до 2000 символов. Максимум 100 версий в цепочке; следующие варианты создаются
независимо. Ключ запроса: 16–100 латинских букв, цифр, `_` или `-`, как в
существующих механизмах повторного сохранения. UUID допустим.

Стабильный ID варианта имеет вид `legacy:{attachmentId}`, ID версии —
`file:{attachmentId}`. Названия не используются для определения принадлежности.
Старый независимый файл представлен виртуальным вариантом с ревизией 0.
Первое изменение материализует его вместе с событием `imported`, затем выполняет
нужное изменение и увеличивает ревизию. Выбранная версия первоначально `""`;
PATCH с пустой строкой снимает выбор. Версии никогда не заменяются по номеру.

Клиент использует готовый относительный `fileUrl`. Для карточки/страницы
`workspaceId` явно включён в адрес, поскольку `<img>` и `<video>` не передают
произвольный заголовок пространства. Сервер повторяет проверку сессии и членства;
параметр не является разрешением. Ответы приватны и не кэшируются. Растровые
изображения/поддерживаемое видео просматриваются с ограничивающим CSP и `nosniff`;
остальные файлы скачиваются. Поддерживается Range. Публичных ссылок не добавлено.

## Загрузка, ревизии и атомарность

Существующие upload-маршруты остаются совместимыми. Заметка/страница уже
поддерживали `requestKey`; карточка теперь тоже поддерживает такой ключ.
Ответ карточки сохраняет прежние имена `id`, `originalName`, `sizeBytes`,
`contentType`. Ответ заметки/страницы сохраняет `id`, `name`, `size`, `contentType`.
Старый клиент без ключа карточки продолжает работать; для загруженных до 076
файлов невозможно выдумать задним числом подтверждение запроса.

Квитанция файла карточки привязана к аккаунту, карточке и ключу. Повтор сравнивает
имя, MIME, размер и SHA-256; совпадение возвращает тот же ID, изменение — 409.
Права повторно проверяются после получения байтов перед записью в БД. Ошибка
или повтор удаляют только временный файл этой попытки. Ответ содержит именно
ID текущей загрузки, без поиска «последнего файла», который мог бы оказаться чужим.

После подтверждения загрузки отдельная транзакция создаёт вариант или версию.
Её квитанция ограничена аккаунтом, областью, родителем, блоком и ключом.
Хеш включает вид операции, вариант и нормализованные поля. Подтверждённый повтор
возвращает актуальную цепочку без второго события или увеличения ревизии.
Проверка доступа всё равно выполняется. Повтор ключа с иными полями даёт 409.

Ревизия сравнивается до изменений и в финальном условном UPDATE. Изменения
цепочки, журнал и квитанция сохраняются в одной транзакции. При ошибке создания
версии не остаётся половины цепочки; ранее загруженный файл остаётся независимым
материалом и доступен для повторной привязки. При смене аккаунта, страницы или
родителя чужая очередь не переносится в новое место.

Локальные черновики и проверка ответов описаны отдельно в
[контракте адаптеров заметки/страницы](NOTE_PAGE_MEDIA_VARIANTS_ADAPTERS_2026_09_15.md).
Они не означают обещание неограниченного офлайн-хранилища: ошибки квоты устройства
показываются до отправки. Серверная квитанция не заменяет локальную проверку
успешного сохранения состояния очереди.

## Миграция и переносимость

`076_media_variants.sql` добавляет пять изначально пустых таблиц:

- `media_variants` — название, область, автор, выбранная версия, архив, ревизия;
- `media_versions` — неизменяемая ссылка на исходное вложение, номер, пометка;
- `media_variant_events` — неизменяемый журнал действий;
- `media_variant_requests` — подтверждения операций над метаданными;
- `record_attachment_requests` — подтверждения загрузок карточек.

Количество прикладных таблиц меняется со 143 на 148. Нет ALTER, переноса старых
строк или изменения схемы существующих таблиц. Первое чтение не делает backfill.
LF и исходный SHA-256 замороженного SQL:
`577efac5cbd49c40414d16dc4eb0a7908c22cea90109b2d4bb3ef6b6ed4f278a`.

Ограничения и триггеры проверяют существование родителя, соответствие вложения
родителю/блоку, уникальность номера и использования файла, область выбранной
версии и квитанций. UPDATE/DELETE версий, журнала и квитанций запрещены.
Область/родитель/первоначальный автор варианта неизменяемы. Эти ограничения
дополняют проверку прав в обработчике, а не заменяют её.

Байты остаются в прежних закрытых каталогах вложений. В определение страницы,
наборы и компоненты не добавляются ID цепочек, подписи, URL или файлы. Установка
набора в другое личное/командное пространство получает собственный пустой блок.

## Проверки до публикации

Первоначальный целевой запуск восьми Go-тестов и 16 вложенных сценариев завершился
PASS 15.09.2026 (8.424 с). Последующий review добавил девятый тест: архив нельзя
обойти через прежний список, историю или сохранённый адрес файла страницы.
Критерии проверок:

- все 14 типов записей созданы через публичный API и принимают варианты;
- загрузка/метаданные после потери ответа не создают дубликаты, другой payload
  с прежним ключом отклоняется, SQL-ошибка не оставляет частичную цепочку;
- старые и новые файлы остаются доступны, выбранная версия сохраняется после
  добавления следующей; прочитанные байты прежних версий совпадают;
- чужая команда, заметка, карточка, медиаблок, отозванное членство и ограниченная
  политика редактирования не обходятся через новую версию или её URL;
- архив родителя сохраняет разрешённую историю; восстановление исходного
  архива возвращает файл ровно один раз и соблюдает вместимость блока;
- CAS-конфликт оставляет загруженный файл для явного повтора; SQL запрещает
  подмену области, выбранной чужой версии и подтверждений;
- миграция поверх реальной схемы 001–075 с существующими строками сравнивает
  каждую из 143 таблиц и все прежние определения схемы: совпадают; пять новых
  таблиц пусты. Первое чтение старого материала не создаёт метаданные;
- изменения материалов не меняют сериализованное определение страницы.

Фактический полный прогон, браузерные проверки, commit и выпуск фиксируются
отдельным отчётом операции. Этот документ не объявляет физический телефон,
производственный деплой или все дальнейшие сценарии согласования проверенными.
Новые версии здесь не предоставляют редактор изображения, объединение файлов,
автоматический выбор лучшего эскиза или замену приложений для дизайна.
