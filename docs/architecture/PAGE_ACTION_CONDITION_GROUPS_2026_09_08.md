# SC-86. Несколько условий кнопки

## Причина и пользовательский сценарий

Одного условия недостаточно для самостоятельной сборки рабочего процесса: оценка должна быть заполнена **и** согласование получено; альтернативный сценарий требует хотя бы одного основания. После чтения задачи `2ad192a4298615883945e23a87d8ecd2` выделен этап `8dec307305e9c75d378b1cedb3cff9ed`. Кнопка теперь принимает до восьми типизированных проверок с выбором «Все условия» либо «Любое условие». Составная операция SC-85 при этом остаётся одной атомарной операцией.

Это развитие общего редактора действий. Специальный набор для владельца не создавался: пользователь собирает свой сценарий самостоятельно, приёмка проходит на синтетическом аккаунте.

## Настройка

1. Открыть конструктор страницы, выбрать список записей и нужное действие.
2. Включить «Выполнять только при условии». Ранее сохранённое одиночное условие не нужно настраивать заново.
3. Выбрать поле, допустимое сравнение и значение. Для пустоты/заполненности значение не требуется; ноль и false считаются заполненными.
4. Нажать «Добавить условие». Появится вторая проверка и выбор «Все условия»/«Любое условие». По умолчанию используется «Все»; новая проверка предлагает заполненность другого доступного поля. Одно поле разрешено использовать несколько раз, например для диапазона больше0 и меньше10.
5. Отдельно изменить или удалить любую проверку. После удаления первой следующая сохраняет свои настройки. Одна оставшаяся проверка становится обычным одиночным условием. Удаление последней снимает ограничение, флажок выключается; это объяснено рядом с редактором. Выключение общего флажка также явно снимает ограничения.
6. Сохранить страницу. Кнопка с невыполненным правилом остаётся видимой и объясняет требование. В предпросмотре перечисляются все проверки и результат каждой: «Выполнено» или «Не выполнено».

Режим «Все» требует выполнения каждой проверки; «Любое» — хотя бы одной. Пустая группа не имеет неявного значения true: она запрещена. Вложенные группы пока не поддержаны и сервер их отклоняет. Для отключения ограничения используется отсутствие condition, а не пустой массив.

## Формат и серверный контроль

Одиночный формат fieldId/operator/value сохраняется. Группа записывается как `condition: {mode: "all" | "any", conditions: [проверки]}`. От1до8 листовых проверок; у группы не может одновременно быть собственных fieldId/operator/value. Неизвестный режим, вложенность, неподходящие сравнения, чужие/удалённые поля и значения неправильного типа отклоняются при сохранении и выполнении.

Все поля условия включаются в schemaHash, даже если ранняя ветка «Любое» уже истинна. Переименование или изменение схемы последнего поля между просмотром и подтверждением требует обновить предпросмотр. Версии записи/страницы, права, ограничения типов и транзакция SC-85 сохраняются. Невыполненное правило отклоняет прямой apply без частичной записи.

Предпросмотр возвращает conditionFields и conditionResults в порядке условий. Групповое действие требует `expectedConditionCount` при подтверждении; старый клиент, который не умеет показывать все проверки, не сможет применить такую кнопку. Старые одиночные условия этого параметра не требуют. Клиент не определяет результат проверки: сервер вычисляет его по актуальной записи повторно.

Сохранение набора проверяет каждое условие. При установке переводятся ID всех полей и вариантов select/multi_select. Конфигурация устанавливается на независимую доску без записей автора. Переход от группы к одиночному условию или снятие условия в копии не меняет исходную страницу и сохранённый набор.

## Проверенные сценарии

- Через UI на синтетической странице настроено «Все»: «Оценка» заполнена и «Подтверждено» больше10. Закрытие, reload и восстановление сохранили обе проверки и10. При9/7 кнопка отключена с объяснением. Переключение на «Любое» сделало её доступной.
- В предпросмотре первая проверка была выполнена, вторая нет. Другой локальный API-клиент очистил оценку и поставил подтверждённое0. Устаревшее подтверждение отклонено409; обновление показало обе проверки невыполненными и отключило сохранение. После восстановления5/0 новое подтверждение дало9/5 после reload.
- Через UI сохранён приватный набор и установлена независимая копия. В ней обычной формой создана собственная запись0/0. Ноль выполнил проверку заполненности, второе условие осталось ложным; «Любое» разрешило действие, результат9/0 сохранён.
- В копии первое условие удалено и сохранено; после reload осталось второе с прежним значением10. Затем последнее удалено/сохранено/reload: condition отсутствует, оригинальная страница сохранила any и обе проверки.
- Проверены настройки, длинные подписи, доступность элементов и предпросмотр при320×800. Проверки не используют цвет как единственное объяснение. Обычная ширина восстановлена; физические телефоны не тестировались.

Go integration проверяет три условия разных типов (число, флажок, select), all/any, false/0, позднюю схему при уже истинной ветке OR, изменение исходных значений, отказ старому клиенту, прямой обход, одну историю/повтор409, независимый набор с переводом поля и варианта, снятие ограничений и неверные группы. Node проверяет общую логику, редактирование второго условия, удаление первого/последнего и экранирование полного списка результатов.

## Выпуск и оставшаяся работа

Миграций нет:117 таблиц, схема065. Деплой требует точный предыдущий релиз, серверный backup, dry run со сравнением всех строк, проверку HTTPS/assets/health/integrity/FK. SC-85 не понимает группу: откат на него блокируется, если после остановки службы найдены сохранённые группы в страницах или наборах. Фактическая квитанция будет добавлена после выпуска.

Следующий этап — несколько условий показа блоков с «Все»/«Любое», безопасной проверкой зависимостей и симуляцией в конструкторе. Он не заменяет произвольные привязки значений/свойств, вложенные выражения, настройку всех встроенных элементов и незавершённую работу чата/команд. Родительские направления остаются открытыми.
