# Сохранность действий при смене типа блока — 14.09.2026

## Подтверждённая проблема

В конструкторе своей страницы выбор «Список записей → Текст → Список записей»
без предупреждения очищал массив настроенных действий. Корневой агент
воспроизвёл сценарий SC-85 через интерфейс: исходное действие с двумя
изменениями и условием исчезало после переключения. Тестовый черновик был
отменён. Ограниченная задача этого исправления:
`16d7b9697374957b6876208c54b1f90e`, маркер `block-kind-safety`.

Причина находилась в `web/page-apps.js`: обработчик `input` сначала менял
`b.kind` и сохранял черновик, затем обработчик `change` очищал `b.actions`
при любом типе, кроме `records`. Защита только второго события опаздывала:
новый тип уже попадал в рабочее определение и локальный черновик.

## Почему настройки нельзя просто оставить в неактивном поле

Текущий серверный контракт `validatePageRecordActions` допускает действия
только у списка записей. Оставить непустой `actions` у текста без изменения
сервера означало бы ошибку сохранения всей страницы. Дополнительное поле
`inactiveActions` также нельзя добавить только в интерфейсе: сервер строго
отклоняет неизвестные JSON-поля.

Полное сохранение неактивных действий технически возможно без SQL-миграции,
но требует отдельного расширения контракта: валидации неактивных настроек,
учёта источника в `pageAppHasSource`, проверки полей/прав, переноса зависимостей
в наборы и библиотеку, а также совместимости отката. Существующий бинарник
не разрешает сохранять такое определение. Этот hotfix не вводит новый формат
под видом совместимого изменения интерфейса.

## Текущее поведение

Новый `web/page-block-kind.js` создаёт защиту для выбранного блока. Когда
у списка есть хотя бы одно действие, попытка выбрать другой тип:

1. Останавливается до изменения любых свойств, обновления предпросмотра и
   сохранения черновика. Тип, действия, цепочки изменений, условия, связи,
   поля и оформление остаются прежними.
2. Возвращает селектор к «Списку записей». Защита учитывает и нативную пару
   `input → change`, и одиночное `change` общего компонента выбора.
3. Показывает объяснение непосредственно под выбором типа:
   «В этом списке настроены действия. Добавьте блок нужного типа рядом;
   этот список можно скрыть, сохранив настройки.»
4. Даёт кнопку «Выбрать другой блок». Она прокручивает существующий каталог
   к запрошенному типу и переводит фокус на его кнопку. Пользователь сам
   добавляет блок штатным действием; исходный список не удаляется, не
   скрывается и не копируется автоматически.

Сообщение использует существующее оформление `.app-draft-notice`, имеет
`role=status` и `aria-live=polite`. Селектор и его визуальная кнопка связаны
с пояснением через `aria-describedby`. Повторная попытка обновляет доступное
продолжение, не добавляя несколько одинаковых сообщений.

Список без действий по-прежнему может менять тип. Редактирование названия,
цветов, размеров и других свойств не блокируется. Если пользователь явно
удалит действия в их редакторе, ограничение исчезает. Скрытие исходного
списка остаётся штатным способом убрать его с рабочего экрана с сохранением
конфигурации.

## Сохранение и совместимость

`collectPending` собирает только введённые пункты трекеров и не переносит
значение селектора типа в определение. Отдельная проверка проходит через
отклонённую пару событий, реальный `collectPending` и последующую
сериализацию: настройки списка остаются побайтно прежними, а новые пункты
другого трекера продолжают сохраняться.

Backend, миграции, структура определений, правила выполнения действий и
пользовательские записи не меняются. Сервер всё так же выполняет действие
только из активного блока `records` с проверкой прав и текущей ревизии.
Исторические определения и уже опубликованные наборы не переписываются.

## Проверка и границы

Новые 9 Node-тестов исполняют настоящие обработчики свойств из `page-apps.js`,
а не их отдельную копию. Они покрывают пару событий и одиночное событие,
повтор отвергнутого значения, полную сохранность вложенных условий и
изменений, отсутствие `persist`/перерисовки, доступное сообщение и переход
к выбранному типу в каталоге, список без действий, изменение названия,
явное удаление действий и `collectPending` перед сериализацией.

Вместе с существующими проверками редактора страниц и представления выполнено
39 тестов: все прошли. Браузерная приёмка исправленного кандидата, narrow
viewport, commit и production-выпуск фиксируются корневым агентом отдельно;
данный документ не объявляет их уже выполненными.

Это защита от подтверждённой потери настройки. Свободное переключение полного
типа с сохранением неактивной конфигурации остаётся отдельным этапом. Изменение
источника доски, которое сбрасывает зависящие от неё действия и поля, также
не переопределено этим исправлением и требует собственной проверки/защиты.
