# Варианты материалов в заметках и медиаблоках — 15.09.2026

## Основание и границы

Этот этап дополняет `PAGE_MEDIA_AND_SKETCHES_2026_09_15.md`, сохраняя историю
прежнего выпуска. Пользователь хочет обсуждать наброски и видеть разные
варианты логотипа, а не только получать плоский список вложений. Один общий
контроллер вариантов используется в карточках, сохранённых личных заметках
и медиаблоках конструктора. Это рабочие материалы текущей сущности; настройка
страницы остаётся в общем центре настроек.

Адаптеры находятся в `web/note-media.js` и `web/page-media.js`. Общий
`web/media-variants.js` получает хранилище черновиков через параметр `draftStore`.
Это исключает циклические импорты между общим контроллером, заметками и
медиаблоками. Общие подписи, галерея, история, выбор версии и сравнение
изображений не реализуются тремя разными редакторами.

## Использование

В сохранённой заметке либо рабочем медиаблоке:

1. «Добавить вариант» выбирает файл; имя варианта и подпись можно уточнить
   перед явной загрузкой. Вставка изображения и перетаскивание файлов приводят
   к той же очереди, а не к отдельному способу хранения.
2. «Новая версия» добавляет файл к существующему варианту. Прежняя версия
   сохраняется; загрузка не означает автоматическое принятие решения.
3. «Версии» показывает сохранённую историю и позволяет отметить выбранную
   версию при наличии права управления. Название варианта можно исправить
   там же. Архив сохраняет данные.
4. Для сравнения отмечаются два доступных изображения. Они открываются рядом
   с подписями и версиями; изображение показывается целиком. На узком экране
   общий компонент адаптирует размещение.

В заметке текстовая «История заметки» остаётся отдельным действием от истории
версий файла. Изменения подписи и состава материалов не подменяют текстовый
черновик заметки и не восстанавливают её прошлый текст.

## Сохранённые личные заметки

`bindSavedEditor` добавляет галерею перед существующими действиями редактора.
Остальные поля формы не переписываются. Контекст фиксирует владельца,
активное пространство, ID заметки и живую форму. Ответы после смены аккаунта,
пространства или закрытия редактора не рисуют старые данные.

Обработчики формы перехватывают только clipboard/drop, содержащие файлы.
Обычная вставка текста продолжает работать в текстовом редакторе. Выбранные
файлы передаются в `addFiles` общего компонента. Просмотр использует соседний
диалог, а не перезаписывает редактор заметки. Если диалог просмотра уже занят,
общий компонент предлагает закрыть его, сохраняя находящийся в нём черновик.

Новая, ещё не сохранённая заметка использует прежний поток `noteRequestKey`:
сначала заметка и её файлы попадают в одну durable-очередь, после подтверждения
заметки файлы связываются с полученным ID. Новый контроллер не пытается
отправлять версии к несуществующей заметке.

В сохранённой заметке отдельно видны файлы из прежней outbox-очереди, если
они ещё отправляются или требуют действия. Фильтрация проверяет владельца и
ID заметки. Подтверждение прежней загрузки обновляет общую галерею; файл не
добавляется повторно и не получает новый request key. Статусы, прогресс и
переход в прежнюю очередь остаются доступны до её завершения.

## Медиаблоки и прежние локальные загрузки

Каждый блок получает общий контроллер с владельцем, пространством, страницей
и стабильным ID блока. Переход на другую страницу той же команды, в другую
команду либо другой аккаунт инвалидирует отображение. Файлы соседнего блока
или страницы не используются как источник.

Прежние черновики `page-media-v1` не переименовываются в новые и не считаются
отправленными. Отдельный адаптер завершает старую очередь с исходными Blob и
request key. Панель видна только при наличии старых файлов либо ошибки чтения
этой очереди; второй галереи и второй кнопки добавления файлов нет.

После ответа сервера проверяются ID, имя, размер и тип вложения. Только затем
подтверждение записывается в локальное хранилище и файл удаляется из ожидающих.
Неполный ответ либо ошибка локального commit сохраняют прежние байты и ключ
для повтора. После подтверждения обновляется общая галерея вариантов.

Если пользователь перешёл в другую команду во время запроса, подтверждённая
загрузка завершается в исходном локальном контексте, но не меняет новую
страницу. Это сохраняет результат отправки без раскрытия прежнего содержимого.

## Проверки адаптеров и ограничения

Локально прошли 20 Node-тестов: 9 заметок и 11 медиаблоков. Сохранены прежние
проверки допустимых файлов, URL, миниатюр, receipt и IndexedDB. Добавлены:

- передача ID и границ контекста в общий контроллер;
- сохранение несохранённого текста при обновлении галереи;
- перехват только файлов, сохранение обычной вставки текста;
- запрет старых ответов после смены владельца/пространства и закрытия формы;
- сохранение старой outbox-очереди с фильтрацией по владельцу и заметке;
- продолжение старой очереди страницы с исходным request key;
- сохранность Blob при неверном ответе и ошибке локального commit;
- отсутствие отрисовки в новой команде после запоздалого подтверждения.

Проверка синтаксиса обоих адаптеров прошла. Эти тесты проверяют интеграцию и
сохранность перехода; полный сценарий загрузки → новая версия → история →
сравнение проверяется также общим компонентом и основной браузерной приёмкой.
Этот документ не заявляет, что эмуляция браузера означает проверку физического
телефона: Android/iPhone данным агентом не проверялись. Фактический выпуск
регистрируется отдельным операционным отчётом после деплоя.
