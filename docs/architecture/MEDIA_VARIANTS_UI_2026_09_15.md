# Варианты и версии материалов — интерфейс, 15.09.2026

## Зачем нужен этот этап

Для разработки логотипа одного списка вложений недостаточно: автору нужно
назвать разные варианты, дополнять каждый вариант новой версией, видеть
предыдущие и явно отмечать выбранную. Возможность относится к обычным
материалам платформы, а не к специальной странице одной команды. Общий
`web/media-variants.js` используется карточками всех типов, сохранёнными
личными заметками и медиаблоком конструктора. Формы заметок и страниц
подключают тот же контроллер через адаптеры, описанные в
`NOTE_PAGE_MEDIA_VARIANTS_ADAPTERS_2026_09_15.md`.

Этот документ дополняет прежний контракт `PAGE_MEDIA_AND_SKETCHES_2026_09_15.md`.
Историческое ограничение «версии одного файла не реализованы» относится к
предыдущему выпуску. Здесь реализуются группы вариантов и история версий,
но совместное рисование и произвольный перенос приватных файлов не добавляются.

## Повседневный сценарий

1. Открыть материалы карточки, заметки или собственный медиаблок. Старые
   вложения видны сразу как варианты с одной версией; обязательного переноса
   или повторной загрузки нет.
2. Выбрать «Добавить вариант», вставить файл из буфера или перетащить файлы
   в область материалов. Выбор сохраняется на этом устройстве. До отправки
   можно указать понятное название и подпись к каждому файлу.
3. Нажать «Загрузить выбранные». Успешное подтверждение убирает файл из
   локальной очереди. Ошибка оставляет его вместе с подписью для повтора.
4. Действие «Новая версия» у нужного варианта добавляет один новый файл в
   эту историю. Старый файл остаётся доступным; новая загрузка сама не
   меняет ранее выбранную версию.
5. В «Версии» можно переименовать вариант, посмотреть время и автора каждой
   загрузки, подписи, скачать файл, явно выбрать версию или снять выбор.
   Когда выбор не сделан, галерея показывает последнюю версию.
6. Две отметки «Для сравнения» открывают изображения рядом. Подходят версии
   одного варианта и разных вариантов. Картинки помещаются целиком в две
   одинаковые области, подписи и авторство остаются видны. Третья отметка
   предлагает снять одну из двух существующих.
7. «В архив» скрывает вариант из обычной галереи. Кнопка «Архив» показывает
   его вместе с историей и действием восстановления. Это не удаление файлов.

Счётчик «Файлы» в карточке отражает число разных исходных вложений, включая
версии в архивных вариантах, кроме ранее удалённых вложений. После подтверждения
он обновляется на месте в обычных вкладках и мобильном списке разделов. Вся
карточка не перерисовывается: открытые поля и несохранённый текст сохраняются.

## Контракт адаптеров

`createMediaVariantsUI` принимает существующие `state`, `api`, функции
экранирования и иконок, открытия/закрытия диалога, уведомления и экземпляр
`draftStore`. Хранилище передаётся зависимостью: общий модуль не импортирует
адаптер заметок и не образует циклической зависимости с ним.

`mount(root, context)` возвращает `ready`, `addFiles(files, {variantId})`,
`refresh()` и `dispose()`. Контекст закрепляет `kind`, `ownerId`, `workspaceId`
и соответствующий ID карточки, заметки либо страницы с блоком. `isCurrent`
проверяет живой родительский экран. Необязательный `onChange` получает
подтверждённые `items`, `canCreate` и `attachmentCount`; это позволяет
обновить соседний счётчик без замены всей формы. Смена аккаунта, пространства
или родителя прекращает обновления прежнего интерфейса.

Три коллекции API:

- `/api/records/{id}/media-variants`;
- `/api/personal/notes/{id}/media-variants`;
- `/api/workspace/pages/{id}/app/media/{blockId}/variants`.

Файл сначала отправляется через существующий endpoint вложений, затем
подтверждённый `attachmentId` связывается с вариантом. Создание варианта,
новая версия и PATCH метаданных имеют отдельный устойчивый ключ запроса.
`expectedRevision` защищает изменение существующего варианта. Выбор версии
передаётся исключительно отдельным действием; upload его не подменяет.

## Сохранность очереди и конкурентные изменения

Ключ IndexedDB начинается с `media-variants-v1` и включает аккаунт,
пространство, тип родителя, его ID и ID блока. Название, подпись, Blob,
ключ загрузки и ключ изменения сохраняются вместе. Старые очереди заметок
и страницы не переименовываются вслепую: адаптеры досылают их прежними
идемпотентными запросами и затем обновляют общую галерею.

Операции с одной очередью сериализуются в процессе и через Web Locks там,
где браузер поддерживает этот API. Перед записью перечитывается свежий
черновик. Поля дополнительно имеют немедленное локальное представление
введённого текста: обновление галереи во время медленной записи IndexedDB
не возвращает прежнюю подпись. Повторное открытие ждёт уже начатую запись.

До сетевой отправки файл фиксируется в очереди. Ответ upload должен
содержать ID, совпадающие имя и размер и тип содержимого. Подтверждённый ID
сохраняется до запроса метаданных. Если второй ответ потерялся, повтор
отправляет прежний ключ без новой загрузки файла. Blob удаляется из очереди
только после полного подтверждения версии и успешного сохранения очереди.
При ошибке квоты интерфейс показывает проблему, а не обещает сохранность.

При конфликте ревизии приложение перечитывает историю и предлагает явно
добавить уже загруженный файл к текущей истории. Только после решения
пользователя меняются ревизия и ключ запроса метаданных. Если файл уже
сохранён сервером, подтверждение убирает его из очереди без новой версии.

Переименование, выбор и архивирование также сначала сохраняют точный запрос
в локальном черновике. Неизвестный результат оставляет действие повтора
того же запроса. Одновременный второй PATCH этого варианта блокируется до
завершения первого, поля изменения временно недоступны. Подтверждённое
изменение отменяет применение более раннего GET к локальному состоянию.

## Просмотр и границы приватности

Каждый запрос закрепляет `X-Workspace-ID` и `X-Outbox-Owner`. Фронтенд
проверяет, что предоставленный сервером `fileUrl` ведёт к точному родителю,
варианту и версии; для командных страниц и карточек также должен совпадать
workspace в адресе. Само чтение файла повторно авторизуется сервером.
Никакие публичные URL, личные Blob или ID вложений в наборы не передаются.

Встроенный просмотр допускает только подтверждённые растровые типы PNG,
JPEG, GIF, WebP и видео MP4/WebM. SVG и остальные документы предлагаются
как скачивание. Имена, подписи, авторы и адреса экранируются. Недоступные
старые файлы остаются в истории без ложной кнопки просмотра.

Галерея ориентируется на `canCreate` и `canManage`; архивный родитель
доступен разрешённому читателю в режиме просмотра истории. Авторизация
записи остаётся на сервере. Смена аккаунта не запускает следующий этап
старой очереди; выход сбрасывает живые экземпляры контроллера.

Для истории/сравнения используется соседний общий диалог. Если он занят,
контроллер предлагает закрыть его и не заменяет содержимое открытого
редактора. Отметки сравнения обновляются на месте, без повторного создания
checkbox и изображений. Сбой загрузки приватного изображения объясняется
внутри просмотра; прежняя картинка не публикуется для обхода авторизации.

## Проверки и реальные ограничения

15.09.2026: профильные Node-проверки общего контроллера подтверждают
три отдельных scope, защищённые адреса, сохранение выбранной старой версии,
ровно два безопасных изображения, архив/readonly, проверку upload receipt,
загрузку с последующим связыванием, потерю ответа без повторного Blob,
смену аккаунта, восстановление очереди, закреплённую ревизию, сохранность
подписи при медленном IndexedDB и обновление счётчика без чужих callback.
Точный общий итог тестов и факт размещения фиксирует операционный отчёт
`MEDIA_VARIANTS_RELEASE_2026_09_15.md` после проверки координатором.

Координатор проверил в браузере ширины 320/390: старое вложение,
переименование, выбор первой версии, загрузку второй с подписью,
сохранение прежнего выбора, историю и сравнение двух изображений.
Это не заменяет проверку физического телефона и всех видеокодеков.

Одна очередь допускает до 20 файлов, каждый до 15 МБ. Подпись версии
задаётся при загрузке; изменение уже сохранённой подписи, графические
пометки поверх изображения, рисование вместе, масштабирование синхронным
жестом и сравнение видео здесь не реализованы. При отказе создания
метаданных подтверждённый исходный файл остаётся доступен в материалах
родителя; пользователь может повторить связывание, не теряя файл.

### Уточнение для ранее архивированного исходного файла

Если отдельное вложение ранее убрано старым интерфейсом (`removed`), но
сервер разрешает его историческое чтение (`available`), история показывает
«файл в архиве» и сохраняет просмотр, сравнение и скачивание. Выбрать такой
файл текущей версией нельзя, поэтому соответствующая кнопка скрывается.
Архив варианта и архив исходного вложения не подменяют друг друга.
